## **Nội dung chính**

### **1. Ôn nhanh: vì sao Handler CQRS dễ test hơn — và đào sâu thêm (10 phút · Lý thuyết)**

Ở bài 1.10, bạn đã viết test đầu tiên cho CreateCourseCommandHandler bằng cách mock ICourseRepository. Hôm nay ôn lại lý do cốt lõi, rồi đi sâu hơn vào lý do bạn sẽ thấy giá trị thật của nó ở Module 9.

- Handler nhận vào 1 Command (record/class thuần), trả về 1 kết quả rõ ràng — không có HttpContext, không có Request/Response ASP.NET Core nào len vào giữa.
- Handler chỉ phụ thuộc vào interface (ICourseRepository, IOrderRepository...) được định nghĩa ở Application layer — theo Dependency Inversion Principle đã học ở bài 0.2. Test chỉ cần mock interface đó, không cần Postgres thật, không cần EF Core thật.
- So sánh trực diện: Controller CRUD truyền thống muốn unit test đúng nghĩa phải mock cả HttpContext, ModelState, đôi khi phải dựng WebApplicationFactory chỉ để test 1 nhánh logic — chi phí cao hơn hẳn.

Đây chính là lý do 4 quyết định kiến trúc ở mục 5 của outline không chỉ là "tách tên class Command/Query" — CQRS có lý do tồn tại thật vì nó tạo ra một lớp logic (Application) hoàn toàn độc lập với hạ tầng, test được ở tốc độ mili-giây.

> **📘 Ghi chú giảng viên:** *Tôi hay dừng ở đây và hỏi ngược: "Nếu Handler của bạn gọi thẳng AppDbContext.SaveChangesAsync() thay vì đi qua ICourseRepository, bạn sẽ mock cái gì?" — hầu hết học viên khựng lại vì DbContext rất khó mock đúng nghĩa (DbSet, ChangeTracker...). Đó là lúc nhấn mạnh lại: Repository interface ở Application layer không phải là thủ tục hình thức, nó là điều kiện để unit test Handler tồn tại được mà không cần hạ tầng thật.*

Một lý do thực dụng khác: bài 9.6 (CI/CD GitHub Actions) sẽ bắt buộc toàn bộ test pass trước khi cho phép deploy — đây là build gate thật, không phải hình thức. Bộ test bạn viết hôm nay chính là một phần của gate đó, nên đặt tên và tổ chức project cho chuẩn ngay từ bây giờ.

### **3. Demo + Lab: Test UpdateCourseCommandHandler — mock Repository, verify business rule (17 phút)**

Nhắc lại bài 1.2: CreateCourseCommand, UpdateCourseCommand đã hoạt động, kèm business rule tạm — chỉ Instructor sở hữu Course mới được sửa, check bằng InstructorId truyền thẳng vào Handler (Authorization đầy đủ để dành bài 3.8). Hôm nay ta viết test bao đủ cả 2 nhánh: chủ sở hữu đúng và chủ sở hữu sai.

Giả định chữ ký Handler kế thừa từ bài 1.2 (điều chỉnh theo đúng tên bạn đã đặt nếu khác):

```csharp
// TeduMarket.Application/Courses/Commands/UpdateCourseCommandHandler.cs
public sealed class UpdateCourseCommandHandler
    : IRequestHandler<UpdateCourseCommand, Unit>
{
    private readonly ICourseRepository _courseRepository;
 
    public UpdateCourseCommandHandler(ICourseRepository courseRepository)
        => _courseRepository = courseRepository;
 
    public async Task<Unit> Handle(UpdateCourseCommand request, CancellationToken ct)
    {
        var course = await _courseRepository.GetByIdAsync(request.CourseId, ct)
            ?? throw new CourseNotFoundException(request.CourseId);
 
        if (course.InstructorId != request.InstructorId)
            throw new CourseForbiddenException(request.CourseId);
 
        course.UpdateDetails(request.Title, request.Description, request.Price);
        await _courseRepository.UpdateAsync(course, ct);
 
        return Unit.Value;
    }
}
```

Test class đầy đủ 3 kịch bản — chủ sở hữu đúng, chủ sở hữu sai, và Course không tồn tại:

```csharp
// tests/TeduMarket.Application.UnitTests/Courses/UpdateCourseCommandHandlerTests.cs
using Moq;
using TeduMarket.Application.Courses.Commands;
using TeduMarket.Domain.Courses;
using Xunit;
 
namespace TeduMarket.Application.UnitTests.Courses;
 
public sealed class UpdateCourseCommandHandlerTests
{
    private readonly Mock<ICourseRepository> _repositoryMock = new();
 
    [Fact]
    public async Task Handle_KhiInstructorLaChuSoHuu_ShouldCapNhatCourse()
    {
        // Arrange
        var instructorId = Guid.NewGuid();
        var course = Course.Create("ASP.NET Core Nang Cao", instructorId);
        _repositoryMock
            .Setup(r => r.GetByIdAsync(course.Id, It.IsAny<CancellationToken>()))
            .ReturnsAsync(course);
 
        var handler = new UpdateCourseCommandHandler(_repositoryMock.Object);
        var command = new UpdateCourseCommand(course.Id, instructorId, "Ten moi", "Mo ta moi", 599_000m);
 
        // Act
        await handler.Handle(command, CancellationToken.None);
 
        // Assert
        Assert.Equal("Ten moi", course.Title);
        _repositoryMock.Verify(
            r => r.UpdateAsync(course, It.IsAny<CancellationToken>()), Times.Once);
    }
 
    [Fact]
    public async Task Handle_KhiInstructorKhongPhaiChuSoHuu_ShouldNemCourseForbiddenException()
    {
        // Arrange
        var chuSoHuuThat = Guid.NewGuid();
        var nguoiKhac = Guid.NewGuid();
        var course = Course.Create("ASP.NET Core Nang Cao", chuSoHuuThat);
        _repositoryMock
            .Setup(r => r.GetByIdAsync(course.Id, It.IsAny<CancellationToken>()))
            .ReturnsAsync(course);
 
        var handler = new UpdateCourseCommandHandler(_repositoryMock.Object);
        var command = new UpdateCourseCommand(course.Id, nguoiKhac, "Ten moi", "Mo ta moi", 599_000m);
 
        // Act & Assert
        await Assert.ThrowsAsync<CourseForbiddenException>(
            () => handler.Handle(command, CancellationToken.None));
 
        // Repository.UpdateAsync KHONG duoc goi khi bi chan
        _repositoryMock.Verify(
            r => r.UpdateAsync(It.IsAny<Course>(), It.IsAny<CancellationToken>()), Times.Never);
    }
 
    [Fact]
    public async Task Handle_KhiCourseKhongTonTai_ShouldNemCourseNotFoundException()
    {
        // Arrange
        var courseId = Guid.NewGuid();
        _repositoryMock
            .Setup(r => r.GetByIdAsync(courseId, It.IsAny<CancellationToken>()))
            .ReturnsAsync((Course?)null);
 
        var handler = new UpdateCourseCommandHandler(_repositoryMock.Object);
        var command = new UpdateCourseCommand(courseId, Guid.NewGuid(), "X", "Y", 0m);
 
        // Act & Assert
        await Assert.ThrowsAsync<CourseNotFoundException>(
            () => handler.Handle(command, CancellationToken.None));
    }
}
```

> **📘 Ghi chú giảng viên:** *Điểm hay bị hỏi nhất ở đây: "Sao không mock luôn Course?" — vì Course là Entity/Aggregate của Domain layer, không phải dependency cần cô lập, nên ta dùng instance thật (Course.Create(...)) và chỉ mock ranh giới hạ tầng (ICourseRepository). Mock quá tay — mock luôn cả Domain object — là lỗi rất phổ biến khiến test không còn phản ánh đúng hành vi thật.*

> **✏️ Thực hành:** Ngay tại đây, dừng video và tự viết thêm 1 test case: Handle_KhiTitleRong_ShouldNemCourseValidationException (giả định Course.UpdateDetails ném exception khi title rỗng — nếu Domain của bạn ở bài 1.1 chưa có invariant này, đây là lúc quay lại 1.1 bổ sung, vì Application layer chỉ nên orchestrate, không nên tự if-check việc này).

### **4. Demo + Lab: Test CheckoutCommandHandler — Handler nhiều dependency hơn (18 phút)**

Chuyển sang bounded context Order (bài 2.1–2.2). CheckoutCommandHandler phức tạp hơn UpdateCourseCommandHandler vì: (1) đọc từ ICartRepository, (2) ghi xuống IOrderRepository, và (3) Order Aggregate phải phát ra CourseOrderedEvent ngay khi tạo — đúng quy ước Domain Event ở mục 7 outline.

> **📘 Ghi chú giảng viên:** *Tôi luôn nhấn mạnh ranh giới ở đây: unit test hôm nay CHỈ kiểm tra Order được tạo đúng trạng thái Pending và Aggregate có phát domain event hay không. Việc domain event đó có thật sự được ghi vào bảng Outbox trong cùng transaction hay không — đó là hành vi của SaveChangesInterceptor ở Infrastructure layer, thuộc phạm vi Integration Test ở bài 8.3 (WebApplicationFactory + Testcontainers), không test được bằng mock ở đây. Nói rõ ranh giới này để học viên không hoang mang khi bài 8.1 "chưa test" luôn cả Outbox.*

```csharp
// tests/TeduMarket.Application.UnitTests/Orders/CheckoutCommandHandlerTests.cs
using Moq;
using TeduMarket.Application.Orders.Commands;
using TeduMarket.Domain.Orders;
using TeduMarket.Domain.Orders.Events;
using Xunit;
 
namespace TeduMarket.Application.UnitTests.Orders;
 
public sealed class CheckoutCommandHandlerTests
{
    private readonly Mock<ICartRepository> _cartRepositoryMock = new();
    private readonly Mock<IOrderRepository> _orderRepositoryMock = new();
 
    [Fact]
    public async Task Handle_KhiCartCoItem_ShouldTaoOrderPendingVaPhatCourseOrderedEvent()
    {
        // Arrange
        var userId = Guid.NewGuid();
        var cart = Cart.Create(userId);
        cart.AddItem(courseId: Guid.NewGuid(), gia: 599_000m);
 
        _cartRepositoryMock
            .Setup(r => r.GetByUserIdAsync(userId, It.IsAny<CancellationToken>()))
            .ReturnsAsync(cart);
 
        Order? orderDaLuu = null;
        _orderRepositoryMock
            .Setup(r => r.AddAsync(It.IsAny<Order>(), It.IsAny<CancellationToken>()))
            .Callback<Order, CancellationToken>((order, _) => orderDaLuu = order)
            .Returns(Task.CompletedTask);
 
        var handler = new CheckoutCommandHandler(
            _cartRepositoryMock.Object, _orderRepositoryMock.Object);
        var command = new CheckoutCommand(userId);
 
        // Act
        await handler.Handle(command, CancellationToken.None);
 
        // Assert — trang thai Order
        Assert.NotNull(orderDaLuu);
        Assert.Equal(OrderStatus.Pending, orderDaLuu!.Status);
        Assert.Single(orderDaLuu.Items);
 
        // Assert — domain event da duoc Aggregate phat ra
        Assert.Contains(
            orderDaLuu.DomainEvents,
            e => e is CourseOrderedEvent);
 
        _orderRepositoryMock.Verify(
            r => r.AddAsync(It.IsAny<Order>(), It.IsAny<CancellationToken>()), Times.Once);
    }
 
    [Fact]
    public async Task Handle_KhiCartRong_ShouldNemCartEmptyException()
    {
        // Arrange
        var userId = Guid.NewGuid();
        var cartRong = Cart.Create(userId);
        _cartRepositoryMock
            .Setup(r => r.GetByUserIdAsync(userId, It.IsAny<CancellationToken>()))
            .ReturnsAsync(cartRong);
 
        var handler = new CheckoutCommandHandler(
            _cartRepositoryMock.Object, _orderRepositoryMock.Object);
 
        // Act & Assert
        await Assert.ThrowsAsync<CartEmptyException>(
            () => handler.Handle(new CheckoutCommand(userId), CancellationToken.None));
 
        _orderRepositoryMock.Verify(
            r => r.AddAsync(It.IsAny<Order>(), It.IsAny<CancellationToken>()), Times.Never);
    }
}
```

Điểm kỹ thuật đáng chú ý trong đoạn test trên:

- Dùng .Callback\<Order, CancellationToken>(...) để "chụp lại" đối tượng Order thật mà Handler tạo ra, thay vì chỉ Verify lời gọi suông — cách này cho phép assert sâu vào trạng thái nội tại của Order (Status, Items, DomainEvents).
- orderDaLuu.DomainEvents giả định Order (kế thừa AggregateRoot) có property public IReadOnlyCollection\<IDomainEvent> DomainEvents — nếu bài 2.1 bạn đặt tên khác (ví dụ GetUncommittedEvents()), đổi lại cho khớp, miễn giữ đúng ý nghĩa: kiểm tra được Aggregate đã tự thêm domain event, không phải Handler tự gọi IPublisher.Publish(...) thủ công.
- Test thứ hai (CartEmptyException) là ví dụ tối thiểu — trong Lab, học viên nên bổ sung thêm case Coupon hết hạn nếu Handler thật của bạn đã tích hợp ApplyCouponCommand từ bài 2.3.

## **Bài tập thực hành**

Tự viết bộ unit test cho AddToCartCommandHandler (đã xây ở bài 2.2), theo đúng convention vừa học ở phần 3–4.

### **Yêu cầu**

- Input: AddToCartCommand(userId, courseId).
- Test case 1 — Course tồn tại và chưa có trong Cart: Handle_KhiCourseChuaCoTrongCart_ShouldThemVaoCart. Expected: Cart sau khi Handle có đúng 1 item với courseId tương ứng, ICartRepository.SaveAsync (hoặc UpdateAsync tùy tên bạn đặt) được gọi đúng 1 lần.
- Test case 2 — Course đã có sẵn trong Cart: Handle_KhiCourseDaCoTrongCart_ShouldKhongThemTrung. Expected: số lượng item trong Cart KHÔNG tăng lên (dùng Assert.Single hoặc Assert.Equal(1, cart.Items.Count) để chắc chắn không có bản ghi trùng).
- Test case 3 — Course không tồn tại: Handle_KhiCourseKhongTonTai_ShouldNemCourseNotFoundException. Expected: ném đúng CourseNotFoundException, ICartRepository không bị gọi lưu gì cả (Verify Times.Never).

### **Hint**

- Mock ICourseRepository.GetByIdAsync trả về null để giả lập trường hợp not-found — giống hệt cách đã làm ở test case thứ 3 của UpdateCourseCommandHandlerTests phía trên.
- Nếu Handler thật của bạn kiểm tra trùng lặp bằng cart.Items.Any(i => i.CourseId == courseId), test case 2 chỉ cần Arrange sẵn 1 Cart đã có item đó rồi Act — không cần mock gì thêm phức tạp.

Solution gợi ý: cấu trúc giống hệt CheckoutCommandHandlerTests ở trên — 1 Mock cho mỗi repository dependency, dùng Callback để chụp lại entity thật khi cần assert sâu, Verify Times.Once/Times.Never để xác nhận nhánh nào được/không được thực thi.

## **Tổng kết**

- Handler CQRS test được nhanh vì chỉ phụ thuộc interface ở Application layer — mock Repository, không cần HttpContext/DB thật.
- Test class đặt tên {HandlerName}Tests, method đặt tên Handle_[KịchBản]_Should[KếtQuả] — convention này dùng xuyên suốt Module 8.
- Handler càng nhiều dependency (như CheckoutCommandHandler) càng cần Callback để chụp lại entity thật, thay vì chỉ Verify lời gọi suông.
- Domain Event do Aggregate tự phát ra — unit test Handler chỉ kiểm tra event có được thêm vào DomainEvents hay chưa, KHÔNG kiểm tra việc ghi Outbox (đó là phạm vi Integration Test, bài 8.3).
- Không dùng FluentAssertions trong khóa này vì license đã chuyển sang thương mại từ bản 8.0 — dùng Assert có sẵn của xUnit, miễn phí hoàn toàn.

> **✅ Tóm tắt:** Bộ unit test hôm nay (UpdateCourseCommandHandler, CheckoutCommandHandler) chạy được bằng dotnet test và sẽ là 1 phần của build gate bắt buộc ở bài 9.6. Bước tiếp theo — bài 8.2: Unit Test Domain Logic, chuyển trọng tâm xuống test trực tiếp Aggregate invariant và Value Object, không cần mock gì cả vì không đụng tới hạ tầng.
