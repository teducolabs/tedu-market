## Nội dung chính

### 1. Vì sao Domain layer test được mà không cần DB, không cần mock?

*Thời lượng: 5 phút | Loại: Lý thuyết*

Ở bài 8.1 bạn đã test CommandHandler bằng cách mock ICourseRepository — vì Handler phụ thuộc vào interface đó để hoạt động. Course, Lesson, Pricing, Coupon, Discount thì khác: đây là các lớp thuần C# (POCO), không gọi EF Core, không gọi HTTP, không đọc file. Mọi hành vi của chúng là hàm số thuần: cùng input → luôn cùng output, không side-effect ra ngoài.

Vì vậy test Domain layer không cần:

- Repository interface + mock (NSubstitute/Moq) như bài 8.1
- Database thật hay Testcontainers như bài 8.3
- HttpContext, MediatR pipeline, hay bất kỳ DI container nào

Bạn chỉ cần: new một Aggregate/Entity/Value Object, gọi method, assert kết quả hoặc assert exception.

| **Tiêu chí** | **Unit Test Handler (8.1)** | **Unit Test Domain (8.2)** |
|---|---|---|
| Đối tượng test | CreateCourseCommandHandler | Course, Coupon, Discount |
| Cần mock gì? | ICourseRepository (mock) | Không cần mock gì cả |
| Tốc độ chạy | Vài mili-giây / test | Dưới 1 mili-giây / test |
| Phát hiện lỗi gì | Sai luồng gọi Repository, validation | Sai business rule, sai invariant |

> **📘 Ghi chú giảng viên:** *Đây chính là đáy của testing pyramid: Domain test phải là loại test bạn viết nhiều nhất trong dự án, vì rẻ nhất và ổn định nhất. Tôi hay dừng ở bảng so sánh này và hỏi ngược lớp: "Nếu Domain test chạy dưới 1ms và không đụng hạ tầng, vậy tại sao mình không viết Handler test kiểu này luôn?" — dẫn học viên tự nhận ra: vì Handler còn phải điều phối Repository, nó không phải Domain logic thuần, nên vẫn cần layer test riêng ở 8.1.*

### 2. Mở rộng test cho Course.Publish() — ôn lại bài 1.1

*Thời lượng: 10 phút | Loại: Demo + Lab*

Nhắc lại nhanh: ở bài 1.1 bạn đã dựng Course Aggregate với business invariant "Course phải có ít nhất 1 Lesson mới được publish", và đã viết 1 unit test cho invariant đó. Ở bài này ta không viết lại từ đầu — ta bổ sung thêm 2 case biên mà bài 1.1 chưa cover: publish thành công khi đủ điều kiện, và invariant tên Course không rỗng (theo đúng pattern đã luyện ở Category từ bài 0.3).

Domain code liên quan (namespace TeduMarket.Domain.Courses, đã có từ bài 1.1 — chỉ liệt lại phần cần thiết để viết test):

```csharp
namespace TeduMarket.Domain.Courses;
 
public sealed class Course
{
    private readonly List<Lesson> _lessons = new();
 
    public Guid Id { get; private set; }
    public string Title { get; private set; }
    public Guid InstructorId { get; private set; }
    public Pricing Pricing { get; private set; }
    public CourseStatus Status { get; private set; }
    public IReadOnlyCollection<Lesson> Lessons => _lessons.AsReadOnly();
 
    private Course() { } // dành cho EF Core (bài 1.4)
 
    public static Course Create(string title, Guid instructorId, Pricing pricing)
    {
        if (string.IsNullOrWhiteSpace(title))
            throw new ArgumentException("Tên khóa học không được để trống", nameof(title));
 
        return new Course
        {
            Id = Guid.NewGuid(),
            Title = title,
            InstructorId = instructorId,
            Pricing = pricing,
            Status = CourseStatus.Draft
        };
    }
 
    public void AddLesson(string title, int order, string videoUrl)
        => _lessons.Add(Lesson.Create(title, order, videoUrl));
 
    public void Publish()
    {
        if (_lessons.Count == 0)
            throw new CourseCannotBePublishedException(Id);
 
        Status = CourseStatus.Published;
    }
}
```

Test bổ sung — tạo file tests/TeduMarket.Application.UnitTests/Domain/CourseTests.cs (đặt trong project Application.UnitTests đã có từ bài 8.1, vì mục 6 của outline chưa định nghĩa project test riêng cho Domain — project này vẫn reference được Domain vì Application phụ thuộc Domain):

```csharp
using TeduMarket.Domain.Courses;
using Xunit;
 
namespace TeduMarket.Application.UnitTests.Domain;
 
public class CourseTests
{
    // Đã có từ bài 1.1 — nhắc lại để đối chiếu, KHÔNG viết lại
    [Fact]
    public void Publish_KhiChuaCoLesson_PhaiThrowException()
    {
        var course = Course.Create("ASP.NET Core từ Zero", Guid.NewGuid(),
            Pricing.Of(499_000m, "VND"));
 
        var act = () => course.Publish();
 
        Assert.Throws<CourseCannotBePublishedException>(act);
    }
 
    // Bổ sung ở bài 8.2
    [Fact]
    public void Publish_KhiDaCoItNhat1Lesson_PhaiThanhCong()
    {
        var course = Course.Create("ASP.NET Core từ Zero", Guid.NewGuid(),
            Pricing.Of(499_000m, "VND"));
        course.AddLesson("Giới thiệu khóa học", 1, "https://cdn.tedu.com.vn/lesson-1.mp4");
 
        course.Publish();
 
        Assert.Equal(CourseStatus.Published, course.Status);
    }
 
    [Fact]
    public void Create_KhiTitleRong_PhaiThrowException()
    {
        var act = () => Course.Create("   ", Guid.NewGuid(), Pricing.Of(100_000m, "VND"));
 
        Assert.Throws<ArgumentException>(act);
    }
}
```

> **📘 Ghi chú giảng viên:** *Lỗi phổ biến nhất ở đây: học viên assert Assert.Throws\<Exception>(...) thay vì đúng kiểu CourseCannotBePublishedException. Assert kiểu Exception chung chung sẽ pass ngay cả khi code ném nhầm loại lỗi khác (ví dụ NullReferenceException do bug) — test lúc đó không còn bảo vệ được gì. Tôi luôn dừng lại nhấn mạnh: assert đúng loại Exception cụ thể theo đúng quy ước {Thực thể}{LoạiLỗi}Exception ở mục 7 outline.*

### 3. Test Discount (Value Object) và Coupon (Aggregate) — bài 2.1 / 2.3

*Thời lượng: 10 phút | Loại: Demo + Lab*

Bài 2.3 đã thiết kế Discount là Value Object bất biến, và Specification pattern nhẹ để áp rule coupon (% giảm, giới hạn thời gian, giới hạn Course áp dụng). Ở đây ta viết test cho 2 rule đầu tiên: % giảm hợp lệ, và giới hạn thời gian hiệu lực. Rule thứ 3 (giới hạn Course áp dụng) để lại làm bài tập cuối bài.

Domain code (namespace TeduMarket.Domain.Ordering, đã có từ bài 2.1/2.3):

```csharp
namespace TeduMarket.Domain.Ordering;
 
public sealed class Discount
{
    public decimal Percentage { get; }
 
    private Discount(decimal percentage) => Percentage = percentage;
 
    public static Discount Percent(decimal percentage)
    {
        if (percentage is <= 0 or > 100)
            throw new ArgumentOutOfRangeException(
                nameof(percentage), "Phần trăm giảm giá phải trong khoảng (0, 100]");
 
        return new Discount(percentage);
    }
 
    public decimal ApplyTo(decimal originalPrice)
        => originalPrice - originalPrice * Percentage / 100m;
}
 
public sealed class Coupon
{
    public Guid Id { get; private set; }
    public string Code { get; private set; }
    public Discount Discount { get; private set; }
    public DateTime StartDate { get; private set; }
    public DateTime EndDate { get; private set; }
 
    private Coupon() { }
 
    public static Coupon Create(string code, Discount discount, DateTime startDate, DateTime endDate)
    {
        if (endDate <= startDate)
            throw new ArgumentException("Ngày kết thúc phải sau ngày bắt đầu", nameof(endDate));
 
        return new Coupon
        {
            Id = Guid.NewGuid(), Code = code, Discount = discount,
            StartDate = startDate, EndDate = endDate
        };
    }
 
    public bool IsValidAt(DateTime now) => now >= StartDate && now <= EndDate;
 
    public decimal ApplyTo(decimal originalPrice, DateTime now)
    {
        if (!IsValidAt(now))
            throw new CouponExpiredException(Code);
 
        return Discount.ApplyTo(originalPrice);
    }
}
```

Test — tạo file tests/TeduMarket.Application.UnitTests/Domain/CouponTests.cs:

```csharp
using TeduMarket.Domain.Ordering;
using Xunit;
 
namespace TeduMarket.Application.UnitTests.Domain;
 
public class CouponTests
{
    [Fact]
    public void ApplyTo_TrongThoiGianHieuLuc_PhaiTinhDungGiaSauGiam()
    {
        var coupon = Coupon.Create("TEDU20", Discount.Percent(20),
            new DateTime(2026, 9, 1), new DateTime(2026, 9, 30));
 
        var finalPrice = coupon.ApplyTo(500_000m, new DateTime(2026, 9, 15));
 
        Assert.Equal(400_000m, finalPrice);
    }
 
    [Fact]
    public void ApplyTo_KhiHetHan_PhaiThrowCouponExpiredException()
    {
        var coupon = Coupon.Create("TEDU20", Discount.Percent(20),
            new DateTime(2026, 9, 1), new DateTime(2026, 9, 30));
 
        var act = () => coupon.ApplyTo(500_000m, new DateTime(2026, 10, 1));
 
        Assert.Throws<CouponExpiredException>(act);
    }
 
    [Theory]
    [InlineData(0)]
    [InlineData(101)]
    public void Percent_NgoaiKhoangChoPhep_PhaiThrowException(decimal percentage)
    {
        var act = () => Discount.Percent(percentage);
 
        Assert.Throws<ArgumentOutOfRangeException>(act);
    }
}
```

> **📘 Ghi chú giảng viên:** *Đây là chỗ đúng để dùng [Theory] thay vì viết 2 [Fact] riêng cho 0% và 101%: hai case này test cùng MỘT hành vi ("ngoài khoảng thì throw"), chỉ khác dữ liệu đầu vào. Quy tắc tôi hay nhắc: nếu bạn thấy 2 test có structure Arrange-Act-Assert giống hệt nhau, chỉ số liệu khác — gộp thành Theory.*

### 4. Chạy test và tổng kết tốc độ

*Thời lượng: 5 phút | Loại: Demo*


Quan sát thời gian chạy trong output — 5 test này thường chạy xong trong vài mili-giây, so với test Handler ở bài 8.1 (phải khởi tạo mock object) đã chậm hơn, và sẽ càng rõ khoảng cách khi so với Integration Test ở bài 8.3 (phải dựng Postgres container thật, chạy hàng giây thay vì mili-giây).

## Bài tập / Thực hành

> **✏️ Thực hành:** Viết test cho rule thứ 3 của Coupon (bài 2.3): "giới hạn Course áp dụng" — một Coupon chỉ hợp lệ cho một danh sách Course cụ thể (ví dụ Coupon khuyến mãi riêng cho khóa ASP.NET Core, không áp dụng được cho khóa khác).

Input: một Coupon được tạo với danh sách ApplicableCourseIds chỉ chứa courseId A. Gọi ApplyTo với courseId B (không nằm trong danh sách).

Expected output: phải throw một exception mới, đặt tên đúng theo quy ước mục 7 — CouponNotApplicableException (không dùng ArgumentException chung chung, vì đây là lỗi nghiệp vụ, không phải lỗi tham số kỹ thuật).

Hint 1: Coupon.Create cần thêm tham số IEnumerable\<Guid> applicableCourseIds. ApplyTo cần thêm tham số courseId để kiểm tra.

Hint 2: Nếu applicableCourseIds rỗng, coi như Coupon áp dụng cho MỌI Course (đừng bắt học viên phải luôn truyền danh sách).

Solution (tham khảo, chỉ mở sau khi đã tự làm):

```csharp
// Domain/Ordering/Coupon.cs — bổ sung
public decimal ApplyTo(decimal originalPrice, DateTime now, Guid courseId)
{
    if (!IsValidAt(now))
        throw new CouponExpiredException(Code);
 
    if (_applicableCourseIds.Count > 0 && !_applicableCourseIds.Contains(courseId))
        throw new CouponNotApplicableException(Code, courseId);
 
    return Discount.ApplyTo(originalPrice);
}
 
// Test
[Fact]
public void ApplyTo_KhiCourseKhongNamTrongDanhSachApDung_PhaiThrowException()
{
    var courseA = Guid.NewGuid();
    var courseB = Guid.NewGuid();
    var coupon = Coupon.Create("TEDU-ASPNET", Discount.Percent(10),
        new DateTime(2026, 9, 1), new DateTime(2026, 9, 30), new[] { courseA });
 
    var act = () => coupon.ApplyTo(500_000m, new DateTime(2026, 9, 15), courseB);
 
    Assert.Throws<CouponNotApplicableException>(act);
}
```

## Tổng kết

- Domain layer (Entity/Aggregate/Value Object thuần) test được mà không cần mock, không cần DB — vì đây là logic thuần, không side-effect.
- Test invariant Publish() của Course đã có từ bài 1.1 — bài này chỉ bổ sung case biên, không viết lại từ đầu.
- Discount và Coupon (bài 2.1/2.3) có business rule rõ ràng (% giảm hợp lệ, thời hạn hiệu lực) — mỗi rule nên có ít nhất 1 test.
- [Fact] cho 1 case cụ thể; [Theory] + [InlineData] khi nhiều input test cùng 1 hành vi.
- Luôn assert đúng loại Exception cụ thể (theo quy ước {Thực thể}{LoạiLỗi}Exception), không assert Exception chung chung.

| **Loại test** | **Bài học** | **Tốc độ chạy** |
|---|---|---|
| Unit Test Handler | 8.1 | Vài ms / test (có mock) |
| Unit Test Domain | 8.2 (bài này) | Dưới 1 ms / test |
| Integration Test | 8.3 (tiếp theo) | Vài giây / test (Postgres thật) |

> **✅ Tóm tắt:** Bài tiếp theo — 8.3: Integration Test với WebApplicationFactory + Testcontainers, nơi bạn sẽ thấy sự đánh đổi ngược lại: chậm hơn nhiều, nhưng bắt được lỗi migration và lỗi SQL mà unit test domain/handler không thấy được.

## Phụ lục — Cheatsheet xUnit.net v3

| **Attribute / Method** | **Dùng khi nào** | **Ví dụ** |
|---|---|---|
| [Fact] | Test đúng cho mọi trường hợp, không có input thay đổi | 1 test case cụ thể |
| [Theory] + [InlineData] | Cùng 1 hành vi, nhiều bộ input khác nhau | Boundary test (0, 101) |
| Assert.Equal(expected, actual) | So sánh giá trị mong đợi và thực tế | Assert.Equal(400000m, price) |
| Assert.Throws\<T>(action) | Xác nhận method ném đúng loại Exception | Assert.Throws\<CouponExpiredException> |
| Assert.True / Assert.False | Kiểm tra điều kiện boolean | Assert.True(coupon.IsValidAt(now)) |

> **📘 Ghi chú giảng viên:** *Lưu ý về thư viện assertion: từ bản 8.0, FluentAssertions đã đổi sang giấy phép thương mại (Xceed) — chỉ miễn phí cho mục đích phi thương mại. Vì TEDU Market là sản phẩm thương mại, bài này chủ đích dùng Assert built-in của xUnit để tránh rủi ro bản quyền. Nếu muốn cú pháp "đọc như tiếng Anh" hơn, Shouldly (MIT, miễn phí hoàn toàn) là lựa chọn thay thế an toàn — không bắt buộc trong khóa.*
