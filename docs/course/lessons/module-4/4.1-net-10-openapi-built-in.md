## **Nội dung chính**

### **1. Vì sao Module 4 bắt đầu bằng OpenAPI (10 phút)**

Từ bài 0.7, bạn đã build endpoint bằng Minimal API và nó chạy được thật qua Scalar/Postman. Nhưng đến giờ, endpoint mới chỉ “chạy được” — chưa có metadata mô tả chính xác kiểu dữ liệu, mã lỗi có thể trả về, hay ý nghĩa từng tham số. Module 4 tồn tại vì một lý do rất cụ thể: ở Module 5, bạn sẽ dùng @hey-api/openapi-ts để generate type-safe client từ chính file openapi.json này. Generator không đoán được điều gì bạn không khai báo — nó chỉ đọc đúng những gì có trong document. Annotate sơ sài ở bài này đồng nghĩa với việc cả 2 app React Admin và Next.js ở Module 6–7 nhận type sai hoặc type any.

Từ .NET 9, ASP.NET Core có sẵn hỗ trợ sinh tài liệu OpenAPI thông qua package Microsoft.AspNetCore.OpenApi — không cần Swashbuckle. .NET 10 nâng cấp package này lên 2 điểm đáng chú ý cho khóa học:

- Document mặc định sinh ra theo chuẩn OpenAPI 3.1 (thay vì 3.0 như các bản .NET cũ hơn).
- Hỗ trợ đọc XML documentation comment (///summary, ///param) trực tiếp từ code để điền vào summary/description — trước .NET 10, muốn có mô tả trong OpenAPI, bạn bắt buộc phải gọi WithSummary/WithDescription bằng tay cho từng endpoint.

Microsoft.AspNetCore.OpenApi chỉ sinh document (file JSON/YAML mô tả API) — nó không đi kèm giao diện xem trực quan như Swagger UI. Giao diện đó là Scalar, học ở bài 4.2 ngay sau bài này.

> **📘 Ghi chú giảng viên:** *Tôi hay dừng ở đây để hỏi học viên: “Ai từng dùng [SwaggerOperation] hay XML comment với Swashbuckle ở khóa nền tảng?” — phần lớn sẽ nói có. Điểm khác biệt cần nhấn: Swashbuckle đọc XML comment qua reflection lúc runtime và cấu hình khá lằng nhằng (IncludeXmlComments, đường dẫn file .xml); OpenAPI built-in của .NET 10 dùng source generator lúc build-time, không cần cấu hình gì thêm ngoài bật GenerateDocumentationFile.*

### **2. Cài đặt Microsoft.AspNetCore.OpenApi (5 phút)**

Thêm package vào TeduMarket.Api (project duy nhất có OpenIddict + Minimal API endpoint theo quyết định kiến trúc mục 5.2 của khóa):

```bash
dotnet add package Microsoft.AspNetCore.OpenApi --version 10.0.*
```

Bật sinh file XML documentation — đây là điều kiện bắt buộc để tính năng đọc XML comment của .NET 10 hoạt động, thêm vào TeduMarket.Api.csproj:

```
<PropertyGroup>
  <TargetFramework>net10.0</TargetFramework>
  <Nullable>enable</Nullable>
  <ImplicitUsings>enable</ImplicitUsings>
  <GenerateDocumentationFile>true</GenerateDocumentationFile>
  <NoWarn>$(NoWarn);CS1591</NoWarn>
</PropertyGroup>
```

CS1591 là warning “thiếu XML comment cho public member” — tắt warning này vì chúng ta chỉ chủ động viết comment cho endpoint cần thiết, không bắt buộc toàn bộ codebase.

Đăng ký service và map endpoint xem document trong Program.cs:

```csharp
// TeduMarket.Api/Program.cs
builder.Services.AddOpenApi(options =>
{
    // .NET 10 mặc định sinh OpenAPI 3.1 — giữ nguyên, không cần đổi
    options.AddDocumentTransformer((document, context, ct) =>
    {
        document.Info.Title = "TEDU Market API";
        document.Info.Version = "v1";
        document.Info.Description =
            "API cho nền tảng bán khóa học trực tuyến TEDU Market.";
        return Task.CompletedTask;
    });
});
 
var app = builder.Build();
 
if (app.Environment.IsDevelopment())
{
    app.MapOpenApi(); // GET /openapi/v1.json
}
```

> **📘 Ghi chú giảng viên:** *AddDocumentTransformer là API “transformer” chính thức của Microsoft.AspNetCore.OpenApi để chỉnh sửa document sau khi sinh — dùng cho thông tin ở cấp document (title, version, mô tả chung), khác với WithOpenApi (chỉnh metadata ở cấp một endpoint) mà ta dùng ngay bên dưới.*

### **3. Annotate endpoint theo từng nhóm (15 phút)**

Nguyên tắc annotate áp dụng thống nhất cho mọi endpoint từ Module 0 đến Module 3, theo đúng bảng metadata chuẩn của OpenAPI trong Minimal API:

- `WithName` — operation ID duy nhất, dùng cho link generation và là tên hàm được @hey-api/openapi-ts sinh ra ở Module 5. Đặt theo PascalCase, mô tả hành động: `CreateCourse`, `GetCourseDetail`.
- `WithTags` — nhóm endpoint trong document, tương ứng 1 tag = 1 nhóm nghiệp vụ (Categories, Courses, Orders, Payments, Auth). Đây cũng là nhóm hiển thị trên Scalar UI ở bài 4.2.
- `WithSummary / WithDescription` — có thể set trực tiếp bằng extension method, hoặc để .NET 10 tự đọc từ XML doc comment trên delegate. Bài này ưu tiên XML comment cho endpoint phức tạp (nhiều rule nghiệp vụ), dùng WithSummary nhanh cho endpoint đơn giản.
- `Produces<T> / ProducesProblem` — khai báo chính xác response type theo từng status code. Đây là phần ảnh hưởng trực tiếp nhất đến TypeScript sinh ra: thiếu khai báo → openapi-ts không biết field nào, sinh ra `unknown`.

Ví dụ 1 — Category (bài 0.7, endpoint đơn giản, dùng WithSummary trực tiếp):

```csharp
// TeduMarket.Api/Endpoints/CategoryEndpoints.cs
app.MapPost("/api/v1/categories", async (
    CreateCategoryCommand command, ISender sender) =>
{
    var categoryId = await sender.Send(command);
    return Results.Created($"/api/v1/categories/{categoryId}", new { id = categoryId });
})
.WithName("CreateCategory")
.WithSummary("Tạo mới một Category")
.WithDescription("Tên Category không được rỗng — kiểm tra qua CreateCategoryCommandValidator.")
.WithTags("Categories")
.Produces<CreateCategoryResponse>(StatusCodes.Status201Created)
.ProducesValidationProblem();
```

Ví dụ 2 — Course Detail (bài 1.7, endpoint phức tạp hơn, ưu tiên XML doc comment vì handler đã tách riêng thành method, không còn là lambda inline):

```csharp
// TeduMarket.Api/Endpoints/CourseEndpoints.cs
app.MapGet("/api/v1/courses/{slug}", GetCourseDetailAsync)
    .WithName("GetCourseDetail")
    .WithTags("Courses")
    .Produces<CourseDetailResponse>(StatusCodes.Status200OK)
    .ProducesProblem(StatusCodes.Status404NotFound);
 
/// <summary>Lấy chi tiết Course kèm Lesson và Instructor theo slug.</summary>
/// <param name="slug">Slug định danh Course, ví dụ "aspnet-core-10-cqrs".</param>
/// <param name="sender">MediatR sender, DI tự inject.</param>
/// <remarks>
/// Dùng 1 câu Dapper multi-mapping (bài 1.7) để tránh N+1 khi lấy
/// đồng thời Course, danh sách Lesson và Instructor.
/// </remarks>
static async Task<IResult> GetCourseDetailAsync(string slug, ISender sender)
{
    var query = new GetCourseDetailQuery(slug);
    var result = await sender.Send(query);
    return result is null ? Results.NotFound() : Results.Ok(result);
}
```

Vì GetCourseDetailAsync là static local function có XML comment và GenerateDocumentationFile đã bật, .NET 10 tự điền Summary/Description vào OpenAPI operation — không cần gọi WithSummary/WithDescription thêm. Chạy /openapi/v1.json sau bài này để thấy rõ 2 cách annotate cho cùng một kết quả.

Ví dụ 3 — Checkout (bài 2.2, nhiều response type khác nhau theo kết quả nghiệp vụ):

```csharp
app.MapPost("/api/v1/cart/checkout", async (
    CheckoutCommand command, ISender sender) =>
{
    var orderId = await sender.Send(command);
    return Results.Ok(new { orderId, status = "Pending" });
})
.WithName("Checkout")
.WithSummary("Chuyển Cart hiện tại thành Order ở trạng thái Pending")
.WithTags("Orders")
.Produces<CheckoutResponse>(StatusCodes.Status200OK)
.ProducesValidationProblem()
.ProducesProblem(StatusCodes.Status404NotFound) // Course trong Cart không còn tồn tại
.RequireAuthorization();
```

> **📘 Ghi chú giảng viên:** *Điểm hay bị hỏi: học viên hỏi có cần gọi .WithOpenApi() không, vì tutorial cũ hay thấy. Trả lời rõ: với Microsoft.AspNetCore.OpenApi từ .NET 9+, WithOpenApi() KHÔNG bắt buộc — metadata từ WithName/WithTags/Produces đã tự động được framework đọc. WithOpenApi() chỉ cần khi muốn chỉnh tay sâu vào OpenApiOperation sinh ra (ví dụ set Deprecated = true) mà không extension method nào hỗ trợ.*

### **4. Kiểm tra kết quả (bonus, không tính vào 30 phút)**

Chạy app ở môi trường Development và mở /openapi/v1.json — kiểm tra 3 điều:

- Mọi endpoint đã annotate đều xuất hiện với đúng operationId (khớp WithName).
- Mỗi endpoint có đúng tag nhóm (Categories/Courses/Orders/Payments/Auth).
- Response schema khớp property của DTO thật (không phải object{} rỗng) — nếu thấy schema rỗng, khả năng cao endpoint đó dùng Results.Ok(anonymousObject) thay vì kiểu cụ thể; sửa lại thành DTO có tên (record/class) rồi khai báo qua Produces\<T>.

## **Bài tập thực hành**

> **✏️ Thực hành:** Annotate toàn bộ endpoint còn lại của Module 1 (Lesson, Instructor), Module 2 (AddToCart, ApplyCoupon, InitiatePayment, GetOrderPaymentStatus, GetOrderHistory, GetInstructorRevenue) và Module 3 (các endpoint OpenIddict áp dụng được — /connect/token thường không cần annotate vì OpenIddict tự quản lý, nhưng endpoint nghiệp vụ có [Authorize(Policy="InstructorOnly")] thì cần) theo đúng pattern 3 ví dụ trên. Input: toàn bộ endpoint hiện có trong TeduMarket.Api. Expected output: chạy dotnet run, mở /openapi/v1.json, đếm đủ số operationId tương ứng số endpoint, không còn tag mặc định do framework tự sinh (ví dụ tag trùng tên class Program).

Hint: nếu một nhóm endpoint đã tách theo Endpoint Group (bài 0.7) bằng app.MapGroup("/api/v1/courses"), bạn có thể gọi .WithTags("Courses") một lần trên group thay vì lặp lại trên từng endpoint con — .WithTags trên group áp dụng cho toàn bộ endpoint bên trong trừ khi endpoint con override lại.

Solution tham khảo: đối chiếu file openapi.json học viên tự sinh với danh sách endpoint đã liệt kê ở outline Module 0–3 — nếu thiếu operationId nào, quay lại endpoint đó bổ sung WithName.

## **Tổng kết**

> **✅ Tóm tắt: Bài 4.1**

- Microsoft.AspNetCore.OpenApi là hỗ trợ built-in của .NET 9+, .NET 10 nâng lên OpenAPI 3.1 và thêm khả năng đọc XML documentation comment — không cần Swashbuckle.
- AddOpenApi() đăng ký service, MapOpenApi() (giới hạn Development) expose document tại /openapi/{documentName}.json.
- 5 metadata cốt lõi cho mỗi endpoint: WithName (operationId), WithTags (nhóm), WithSummary/WithDescription (mô tả — có thể thay bằng XML comment), Produces\<T>/ProducesProblem (response type theo status code).
- WithOpenApi() không bắt buộc trong .NET 10 — chỉ dùng khi cần chỉnh tay OpenApiOperation ngoài phạm vi các extension method có sẵn.
- Chất lượng annotate ở bài này quyết định trực tiếp chất lượng TypeScript sinh ra ở Module 5 — đây là lý do Module 4 đứng trước Module 5 trong outline.

*Bước tiếp theo: Bài 4.2 sẽ thay Swagger UI truyền thống bằng Scalar — giao diện trực quan để xem và test ngay document openapi.json vừa hoàn thiện, bao gồm test thử luồng OAuth2 đã cấu hình ở Module 3.*
