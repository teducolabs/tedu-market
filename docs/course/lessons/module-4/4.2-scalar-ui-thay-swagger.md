# **Nội dung chính**

## **1. Từ Swagger sang Scalar — cài đặt cơ bản**

*Thời lượng: 5 phút | Loại: Demo*

Từ .NET 9, Microsoft đã bỏ Swashbuckle khỏi template mặc định và chuyển sang Microsoft.AspNetCore.OpenApi — gói built-in do chính đội ASP.NET Core duy trì, sinh ra tài liệu OpenAPI 3.1 (bài 4.1 đã cấu hình xong phần này). Việc sinh tài liệu và việc hiển thị tài liệu (UI) giờ là hai việc tách biệt: bạn phải tự chọn thêm một package UI. TEDU Market chọn Scalar.AspNetCore thay vì kéo lại Swagger UI, vì Scalar có giao diện hiện đại hơn, có sẵn dark mode, và request builder (thử API trực tiếp trên UI) mượt hơn Swagger UI cũ.

### **Cài đặt package**

```bash
# Chạy trong thư mục project TeduMarket.Api
dotnet add package Scalar.AspNetCore
```

### **Cấu hình Program.cs**

Trong bài 4.1 bạn đã có builder.Services.AddOpenApi() và app.MapOpenApi(). Giờ thêm MapScalarApiReference() ngay sau đó:

```csharp
using Scalar.AspNetCore;
 
// ... builder.Services.AddOpenApi(...) đã có từ bài 4.1
 
var app = builder.Build();
 
if (app.Environment.IsDevelopment())
{
    app.MapOpenApi();          // sinh /openapi/v1.json
    app.MapScalarApiReference(); // UI tại /scalar
}
```

Chạy project, mở trình duyệt vào https://localhost:\<port>/scalar — mặc định route của Scalar.AspNetCore là /scalar (không phải /scalar/v1 như vài bài viết cũ hay ghi nhầm). Bạn sẽ thấy toàn bộ endpoint đã xây từ Module 0 đến Module 3, đúng schema kiểu dữ liệu nhờ bài 4.1 đã annotate kỹ.

> **📘 Ghi chú giảng viên:** *Tôi hay set sẵn "launchUrl": "scalar" và "launchBrowser": true trong Properties/launchSettings.json, để bấm F5 là mở thẳng vào Scalar — đỡ mất công gõ URL mỗi lần demo. Nhắc học viên: route /openapi/v1.json và /scalar hiện đang public hoàn toàn, ai cũng xem được nếu biết địa chỉ — đây chỉ là môi trường Development, sẽ siết lại ở Module 9 (production).*

## **2. Khai báo OAuth2 Security Scheme cho OpenIddict**

*Thời lượng: 10 phút | Loại: Demo*

Vấn đề: dù nhiều endpoint của TeduMarket.Api đã có [Authorize] hoặc .RequireAuthorization() từ Module 3, tài liệu OpenAPI sinh ra ở bài 4.1 hoàn toàn không nhắc gì đến việc phải đăng nhập — AddOpenApi() mặc định không tự suy ra security scheme từ OpenIddict. Vì vậy Scalar chưa hiện nút "Authorize", và bạn không thể test các endpoint cần token ngay trên UI. Phải khai báo scheme này thủ công bằng Document Transformer.

### **2.1. Đăng ký OAuth2 Security Scheme (Document Transformer)**

Microsoft.OpenApi mà .NET 10 dùng là bản v2 — đổi namespace và một số kiểu so với các bài hướng dẫn .NET 8/9 cũ (không còn Microsoft.OpenApi.Models, không còn OpenApiReference { Type = ReferenceType.SecurityScheme }). Nếu bạn copy code kiểu cũ vào sẽ lỗi biên dịch ngay. Dùng đúng API mới:

```csharp
// TeduMarket.Api/OpenApi/OAuth2SecuritySchemeTransformer.cs
using Microsoft.OpenApi;
 
namespace TeduMarket.Api.OpenApi;
 
public sealed class OAuth2SecuritySchemeTransformer : IOpenApiDocumentTransformer
{
    public Task TransformAsync(
        OpenApiDocument document,
        OpenApiDocumentTransformerContext context,
        CancellationToken cancellationToken)
    {
        document.Components ??= new OpenApiComponents();
        document.Components.SecuritySchemes ??= new Dictionary<string, IOpenApiSecurityScheme>();
 
        document.Components.SecuritySchemes["OAuth2"] = new OpenApiSecurityScheme
        {
            Type = SecuritySchemeType.OAuth2,
            Flows = new OpenApiOAuthFlows
            {
                AuthorizationCode = new OpenApiOAuthFlow
                {
                    AuthorizationUrl = new Uri("/connect/authorize", UriKind.Relative),
                    TokenUrl = new Uri("/connect/token", UriKind.Relative),
                    Scopes = new Dictionary<string, string>
                    {
                        ["openid"] = "Đăng nhập OpenID Connect",
                        ["profile"] = "Đọc thông tin hồ sơ người dùng",
                        ["tedumarket_api"] = "Gọi TeduMarket API (Course, Order, ...)",
                        ["offline_access"] = "Cấp refresh token"
                    }
                }
            }
        };
 
        // Cho các OpenApiSecuritySchemeReference tạo ở Operation Transformer
        // (chạy trước) được gắn đúng vào document cuối cùng
        document.SetReferenceHostDocument();
 
        return Task.CompletedTask;
    }
}
```

> **📘 Ghi chú giảng viên:** *Tên scope "tedumarket_api" và "offline_access" ở đây tôi đặt theo quy ước resource scope thường dùng với OpenIddict — phải khớp chính xác với danh sách scope bạn đã đăng ký ở bài 3.2 (AddScopes) và gắn cho OpenIddict Client ở bài 3.5. Nếu tên khác, sửa lại dictionary Scopes cho đúng, nếu không nút Authorize trên Scalar sẽ xin quyền sai tên và OpenIddict server sẽ từ chối cấp token.*

### **2.2. Chỉ áp security requirement cho endpoint cần đăng nhập**

TEDU Market có endpoint public thật sự — ví dụ GET /api/v1/courses (duyệt khóa học, bài 1.6) không cần đăng nhập. Nếu gắn security requirement toàn cục cho cả document, Scalar sẽ đòi Authorize cả những endpoint này, gây hiểu lầm. Cách đúng: dùng Operation Transformer, chỉ thêm requirement cho endpoint KHÔNG có [AllowAnonymous]:

```csharp
// TeduMarket.Api/OpenApi/OAuth2OperationTransformer.cs
using Microsoft.AspNetCore.Authorization;
using Microsoft.OpenApi;
 
namespace TeduMarket.Api.OpenApi;
 
public sealed class OAuth2OperationTransformer : IOpenApiOperationTransformer
{
    public Task TransformAsync(
        OpenApiOperation operation,
        OpenApiOperationTransformerContext context,
        CancellationToken cancellationToken)
    {
        var isAnonymous = context.Description.ActionDescriptor.EndpointMetadata
            .OfType<AllowAnonymousAttribute>()
            .Any();
 
        if (isAnonymous)
        {
            return Task.CompletedTask;
        }
 
        operation.Security ??= [];
        operation.Security.Add(new OpenApiSecurityRequirement
        {
            [new OpenApiSecuritySchemeReference("OAuth2")] =
                ["tedumarket_api"]
        });
 
        return Task.CompletedTask;
    }
}
```

Đăng ký cả 2 transformer trong Program.cs:

```csharp
builder.Services.AddOpenApi(options =>
{
    options.AddDocumentTransformer<OAuth2SecuritySchemeTransformer>();
    options.AddOperationTransformer<OAuth2OperationTransformer>();
});
```

> **📘 Ghi chú giảng viên:** *Điểm hay bị hỏi: tại sao Operation Transformer chạy TRƯỚC Document Transformer mà vẫn tham chiếu được security scheme "OAuth2" — lúc đó scheme chưa tồn tại trong document? Trả lời: OpenApiSecuritySchemeReference chỉ giữ một chuỗi id, việc tra cứu ra scheme thật chỉ xảy ra lúc serialize tài liệu ra JSON, sau khi mọi transformer (kể cả Document Transformer thêm scheme) đã chạy xong — document.SetReferenceHostDocument() là bước nối các reference "treo" đó vào đúng document cuối cùng. Thứ tự chạy: Schema → Operation → Document (đã học nguyên tắc này ở phần OpenAPI transformer bài 4.1).*

Tải lại /scalar: các endpoint public (GET /api/v1/courses, GET /api/v1/categories) không còn ổ khoá, còn các endpoint như PUT /api/v1/courses/{id} (UpdateCourse, đang được bảo vệ bởi Policy "InstructorOnly" từ bài 3.7) hiện ổ khoá và nút Authorize đã xuất hiện ở góc trên bên phải.

## **3. Đăng ký Test Client & đăng nhập thử trên Scalar UI**

*Thời lượng: 5 phút | Loại: Demo*

Khai báo scope xong, Scalar đã biết "phải xin quyền gì" nhưng chưa có Client nào để thực hiện luồng Authorization Code + PKCE. Không dùng lại Client đã đăng ký cho React Admin ở bài 3.3 — nên tạo riêng 1 Client public dành cho việc test tài liệu API, tách biệt với client thật của frontend, đúng khuyến nghị bảo mật: ứng dụng chạy hoàn toàn trên trình duyệt (Scalar cũng vậy) không giữ được client secret an toàn, nên phải là public client + PKCE, không có secret.

### **3.1. Đăng ký OpenIddict Client cho Scalar**

Thêm vào đoạn seed Client trong Program.cs hoặc worker seed data (giống cách đã làm ở bài 3.3 cho React Admin):

```csharp
await manager.CreateAsync(new OpenIddictApplicationDescriptor
{
    ClientId = "scalar-test-client",
    ClientType = ClientTypes.Public,      // không có ClientSecret
    ConsentType = ConsentTypes.Explicit,
    DisplayName = "Scalar API Reference (test)",
    RedirectUris = { new Uri("https://localhost:7001/scalar/oauth/callback") },
    Permissions =
    {
        Permissions.Endpoints.Authorization,
        Permissions.Endpoints.Token,
        Permissions.GrantTypes.AuthorizationCode,
        Permissions.ResponseTypes.Code,
        Permissions.Scopes.Profile,
        Permissions.Prefixes.Scope + "tedumarket_api",
        Permissions.Prefixes.Scope + "offline_access"
    },
    Requirements =
    {
        Requirements.Features.ProofKeyForCodeExchange   // bắt buộc PKCE
    }
});
```

> **📘 Ghi chú giảng viên:** *Giá trị RedirectUris "https://localhost:7001/scalar/oauth/callback" là quy ước Scalar.AspNetCore tự sinh theo route UI (ở đây là /scalar mặc định), nhưng tài liệu chính thức của Scalar không liệt kê cố định pattern này — cách chắc ăn nhất khi lên lớp: mở nút Authorize trên Scalar trước, Scalar sẽ tự hiện đúng giá trị Redirect URI cần đăng ký, copy y nguyên giá trị đó dán vào RedirectUris rồi mới chạy migration/seed lại. Đừng gõ tay theo trí nhớ, và cổng (7001) phải đúng cổng https thật của project bạn.*

### **3.2. Cho Scalar tự điền sẵn thông tin đăng nhập**

Scalar hỗ trợ pre-fill Client ID và bật PKCE mặc định, đỡ phải gõ tay mỗi lần demo — chỉ dùng trong Development, không bao giờ đưa các dòng này lên production vì thông tin sẽ lộ ngay trên trình duyệt:

```csharp
app.MapScalarApiReference(options => options
    .AddPreferredSecuritySchemes("OAuth2")
    .AddAuthorizationCodeFlow("OAuth2", flow =>
    {
        flow.ClientId = "scalar-test-client";
        flow.Pkce = Pkce.Sha256;
        flow.SelectedScopes = ["openid", "profile", "tedumarket_api"];
    }));
```

Reload /scalar, bấm Authorize → chọn scope → Scalar chuyển hướng sang /connect/authorize của OpenIddict → đăng nhập bằng tài khoản Instructor đã seed sẵn từ Module 3 → OpenIddict redirect ngược lại kèm authorization code → Scalar tự đổi code lấy access token qua /connect/token (có gửi code_verifier vì PKCE) → token được tự động đính kèm header Authorization cho các lần Try It sau đó.

> **✏️ Thực hành:** Đăng nhập thành công trên Scalar bằng tài khoản Instructor, sau đó gọi thử PUT /api/v1/courses/{id} (UpdateCourse) với 1 courseId do chính Instructor đó sở hữu — endpoint phải trả về 200 OK. Sau đó thử lại với 1 courseId KHÔNG thuộc Instructor này — endpoint phải trả về 403 Forbidden, đúng logic CourseOwnerRequirement đã xây ở bài 3.8. Nếu quên mật khẩu tài khoản seed, xem lại ghi chú seed data ở bài 1.5/3.2.Gợi ý nếu bị kẹt: nếu Scalar báo lỗi CORS khi gọi /connect/token, kiểm tra origin https://localhost:\<port> đã được thêm vào CORS policy của OpenIddict server chưa (xem lại bài 3.9). Nếu Authorize xong nhưng gọi API vẫn 401, decode access token bằng jwt.io kiểm tra claim "scope" có đúng "tedumarket_api" không — nếu thiếu, chỉnh lại SelectedScopes ở bước 3.2.
