# Nội dung chính

## 1. Vì sao Order History & Doanh thu cần Read Model riêng

*Thời lượng: 10 phút | Loại: Lý thuyết*

Order Aggregate bạn xây từ bài 2.1 là Write Model — nhiệm vụ của nó là bảo vệ tính toàn vẹn nghiệp vụ: Cart chuyển thành Order đúng luồng, trạng thái chuyển Pending → Paid đúng 1 lần dù webhook gọi nhiều lần (bài 2.5, 2.9), Outbox ghi đúng transaction (bài 2.6). Nó tồn tại để ghi đúng, không phải để đọc nhanh.

Order History và Doanh thu Instructor lại là hai nhu cầu đọc thuần túy, không hề đổi trạng thái Order:

- Order History: liệt kê hàng trăm, hàng nghìn đơn hàng, cần phân trang, filter theo trạng thái và khoảng thời gian.
- Doanh thu Instructor: cần SUM theo Instructor, theo ngày hoặc tháng — một phép tổng hợp SQL trên nhiều dòng OrderItem cùng lúc.

Nếu tái dùng OrderRepository (EF Core) cho hai việc này, bạn đụng đúng vấn đề đã nói ở bài 0.8 và 1.6: EF Core tối ưu cho việc load 1 Aggregate đầy đủ navigation property để ghi, không tối ưu cho việc quét hàng loạt rồi GROUP BY. Load toàn bộ Order và OrderItem qua EF Core rồi SUM bằng LINQ-to-Objects trong bộ nhớ chắc chắn sẽ chậm khi dữ liệu lớn lên.

Nguyên tắc giữ nguyên từ bài 0.8: **Read Model không tái sử dụng Entity của Write side.** GetOrderHistoryQuery và GetInstructorRevenueQuery đọc thẳng bằng Dapper raw SQL, chiếu ra DTO — không đụng đến class Order, OrderItem trong Domain layer.

> **📘 Ghi chú giảng viên:** *Tôi hay dừng ở đây để hỏi học viên: "Nếu Order Aggregate đã có property TotalAmount rồi, sao Doanh thu Instructor không SUM(TotalAmount) cho nhanh?" — câu trả lời đúng nằm ở Phần 4: một Order có thể chứa khóa học của nhiều Instructor khác nhau trong cùng giỏ hàng, nên phải tính theo OrderItem chứ không phải theo Order.*

## 3. GetOrderHistoryQuery

*Thời lượng: 15 phút | Loại: Demo + Lab*

public sealed record GetOrderHistoryQuery(

PagedResult\<T> đã định nghĩa ở bài 1.6 (GetCoursesQuery) — dùng lại nguyên, không viết lại:

```csharp
public sealed record PagedResult<T>(
    IReadOnlyList<T> Items,
    int TotalCount,
    int Page,
    int PageSize
);
```

Handler dùng lại IDbConnectionFactory từ bài 0.8, không tạo interface mới:

```csharp
namespace TeduMarket.Application.Orders.Queries.GetOrderHistory;
 
public sealed class GetOrderHistoryQueryHandler(IDbConnectionFactory connectionFactory)
    : IRequestHandler<GetOrderHistoryQuery, PagedResult<OrderHistoryItemDto>>
{
    public async Task<PagedResult<OrderHistoryItemDto>> Handle(
        GetOrderHistoryQuery request, CancellationToken cancellationToken)
    {
        using var connection = connectionFactory.CreateConnection();
 
        var filters = new List<string>();
        var parameters = new DynamicParameters();
 
        if (request.UserId is { } userId)
        {
            filters.Add("o.user_id = @UserId");
            parameters.Add("UserId", userId);
        }
 
        if (!string.IsNullOrWhiteSpace(request.Status))
        {
            filters.Add("o.status = @Status");
            parameters.Add("Status", request.Status);
        }
 
        if (request.FromDate is { } fromDate)
        {
            filters.Add("o.created_at >= @FromDate");
            parameters.Add("FromDate", fromDate);
        }
 
        if (request.ToDate is { } toDate)
        {
            filters.Add("o.created_at <= @ToDate");
            parameters.Add("ToDate", toDate);
        }
 
        var whereClause = filters.Count > 0
            ? "WHERE " + string.Join(" AND ", filters)
            : string.Empty;
 
        parameters.Add("Skip", (request.Page - 1) * request.PageSize);
        parameters.Add("Take", request.PageSize);
 
        var sql = $"""
            SELECT COUNT(*) FROM orders o {whereClause};
 
            SELECT
                o.id           AS OrderId,
                o.payment_code AS PaymentCode,
                o.status       AS Status,
                o.total_amount AS TotalAmount,
                COUNT(oi.id)   AS ItemCount,
                o.created_at   AS CreatedAt,
                o.paid_at      AS PaidAt
            FROM orders o
            LEFT JOIN order_items oi ON oi.order_id = o.id
            {whereClause}
            GROUP BY o.id
            ORDER BY o.created_at DESC
            OFFSET @Skip LIMIT @Take;
            """;
 
        using var multi = await connection.QueryMultipleAsync(sql, parameters);
        var totalCount = await multi.ReadSingleAsync<int>();
        var items = (await multi.ReadAsync<OrderHistoryItemDto>()).ToList();
 
        return new PagedResult<OrderHistoryItemDto>(
            items, totalCount, request.Page, request.PageSize);
    }
}
```

> **📘 Ghi chú giảng viên:** *Điểm hay bị làm sai nhất ở đây — build WHERE clause động. Không bao giờ nối trực tiếp giá trị filter vào chuỗi SQL, kể cả khi giá trị đó chỉ là ToString() của một enum. Danh sách filters chỉ chứa tên cột và operator do chính bạn viết cố định trong code; giá trị luôn đi qua DynamicParameters. Đây chính là lý do string interpolation ở đây an toàn: phần {whereClause} chỉ lắp ráp mảnh SQL cố định, không lắp giá trị người dùng nhập.*

## 4. GetInstructorRevenueQuery

*Thời lượng: 15 phút | Loại: Demo + Lab*

Query và DTO — TeduMarket.Application/Orders/Queries/GetInstructorRevenue/GetInstructorRevenueQuery.cs:

```csharp
namespace TeduMarket.Application.Orders.Queries.GetInstructorRevenue;
 
public enum RevenueGroupBy { Day, Month }
 
public sealed record GetInstructorRevenueQuery(
    Guid InstructorId,
    DateTimeOffset FromDate,
    DateTimeOffset ToDate,
    RevenueGroupBy GroupBy = RevenueGroupBy.Month
) : IRequest<InstructorRevenueDto>;
 
public sealed record InstructorRevenueDto(
    Guid InstructorId,
    decimal TotalRevenue,
    int TotalOrders,
    IReadOnlyList<RevenueByPeriodDto> Breakdown
);
 
public sealed record RevenueByPeriodDto(
    DateTimeOffset PeriodStart,
    decimal Revenue,
    int OrderCount
);
```

Handler — 2 SELECT trong 1 lượt round-trip bằng QueryMultipleAsync, giống pattern multi-mapping đã dùng ở bài 1.7:

```csharp
namespace TeduMarket.Application.Orders.Queries.GetInstructorRevenue;
 
public sealed class GetInstructorRevenueQueryHandler(IDbConnectionFactory connectionFactory)
    : IRequestHandler<GetInstructorRevenueQuery, InstructorRevenueDto>
{
    private sealed record RevenueSummaryRow(decimal TotalRevenue, int TotalOrders);
 
    public async Task<InstructorRevenueDto> Handle(
        GetInstructorRevenueQuery request, CancellationToken cancellationToken)
    {
        using var connection = connectionFactory.CreateConnection();
 
        var truncUnit = request.GroupBy == RevenueGroupBy.Day ? "day" : "month";
 
        const string sql = """
            SELECT
                COALESCE(SUM(oi.unit_price), 0) AS TotalRevenue,
                COUNT(DISTINCT o.id)             AS TotalOrders
            FROM order_items oi
            JOIN orders  o ON o.id = oi.order_id
            JOIN courses c ON c.id = oi.course_id
            WHERE c.instructor_id = @InstructorId
              AND o.status = 'Paid'
              AND o.paid_at BETWEEN @FromDate AND @ToDate;
 
            SELECT
                DATE_TRUNC(@TruncUnit, o.paid_at) AS PeriodStart,
                SUM(oi.unit_price)                AS Revenue,
                COUNT(DISTINCT o.id)               AS OrderCount
            FROM order_items oi
            JOIN orders  o ON o.id = oi.order_id
            JOIN courses c ON c.id = oi.course_id
            WHERE c.instructor_id = @InstructorId
              AND o.status = 'Paid'
              AND o.paid_at BETWEEN @FromDate AND @ToDate
            GROUP BY DATE_TRUNC(@TruncUnit, o.paid_at)
            ORDER BY PeriodStart;
            """;
 
        using var multi = await connection.QueryMultipleAsync(sql, new
        {
            request.InstructorId,
            request.FromDate,
            request.ToDate,
            TruncUnit = truncUnit,
        });
 
        var summary = await multi.ReadSingleAsync<RevenueSummaryRow>();
        var breakdown = (await multi.ReadAsync<RevenueByPeriodDto>()).ToList();
 
        return new InstructorRevenueDto(
            request.InstructorId, summary.TotalRevenue, summary.TotalOrders, breakdown);
    }
}
```

> **📘 Ghi chú giảng viên:** *Trả lời câu hỏi đặt ra ở Phần 1: vì sao SUM(oi.unit_price) chứ không SUM(o.total_amount). Một Order có thể có 2 OrderItem của 2 Instructor khác nhau — học viên mua 2 khóa của 2 giảng viên trong cùng 1 lần thanh toán. Nếu SUM theo Order, Instructor A sẽ bị cộng nhầm doanh thu của Instructor B. Bắt buộc JOIN xuống order_items rồi lọc theo courses.instructor_id.*
>
> **📘 Ghi chú giảng viên:** *Cũng cần giải thích COUNT(DISTINCT o.id): vì 1 Order có thể có nhiều OrderItem của cùng 1 Instructor (mua 2 khóa của cùng giảng viên), JOIN sẽ nhân dòng lên — COUNT(o.id) thường sẽ đếm trùng Order. DATE_TRUNC là hàm PostgreSQL (không phải cú pháp SQL Server), gom các payment cùng kỳ (ngày hoặc tháng) vào 1 nhóm.*

# Bài tập thực hành

> **✏️ Đề bài:** Mở rộng GetInstructorRevenueQuery: thêm breakdown doanh thu theo từng Course (không chỉ theo ngày/tháng) — trả về Top 5 khóa học mang lại doanh thu cao nhất trong khoảng thời gian filter.

Input: InstructorId, FromDate, ToDate — giống hệt query hiện tại, không thêm tham số mới.

Expected output: thêm property TopCourses: IReadOnlyList\<CourseRevenueDto> vào InstructorRevenueDto. Mỗi phần tử gồm CourseId, CourseTitle, Revenue, OrderCount — sắp xếp giảm dần theo Revenue, tối đa 5 dòng.

> **✏️ Hint 1:** Thêm 1 SELECT nữa vào QueryMultiple (handler giờ có 3 SELECT thay vì 2) — GROUP BY courses.id, courses.title thay vì DATE_TRUNC.
>
> **✏️ Hint 2:** Dùng ORDER BY SUM(oi.unit_price) DESC LIMIT 5 ngay trong SQL — không lấy hết dữ liệu về rồi Take(5) trong C#.

### Gợi ý lời giải

```sql
SELECT
    c.id    AS CourseId,
    c.title AS CourseTitle,
    SUM(oi.unit_price)   AS Revenue,
    COUNT(DISTINCT o.id) AS OrderCount
FROM order_items oi
JOIN orders  o ON o.id = oi.order_id
JOIN courses c ON c.id = oi.course_id
WHERE c.instructor_id = @InstructorId
  AND o.status = 'Paid'
  AND o.paid_at BETWEEN @FromDate AND @ToDate
GROUP BY c.id, c.title
ORDER BY Revenue DESC
LIMIT 5;
```

Đặt LIMIT 5 ngay trong SQL thay vì lấy hết Course rồi Take(5) trong C# — bớt dữ liệu chuyển qua network, đúng tinh thần Query side tối ưu cho tốc độ đọc đã nói xuyên suốt từ bài 0.8.

# Tổng kết

> **✅ Tóm tắt**
>
> • Order History và Doanh thu Instructor là Read Model riêng, đọc thẳng bằng Dapper — không tái dùng Order/OrderItem Entity của Write side.
>
> • Doanh thu phải tính trên OrderItem (SUM(unit_price)), không tính trên Order.TotalAmount, vì 1 Order có thể chứa khóa học của nhiều Instructor.
>
> • COUNT(DISTINCT o.id) để tránh đếm trùng Order khi JOIN order_items làm nhân dòng lên.
>
> • WHERE clause động phải build bằng DynamicParameters — filters chỉ chứa tên cột cố định, không bao giờ chứa giá trị người dùng nhập.
>
> • Hai endpoint mới /api/v1/orders và /api/v1/instructors/{id}/revenue tạm thời chưa có Authorization — sẽ khóa lại đúng chuẩn ở bài 3.8.

### So sánh Write Model vs Read Model (Order)

| **Tiêu chí** | **Write Model (Order Aggregate)** | **Read Model (bài này)** |
|---|---|---|
| Công nghệ | EF Core + Aggregate | Dapper raw SQL |
| Mục tiêu | Bảo vệ invariant, transaction | Tốc độ đọc, tổng hợp |
| Bài đã học | 2.1, 2.2, 2.6, 2.9 | 0.8, 1.6, 1.7, bài này |
| Ví dụ | CheckoutCommandHandler | GetOrderHistoryQuery |

**Bước tiếp theo:** Bài 2.9 — Idempotency & Concurrency trong Checkout, xử lý race condition khi user bấm thanh toán 2 lần liên tiếp.
