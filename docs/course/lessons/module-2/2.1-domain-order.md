## 1. Ôn nhanh: Entity, Value Object, Aggregate Root

Thời lượng: ~5 phút · Loại: Lý thuyết (ôn tập, không dạy lại từ đầu)

Bạn đã xây Category Aggregate ở bài 0.3 và Course Aggregate ở bài 1.1. Ba khái niệm dưới đây sẽ dùng lại nguyên vẹn trong bài này:

- Entity — có Id định danh. Hai Entity bằng nhau nếu cùng Id, dù các field khác có khác nhau.
- Value Object — không có Id riêng, bất biến (immutable), 2 Value Object bằng nhau nếu mọi field giống nhau.
- Aggregate Root — Entity đặc biệt, là cửa duy nhất để thay đổi cụm Entity con bên trong, đảm bảo invariant nghiệp vụ luôn đúng sau mỗi thao tác.

> **📘 Ghi chú giảng viên:** *Bài này giả định base class Entity\<TId> và AggregateRoot\<TId> đã dựng ở bài 0.3 (constructor bảo vệ, Equals theo Id). Nếu lớp base ở bài 0.3 của bạn đặt tên hoặc namespace khác, đổi lại cho khớp — logic nghiệp vụ trong bài này chỉ phụ thuộc hành vi (Equals theo Id, Aggregate Root là entry point duy nhất), không phụ thuộc tên class base cụ thể.*

## 2. Vì sao Cart và Order không dùng chung 1 Aggregate?

Thời lượng: ~23 phút · Loại: Lý thuyết — đây là trọng tâm của bài.

### 2.1. Cart thuộc về "hiện tại", Order thuộc về "quá khứ"

- Cart: mutable, sống trong session mua hàng của 1 User. User add/remove khóa học liên tục cho đến khi checkout. Cart không phải bản ghi kế toán — Cart hết hạn hoặc bị xóa không ảnh hưởng gì đến dữ liệu tài chính.
- Order: được tạo ra đúng 1 lần tại thời điểm checkout, và từ đó là bản ghi lịch sử — immutable. Order không được sửa giá hay danh sách khóa học sau khi tạo, chỉ được phép chuyển trạng thái (Pending → Paid/Cancelled).

### 2.2. Lifecycle khác nhau quyết định ranh giới Aggregate

Nguyên tắc DDD: ranh giới Aggregate được vẽ theo consistency boundary — nhóm dữ liệu nào bắt buộc phải nhất quán với nhau trong cùng 1 transaction thì gom vào 1 Aggregate. Ranh giới không được vẽ theo "cùng nói về đơn hàng nên gộp chung 1 class".

- Cart cần nhất quán trong phạm vi: User sở hữu + danh sách item hiện tại.
- Order cần nhất quán trong phạm vi: snapshot giá + danh sách item + trạng thái thanh toán tại đúng thời điểm tạo.

Hai phạm vi này không giao nhau về thời gian: Cart "kết thúc vai trò" đúng lúc Order "sinh ra". Nếu gộp chung 1 class, class đó phải cõng 2 lifecycle mâu thuẫn — vừa mutable (đang mua) vừa immutable (đã mua) — buộc phải chèn if/switch theo trạng thái để biết "giờ đang là Cart hay đã là Order". Đây là code smell kinh điển của việc vẽ sai ranh giới Aggregate.

### 2.3. Hệ quả kỹ thuật nếu gộp chung — rủi ro thực tế

Rủi ro nghiêm trọng nhất: nếu Order chỉ giữ CourseId (không copy Title + Price tại thời điểm mua), thì khi Instructor đổi giá Course sau này, mọi Order lịch sử "đổi giá theo" ngay lập tức. Báo cáo doanh thu (bài 2.8) sẽ sai, không thể đối chiếu với số tiền VNPay đã thực nhận (bài 2.4, 2.5).

Đây là lý do OrderItem PHẢI copy CourseTitle và Price tại thời điểm tạo Order — không giữ tham chiếu sống đến Course Aggregate.

> **📘 Ghi chú giảng viên:** *Câu hỏi hay gặp nhất ở phần này: "Sao không dùng CourseId join sang bảng Course lấy giá cho gọn?" Trả lời bằng ví dụ cụ thể: nếu bạn giảm giá khóa học từ 500.000đ xuống 200.000đ vào tháng sau, học viên đã mua tháng trước với giá 500.000đ có tự nhiên bị đổi thành 200.000đ trên báo cáo doanh thu không? Câu trả lời luôn là không — đó chính là lý do OrderItem là snapshot, không phải reference sống.*

## 3. Demo: Money — Value Object dùng chung cho Ordering

Thời lượng: ~4 phút · Loại: Demo

Trước khi code Cart và Order, cần 1 Value Object đại diện cho số tiền — dùng chung cho SubTotal, DiscountAmount, Total, giá từng item. Đặt ở TeduMarket.Domain.Common vì Course.Pricing (bài 1.4) cũng có thể dùng lại VO này ở tầng thấp nhất.

```csharp
// TeduMarket.Domain/Common/Money.cs
namespace TeduMarket.Domain.Common;
 
public sealed record Money(decimal Amount, string Currency = "VND")
{
    public static Money Zero => new(0m);
 
    public static Money operator +(Money left, Money right)
    {
        EnsureSameCurrency(left, right);
        return left with { Amount = left.Amount + right.Amount };
    }
 
    public static Money operator -(Money left, Money right)
    {
        EnsureSameCurrency(left, right);
        var result = left.Amount - right.Amount;
        return left with { Amount = result < 0 ? 0m : result };
    }
 
    private static void EnsureSameCurrency(Money left, Money right)
    {
        if (left.Currency != right.Currency)
            throw new InvalidOperationException(
                "Không thể cộng/trừ 2 Money khác đơn vị tiền tệ.");
    }
}
```

> **📘 Ghi chú giảng viên:** *Money dùng decimal, không dùng double — đúng nguyên tắc "tiền phải dùng decimal" đã áp dụng xuyên suốt khóa. record cho value equality miễn phí (2 Money bằng nhau nếu Amount và Currency giống nhau, có từ C# 9, ổn định qua mọi bản C# sau này kể cả C# 14 khóa đang dùng). Phép trừ chặn âm ngay tại Value Object — invariant "tiền không được âm" nằm càng sát dữ liệu càng tốt.*

## 4. Demo: Cart Aggregate & CartItem

Thời lượng: ~8 phút · Loại: Demo

Cart là Aggregate Root, CartItem là child entity — invariant quan trọng nhất: không được có 2 CartItem trùng CourseId trong cùng 1 Cart.

```csharp
// TeduMarket.Domain/Ordering/CartItem.cs
namespace TeduMarket.Domain.Ordering;
 
public sealed class CartItem : Entity<Guid>
{
    public Guid CourseId { get; private init; }
    public string CourseTitle { get; private init; } = default!;
    public Money Price { get; private init; } = default!;
 
    private CartItem() { } // dành cho EF Core
 
    internal static CartItem Create(Guid courseId, string courseTitle, Money price)
        => new()
        {
            Id = Guid.NewGuid(),
            CourseId = courseId,
            CourseTitle = courseTitle,
            Price = price
        };
}
// TeduMarket.Domain/Ordering/Cart.cs
namespace TeduMarket.Domain.Ordering;
 
public sealed class Cart : AggregateRoot<Guid>
{
    private readonly List<CartItem> _items = [];
 
    public Guid UserId { get; private init; }
    public IReadOnlyCollection<CartItem> Items => _items.AsReadOnly();
 
    private Cart() { } // dành cho EF Core
 
    public static Cart Create(Guid userId)
        => new() { Id = Guid.NewGuid(), UserId = userId };
 
    public bool ContainsCourse(Guid courseId)
        => _items.Any(i => i.CourseId == courseId);
 
    public void AddItem(Guid courseId, string courseTitle, Money price)
    {
        if (ContainsCourse(courseId))
            throw new CartItemAlreadyExistsException(Id, courseId);
 
        _items.Add(CartItem.Create(courseId, courseTitle, price));
    }
 
    public void RemoveItem(Guid courseId)
    {
        var item = _items.FirstOrDefault(i => i.CourseId == courseId)
            ?? throw new CartItemNotFoundException(Id, courseId);
 
        _items.Remove(item);
    }
 
    public void Clear() => _items.Clear();
 
    public Money GetSubTotal()
        => _items.Aggregate(Money.Zero, (sum, item) => sum + item.Price);
}
```

> **📘 Ghi chú giảng viên:** *AddItem và RemoveItem là 2 phương thức DUY NHẤT được phép thay đổi danh sách Items — giống hệt nguyên tắc Course.AddLesson ở bài 1.3 (không update thẳng bảng con ngoài luồng Aggregate). Học viên hay quên invariant này khi viết Command ở bài 2.2 và tự ý gọi \_items.Add() từ bên ngoài — nhắc lại tên biến \_items là private để chặn hẳn khả năng đó ngay từ compile-time.*

## 5. Demo: Order Aggregate & OrderItem

Thời lượng: ~8 phút · Loại: Demo

Order là bản snapshot bất biến. Sau khi tạo, chỉ Status được phép đổi — mọi field còn lại dùng private init.

```csharp
// TeduMarket.Domain/Ordering/OrderStatus.cs
namespace TeduMarket.Domain.Ordering;
 
public enum OrderStatus
{
    Pending = 0,
    Paid = 1,
    Cancelled = 2
}
// TeduMarket.Domain/Ordering/OrderItem.cs
namespace TeduMarket.Domain.Ordering;
 
public sealed class OrderItem : Entity<Guid>
{
    public Guid CourseId { get; private init; }
    public string CourseTitle { get; private init; } = default!; // snapshot tên
    public Money Price { get; private init; } = default!;        // snapshot giá
 
    private OrderItem() { }
 
    internal static OrderItem Create(Guid courseId, string courseTitle, Money price)
        => new()
        {
            Id = Guid.NewGuid(),
            CourseId = courseId,
            CourseTitle = courseTitle,
            Price = price
        };
}
// TeduMarket.Domain/Ordering/Order.cs
namespace TeduMarket.Domain.Ordering;
 
public sealed class Order : AggregateRoot<Guid>
{
    private readonly List<OrderItem> _items = [];
 
    public Guid UserId { get; private init; }
    public OrderStatus Status { get; private set; }
    public Money SubTotal { get; private init; } = default!;
    public Money DiscountAmount { get; private init; } = default!;
    public Money Total { get; private init; } = default!;
    public string? CouponCode { get; private init; } // copy mã, không giữ ref Coupon
    public DateTime CreatedAtUtc { get; private init; }
    public IReadOnlyCollection<OrderItem> Items => _items.AsReadOnly();
 
    private Order() { }
 
    // Factory: chỉ dựng đối tượng + enforce invariant, KHÔNG gọi Repository/DbContext
    // ở đây. Bài 2.2 sẽ viết CheckoutCommandHandler gọi phương thức này, lưu Order
    // và phát domain event, cùng 1 transaction.
    public static Order CreateFromCart(Cart cart, Coupon? coupon)
    {
        if (cart.Items.Count == 0)
            throw new CartEmptyException(cart.Id);
 
        var subTotal = cart.GetSubTotal();
        var discount = coupon?.CalculateDiscount(subTotal) ?? Money.Zero;
 
        var order = new Order
        {
            Id = Guid.NewGuid(),
            UserId = cart.UserId,
            Status = OrderStatus.Pending,
            SubTotal = subTotal,
            DiscountAmount = discount,
            Total = subTotal - discount, // Money.-() đã chặn âm ở bài 3
            CouponCode = coupon?.Code,
            CreatedAtUtc = DateTime.UtcNow
        };
 
        foreach (var item in cart.Items)
        {
            order._items.Add(
                OrderItem.Create(item.CourseId, item.CourseTitle, item.Price));
        }
 
        return order;
    }
 
    public void MarkAsPaid()
    {
        if (Status != OrderStatus.Pending)
            throw new OrderInvalidStatusTransitionException(Id, Status, OrderStatus.Paid);
 
        Status = OrderStatus.Paid;
    }
 
    public void Cancel()
    {
        if (Status != OrderStatus.Pending)
            throw new OrderInvalidStatusTransitionException(Id, Status, OrderStatus.Cancelled);
 
        Status = OrderStatus.Cancelled;
    }
}
```

> **📘 Ghi chú giảng viên:** *Chưa raise domain event (CourseOrderedEvent) ở CreateFromCart — cố tình để dành cho bài 2.2, nơi CheckoutCommandHandler gọi phương thức này bên trong 1 transaction rồi mới phát event. Idempotency thật của MarkAsPaid khi webhook VNPay gọi lặp lại nhiều lần sẽ xử lý ở tầng Application/Infrastructure tại bài 2.5 (IPN) và 2.9 (RowVersion) — ở đây Domain chỉ định nghĩa transition nào là hợp lệ (Pending → Paid, Pending → Cancelled), chặn transition sai ngay tại nguồn.*

## 6. Demo: Coupon — phiên bản cơ bản

Thời lượng: ~2 phút · Loại: Demo

Coupon là Aggregate Root riêng, có lifecycle độc lập (Admin tạo/tắt), Order chỉ copy lại Code — không giữ tham chiếu sống, cùng nguyên tắc snapshot đã nói ở mục 2.3.

```csharp
// TeduMarket.Domain/Ordering/Coupon.cs
namespace TeduMarket.Domain.Ordering;
 
public sealed class Coupon : AggregateRoot<Guid>
{
    public string Code { get; private init; } = default!;
    public decimal DiscountPercentage { get; private init; }
    public DateTime ValidFromUtc { get; private init; }
    public DateTime ValidToUtc { get; private init; }
    public bool IsActive { get; private set; }
 
    private Coupon() { }
 
    public static Coupon Create(
        string code, decimal discountPercentage, DateTime validFromUtc, DateTime validToUtc)
    {
        if (string.IsNullOrWhiteSpace(code))
            throw new CouponInvalidException("Mã coupon không được để trống.");
        if (discountPercentage is <= 0 or > 100)
            throw new CouponInvalidException("Phần trăm giảm giá phải trong (0, 100].");
        if (validToUtc <= validFromUtc)
            throw new CouponInvalidException("Ngày hết hạn phải sau ngày bắt đầu.");
 
        return new Coupon
        {
            Id = Guid.NewGuid(),
            Code = code.Trim().ToUpperInvariant(),
            DiscountPercentage = discountPercentage,
            ValidFromUtc = validFromUtc,
            ValidToUtc = validToUtc,
            IsActive = true
        };
    }
 
    public bool IsValidAt(DateTime utcNow)
        => IsActive && utcNow >= ValidFromUtc && utcNow <= ValidToUtc;
 
    public Money CalculateDiscount(Money subTotal)
        => subTotal with { Amount = subTotal.Amount * DiscountPercentage / 100m };
 
    public void Deactivate() => IsActive = false;
}
```

> **📘 Ghi chú giảng viên:** *Đây CHỈ là bản đủ dùng để Order.CreateFromCart chạy được — % giảm giá đơn giản, không giới hạn theo Course cụ thể, không giới hạn số lần dùng. Bài 2.3 sẽ thay CalculateDiscount bằng Value Object Discount + Specification pattern để hỗ trợ nhiều loại rule cùng lúc, đúng tinh thần "đã học ở bài 2.1, giờ làm đúng chuẩn hơn" — không phải dạy lại Coupon từ đầu.*

## Bài tập / Thực hành

Làm trực tiếp trên project TeduMarket.Domain vừa code ở trên. Không cần chạy API, chỉ cần biên dịch (dotnet build) là đủ kiểm tra invariant ở bước này.

> **✏️ Yêu cầu 1:** Viết 1 method thử nghiệm tạo Order từ Cart có 1 item giá 100.000đ và Coupon giảm 100%. Kiểm tra Total trả về đúng 0đ, không bị âm hoặc throw exception ngoài ý muốn.
>
> **✏️ Yêu cầu 2:** Thêm method Order.Cancel() gọi 2 lần liên tiếp trên cùng 1 Order (giả lập double-click hủy đơn) — xác nhận lần gọi thứ 2 throw đúng OrderInvalidStatusTransitionException thay vì âm thầm chạy qua.
>
> **✏️ Yêu cầu 3 (nâng cao):** Cart.AddItem đang throw exception khi trùng CourseId. Đổi hành vi này thành no-op (bỏ qua, không throw) và tự đánh giá: cách nào đúng hơn cho UX giỏ hàng thực tế? Ghi lại lý do bằng 2-3 câu.
>
> **✏️ Hint:** Invariant luôn nằm bên trong method của Aggregate Root (Cart, Order, Coupon) — không bao giờ xử lý validate ở ngoài Application layer. Nếu thấy mình đang if-check trạng thái Order ở chỗ khác ngoài class Order, đó là dấu hiệu đặt sai chỗ.
>
> **✏️ Solution — Yêu cầu 1:** Money.CalculateDiscount trả về 100.000đ, Total = SubTotal - Discount = 0đ nhờ Money.-() đã clamp về 0m khi kết quả âm (đã code ở mục 3) — không cần thêm check trong Order.

## Tổng kết

- Cart và Order là 2 Aggregate riêng biệt vì lifecycle khác nhau (mutable/hiện tại vs immutable/quá khứ) — ranh giới Aggregate vẽ theo consistency boundary, không theo chủ đề nghiệp vụ.
- OrderItem copy CourseTitle + Price tại thời điểm mua — không tham chiếu sống đến Course, tránh sai lệch báo cáo doanh thu khi giá Course đổi sau này.
- Money là Value Object dùng chung, decimal + clamp âm ngay tại phép trừ.
- Coupon là Aggregate Root độc lập; Order chỉ copy Code, không giữ reference — cùng nguyên tắc snapshot với OrderItem.
- Order.CreateFromCart chỉ dựng đối tượng và enforce invariant — chưa gọi Repository, chưa raise domain event, để dành cho CheckoutCommandHandler ở bài 2.2.

| **Tiêu chí** | **Cart** | **Order** |
|---|---|---|
| **Mutable?** | Có — add/remove liên tục | Không — snapshot sau khi tạo |
| **Vai trò** | Trạng thái "đang mua", thuộc hiện tại | Bản ghi lịch sử, thuộc quá khứ |
| **Giá item** | Tham chiếu giá Course hiện hành | Snapshot giá tại thời điểm tạo |
| **Invariant chính** | Không trùng CourseId trong giỏ | Chỉ transition Pending → Paid/Cancelled |
| **Mất dữ liệu có sao không?** | Không — chỉ mất tiện lợi | Có — sai lệch kế toán, báo cáo doanh thu |

> **✅ Tóm tắt:** Bài tiếp theo (2.2 — Command AddToCart & Checkout) sẽ dùng lại đúng Cart và Order vừa xây: viết AddToCartCommand gọi Cart.AddItem, CheckoutCommand gọi Order.CreateFromCart rồi phát domain event CourseOrderedEvent — không viết lại Domain, chỉ orchestrate những gì đã có ở bài này.

## Phụ lục

### A. Cheatsheet naming convention áp dụng trong bài

| **Namespace** | TeduMarket.Domain.Ordering (Cart, Order, OrderItem, Coupon, OrderStatus)  ·  TeduMarket.Domain.Common (Money) |
|---|---|
| **Lỗi nghiệp vụ** | {Thực thể}{LoạiLỗi}Exception — CartEmptyException, CartItemNotFoundException, CartItemAlreadyExistsException, CouponInvalidException, OrderInvalidStatusTransitionException |
| **Factory method** | Create(...) cho khởi tạo mới, CreateFromXxx(...) khi khởi tạo từ Aggregate khác (Order.CreateFromCart) |

### B. Glossary

- Aggregate — cụm Entity + Value Object được gom lại, luôn nhất quán với nhau trong cùng 1 transaction.
- Aggregate Root — Entity là cửa duy nhất để thay đổi cả Aggregate, chịu trách nhiệm bảo vệ invariant.
- Invariant — quy tắc nghiệp vụ luôn phải đúng, ví dụ "Cart không được trùng CourseId".
- Consistency boundary — ranh giới dữ liệu phải nhất quán trong cùng 1 transaction; dùng để quyết định Aggregate boundary.
- Snapshot — bản sao dữ liệu đông cứng tại 1 thời điểm, không đổi theo dữ liệu gốc về sau (OrderItem là snapshot của Course).
- Bounded Context — ranh giới nghiệp vụ lớn hơn Aggregate, ví dụ Ordering là 1 Bounded Context riêng so với Catalog.
