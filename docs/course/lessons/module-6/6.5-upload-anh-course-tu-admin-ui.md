## 1. Ôn lại luồng 2 chặng đã xây ở bài 1.8

*Lý thuyết · 5 phút*

Ở bài 1.8, bạn đã xây xong phần backend cho việc upload ảnh Course: UpdateCourseThumbnailCommand nhận CourseId, tên file và Content-Type, sinh ra một presigned PUT URL trỏ thẳng vào MinIO, đồng thời lưu luôn địa chỉ ảnh (ThumbnailUrl) vào Course vì object key được suy ra deterministic theo CourseId (ví dụ courses/{courseId}/thumbnail.jpg). Bạn đã test luồng này bằng Postman: gọi API lấy presigned URL, rồi PUT file thẳng lên MinIO bằng chính Postman.

Bài này không dạy lại backend — bạn chỉ nối luồng đó vào giao diện React Admin thật, nơi Instructor bấm chọn ảnh và thấy kết quả ngay trên UI. Sơ đồ luồng đầy đủ:

```
1. Admin chọn file ảnh trong CourseForm (đã có từ bài 6.3)
```

2. FE gọi mutation (api-client, Module 5.2) → PUT /api/v1/courses/{id}/thumbnail

```
   Backend (bài 1.8) trả về { uploadUrl, thumbnailUrl }
   → đồng thời đã lưu thumbnailUrl vào Course trong DB
3. FE PUT trực tiếp file (bytes) lên "uploadUrl" — đi thẳng đến MinIO,
   KHÔNG đi qua backend TeduMarket.Api
```

4. FE báo thành công → invalidate cache Course detail → UI hiện ảnh mới

> **📘 Ghi chú giảng viên:** *Tôi hay dừng ở bước 3 và hỏi học viên: "Nếu ảnh Course nặng 5MB, cho 200 Instructor upload cùng lúc, backend API của mình phải xử lý bao nhiêu MB dữ liệu binary chạy qua nếu upload theo kiểu proxy truyền thống (client → backend → storage)?" Câu trả lời là toàn bộ 5MB × 200 lần, tốn băng thông + thread pool của Api layer cho việc chỉ đơn thuần là chuyển tiếp byte, không có logic nghiệp vụ nào cả. Presigned URL giải quyết đúng vấn đề đó: backend chỉ ký một chữ ký có thời hạn (vài phút), còn việc truyền file nặng để trình duyệt làm việc thẳng với MinIO.*

## 2. Hook xin presigned URL từ packages/api-client

*Demo · 5 phút*

Vì endpoint POST /api/v1/courses/{id}/thumbnail đã được annotate WithName ở Module 4.1 và có mặt trong openapi.json, nó đã được generate lại thành hook React Query khi bạn chạy pnpm generate:client (bài 5.3). Từ bản cập nhật gần đây của @hey-api/openapi-ts, plugin @tanstack/react-query sinh sẵn hook dạng use{OperationName}Mutation() — không cần tự viết useMutation bọc quanh service function như trước nữa.

```typescript
// apps/admin/src/features/courses/hooks/useCourseThumbnail.ts
import { useUpdateCourseThumbnailMutation } from '@tedu-market/api-client/react-query';
 
// courseId: id của Course đang sửa (đã có sẵn ở CourseForm, bài 6.3)
export function useRequestThumbnailUploadUrl() {
  return useUpdateCourseThumbnailMutation({
    onError: (error) => {
      console.error('Không xin được presigned URL:', error);
    }
  });
}
```

Access token OIDC (bài 6.2) không cần gắn tay ở đây — client instance dùng chung trong packages/api-client (bài 5.1–5.2) đã có interceptor tự đính kèm Authorization header cho mọi request, kể cả mutation này. Backend kiểm tra Instructor có đúng chủ sở hữu Course không bằng CourseOwnerRequirement đã học ở bài 3.8 — nếu Instructor cố sửa ảnh của Course người khác, mutation này trả về lỗi 403 theo đúng format ProblemDetails (bài 4.5), sẽ được xử lý UI ở bài 6.6.

## 3. Component chọn ảnh và xem trước (preview)

*Demo + Lab · 5 phút*

Trước khi gọi API, cho Instructor xem trước ảnh vừa chọn bằng URL.createObjectURL — không cần upload gì lên server chỉ để hiển thị preview.

```tsx
// apps/admin/src/features/courses/components/ThumbnailPicker.tsx
import { useEffect, useState } from 'react';
 
type Props = {
  currentUrl?: string;
  onFileSelected: (file: File) => void;
};
 
export function ThumbnailPicker({ currentUrl, onFileSelected }: Props) {
  const [previewUrl, setPreviewUrl] = useState<string | undefined>(currentUrl);
 
  function handleChange(e: React.ChangeEvent<HTMLInputElement>) {
    const file = e.target.files?.[0];
    if (!file) return;
 
    const objectUrl = URL.createObjectURL(file);
    setPreviewUrl(objectUrl);
    onFileSelected(file);
  }
 
  // Giải phóng object URL khi component unmount hoặc preview đổi,
  // tránh rò rỉ bộ nhớ trình duyệt
  useEffect(() => {
    return () => {
      if (previewUrl?.startsWith('blob:')) URL.revokeObjectURL(previewUrl);
    };
  }, [previewUrl]);
 
  return (
    <div className="thumbnail-picker">
      {previewUrl && <img src={previewUrl} alt="Course thumbnail" width={240} />}
      <input type="file" accept="image/png,image/jpeg,image/webp" onChange={handleChange} />
    </div>
  );
}
```

## 4. Upload thẳng lên MinIO bằng XMLHttpRequest + progress bar

*Demo + Lab · 10 phút — phần trọng tâm của bài*

Bước PUT file lên uploadUrl không đi qua api-client (api-client chỉ biết gọi backend TeduMarket.Api, không biết gì về MinIO). Bạn tự viết một PUT request thuần bằng tay. Điểm hay bị chọn nhầm ở đây là dùng fetch() — Fetch API không phát sự kiện theo dõi tiến trình khi gửi (upload progress), chỉ hỗ trợ theo dõi khi tải về (download). Muốn có thanh tiến trình thật cho việc upload, bắt buộc dùng XMLHttpRequest với sự kiện upload.onprogress.

```typescript
// apps/admin/src/features/courses/lib/uploadToPresignedUrl.ts
export function uploadToPresignedUrl(
  uploadUrl: string,
  file: File,
  onProgress?: (percent: number) => void
): Promise<void> {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('PUT', uploadUrl);
 
    // Content-Type PHẢI khớp đúng với Content-Type mà backend đã ký
    // khi tạo presigned URL (bài 1.8) — lệch header này MinIO trả về
    // 403 SignatureDoesNotMatch, không phải lỗi CORS như hay bị hiểu nhầm.
    xhr.setRequestHeader('Content-Type', file.type);
 
    xhr.upload.onprogress = (event) => {
      if (event.lengthComputable && onProgress) {
        onProgress(Math.round((event.loaded / event.total) * 100));
      }
    };
 
    xhr.onload = () => {
      if (xhr.status >= 200 && xhr.status < 300) {
        resolve();
      } else {
        reject(new Error(`Upload MinIO thất bại: HTTP ${xhr.status}`));
      }
    };
 
    xhr.onerror = () => reject(new Error('Lỗi mạng khi upload lên MinIO'));
 
    xhr.send(file);
  });
}
```

> **📘 Ghi chú giảng viên:** *Lỗi phổ biến nhất học viên gặp ở bước này là SignatureDoesNotMatch (403) từ MinIO. 9/10 lần nguyên nhân là Content-Type gửi lên khác với Content-Type đã truyền khi backend ký URL ở bài 1.8 — ví dụ backend ký cho "image/jpeg" nhưng FE gửi "image/jpg" hoặc để trống. Tôi luôn demo lỗi này trực tiếp (cố tình đổi Content-Type) để học viên nhớ, thay vì chỉ nói suông "phải khớp header".*

## 5. Ráp toàn bộ luồng vào CourseForm (bài 6.3)

*Lab · 5 phút*

Gộp 2 bước (xin presigned URL, upload lên MinIO) và bước cập nhật lại cache React Query vào một custom hook duy nhất, để component CourseForm chỉ cần gọi 1 hàm.

```typescript
// apps/admin/src/features/courses/hooks/useCourseThumbnail.ts (tiếp)
import { useState } from 'react';
import { useQueryClient } from '@tanstack/react-query';
import { uploadToPresignedUrl } from '../lib/uploadToPresignedUrl';
 
export function useCourseThumbnailUpload(courseId: string) {
  const queryClient = useQueryClient();
  const requestUrl = useRequestThumbnailUploadUrl();
  const [progress, setProgress] = useState(0);
  const [isUploading, setIsUploading] = useState(false);
 
  async function upload(file: File) {
    setIsUploading(true);
    setProgress(0);
    try {
      const { uploadUrl } = await requestUrl.mutateAsync({
        path: { id: courseId },
        body: { fileName: file.name, contentType: file.type }
      });
 
      await uploadToPresignedUrl(uploadUrl, file, setProgress);
 
      // ThumbnailUrl đã được backend lưu ngay khi cấp presigned URL (bài 1.8),
      // nên chỉ cần invalidate để CourseDetail fetch lại đúng ảnh mới.
      await queryClient.invalidateQueries({ queryKey: ['courses', courseId] });
    } finally {
      setIsUploading(false);
    }
  }
 
  return { upload, progress, isUploading };
}
// Trong CourseForm.tsx (bài 6.3), thêm:
const { upload, progress, isUploading } = useCourseThumbnailUpload(course.id);
 
<ThumbnailPicker currentUrl={course.thumbnailUrl} onFileSelected={upload} />
{isUploading && <progress value={progress} max={100}>{progress}%</progress>}
```

> **📘 Ghi chú giảng viên:** *CourseOwnerRequirement (bài 3.8) chặn ở tầng API, nhưng nếu request xin presigned URL bị 403, mutateAsync ở đây sẽ throw — hiện tại catch bằng try/finally chỉ đảm bảo tắt loading, chưa hiển thị thông báo lỗi cho Instructor. Đây là chỗ tôi hay để học viên "cảm thấy thiếu" một chút, làm bàn đạp dẫn vào bài 6.6 — chuẩn hóa toast lỗi từ ProblemDetails cho toàn bộ Admin app, không riêng gì upload ảnh.*

## Bài tập thực hành

> **✏️ Thực hành:** Thêm validate phía client TRƯỚC khi gọi mutation xin presigned URL: chỉ cho phép file ≤ 2MB và đúng 1 trong 3 định dạng image/png, image/jpeg, image/webp. Nếu sai, hiển thị thông báo lỗi ngay tại ThumbnailPicker và KHÔNG gọi API — tránh tốn một round-trip network cho lỗi có thể phát hiện ngay trên trình duyệt.

*Input: file người dùng chọn qua thẻ \<input type="file">.*

*Expected output: file hợp lệ → luồng upload chạy như bình thường; file không hợp lệ → hiện dòng chữ lỗi rõ ràng (ví dụ "Ảnh vượt quá 2MB" hoặc "Chỉ nhận PNG/JPEG/WebP"), hàm onFileSelected không được gọi.*

*Hint: kiểm tra file.size (đơn vị byte, 2MB = 2 \* 1024 \* 1024) và file.type ngay trong handleChange của ThumbnailPicker, trước dòng gọi URL.createObjectURL.*

```tsx
// Solution — sửa trong ThumbnailPicker.tsx
const MAX_SIZE = 2 * 1024 * 1024; // 2MB
const ALLOWED_TYPES = ['image/png', 'image/jpeg', 'image/webp'];
 
// Thêm 1 state lỗi bên cạnh previewUrl đã có:
const [error, setError] = useState<string | undefined>();
 
function handleChange(e: React.ChangeEvent<HTMLInputElement>) {
  const file = e.target.files?.[0];
  if (!file) return;
 
  if (!ALLOWED_TYPES.includes(file.type)) {
    setError('Chỉ nhận PNG/JPEG/WebP');
    return;
  }
  if (file.size > MAX_SIZE) {
    setError('Ảnh vượt quá 2MB');
    return;
  }
 
  setError(undefined);
  const objectUrl = URL.createObjectURL(file);
  setPreviewUrl(objectUrl);
  onFileSelected(file);
}
 
// Hiển thị lỗi trong JSX, ngay dưới thẻ <input>:
{error && <p className="field-error">{error}</p>}
```
