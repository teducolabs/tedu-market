# Nội dung chính

## 1. Recap luồng OIDC phía SPA — vì sao PKCE là bắt buộc

*Thời lượng: 15 phút | Loại: Lý thuyết*

Ở bài 3.1 và 3.3, bạn đã dựng OpenIddict Server chạy chung trong TeduMarket.Api (đúng quyết định kiến trúc #2 ở outline) và đăng ký 1 OpenIddict Client riêng cho React Admin. Bài này không dựng lại Authorization Server — chỉ nối phần React vào Client đã có sẵn đó.

React Admin là "public client": toàn bộ code chạy trên trình duyệt của người dùng, không có nơi nào an toàn để giữ client secret. Vì vậy ở bài 3.3, Client này được đăng ký với ClientType = ClientTypes.Public và bắt buộc PKCE qua Requirements.Features.ProofKeyForCodeExchange — khai báo rõ ràng, không phụ thuộc hành vi mặc định ẩn của OpenIddict.

react-oidc-context (dựa trên thư viện lõi oidc-client-ts) tự sinh code_verifier/code_challenge và tự thực hiện toàn bộ vòng trao đổi PKCE — bạn không cần tự tay implement thuật toán PKCE.

### Luồng đăng nhập, từng bước

1. Học viên bấm nút "Đăng nhập" → gọi auth.signinRedirect().
1. Trình duyệt redirect sang authority (TeduMarket.Api) tới /connect/authorize, kèm client_id, code_challenge, code_challenge_method=S256.
1. OpenIddict hiển thị trang đăng nhập (ASP.NET Core Identity UI) → xác thực xong → redirect về redirect_uri của Admin app kèm code và state.
1. react-oidc-context tự động POST /connect/token kèm code và code_verifier để đổi lấy access_token, id_token, refresh_token (nếu scope có offline_access).
1. Token được lưu vào sessionStorage theo key oidc.user:\<authority>:\<client_id> — mặc định react-oidc-context dùng sessionStorage, không phải localStorage.

### Vì sao cần silent renew

Access token OpenIddict cấp có thời hạn ngắn — mặc định khoảng 1 giờ theo SetAccessTokenLifetime ở bài 3.2, trừ khi bạn đã tuỳ chỉnh con số này. Nếu không renew, Instructor đang thao tác dở trên Admin sẽ bị văng ra giữa chừng. Silent renew dùng 1 iframe ẩn gọi lại /connect/authorize với prompt=none, dựa vào cookie phiên đăng nhập của ASP.NET Core Identity vẫn còn hiệu lực để lấy token mới mà không cần người dùng nhập lại mật khẩu.

> **📘 Ghi chú giảng viên:** *Đây là chỗ học viên hay hỏi: "Client_id và scope em gõ trong React có cần y hệt bài 3.3 không?" — Có, tuyệt đối. OpenIddict so khớp chính xác client_id, redirect_uri, scope với những gì đã đăng ký; sai một ký tự sẽ trả lỗi invalid_client hoặc invalid_scope ngay ở bước redirect đầu tiên, trước khi kịp chạm vào code React. Tôi thường dừng ở đây, mở lại đúng đoạn seed OpenIddictApplicationDescriptor của bài 3.3 cùng học viên để đối chiếu từng field trước khi gõ config phía React.*

## 2. Cài đặt & cấu hình AuthProvider

*Thời lượng: 15 phút | Loại: Demo*

Cài thư viện vào đúng workspace apps/admin (Turborepo + pnpm, đúng cấu trúc monorepo ở outline mục 6):

```bash
# chạy từ thư mục gốc frontend/
pnpm add oidc-client-ts react-oidc-context --filter admin
```

Tạo file cấu hình apps/admin/src/auth/oidc-config.ts:

```typescript
import type { AuthProviderProps } from "react-oidc-context";
 
// Đọc từ .env.local — không hard-code giá trị thật vào source code
const authority = import.meta.env.VITE_OIDC_AUTHORITY;
// vd: https://localhost:7000 (port thật lấy theo launchSettings.json của TeduMarket.Api)
const clientId = import.meta.env.VITE_OIDC_CLIENT_ID;
// phải khớp CHÍNH XÁC ClientId đã đăng ký cho React Admin ở bài 3.3
 
export const oidcConfig: AuthProviderProps = {
  authority,
  client_id: clientId,
  redirect_uri: window.location.origin + "/",
  silent_redirect_uri: window.location.origin + "/",
  response_type: "code",
  scope: "openid profile roles offline_access tedumarket_api",
  automaticSilentRenew: true,
  loadUserInfo: true,
  onSigninCallback: () => {
    // Xoá code/state khỏi URL sau khi xử lý xong, tránh xử lý nhầm lại
    // callback cũ mỗi khi component re-render
    window.history.replaceState({}, document.title, window.location.pathname);
  },
};
```

> **📘 Ghi chú giảng viên:** *Giả định cần xác nhận trước khi lên lớp: tên client_id "tedumarket-admin-spa" và scope "tedumarket_api" trong ví dụ này là đặt theo quy ước đặt tên chung của khóa, tôi không có nguyên văn nội dung bài 3.3 đã dạy. Trước khi dạy bài này, đối chiếu đúng ClientId/Scope thật đã seed ở TeduMarket.Infrastructure của bài 3.3 và sửa lại ví dụ cho khớp — nếu lệch, học viên sẽ gặp lỗi invalid_client ngay khi test.*

react-oidc-context không bắt bạn phải tạo riêng 1 route cho redirect_uri: AuthProvider tự dò query string (code, state) ở bất kỳ trang nào nó đang mount và xử lý callback ngay tại đó — đây là lý do redirect_uri và silent_redirect_uri ở trên có thể cùng trỏ về "/". Cách này đơn giản, phù hợp để dạy trong 60 phút; ở môi trường production quy mô lớn hơn, đội ngũ thường tách 1 trang HTML tối giản riêng cho silent_redirect_uri để iframe ẩn không phải tải lại toàn bộ bundle React — nội dung tối ưu này để dành, không bắt buộc trong bài Lab hôm nay.

Wrap toàn bộ ứng dụng bằng AuthProvider trong apps/admin/src/main.tsx:

```typescript
import { StrictMode } from "react";
import { createRoot } from "react-dom/client";
import { AuthProvider } from "react-oidc-context";
import { oidcConfig } from "./auth/oidc-config";
import App from "./App";
 
createRoot(document.getElementById("root")!).render(
  <StrictMode>
    <AuthProvider {...oidcConfig}>
      <App />
    </AuthProvider>
  </StrictMode>,
);
```

## 3. Nút đăng nhập/đăng xuất & bảo vệ route

*Thời lượng: 15 phút | Loại: Demo + Lab*

Dùng hook useAuth() để đọc trạng thái đăng nhập và điều khiển luồng — component apps/admin/src/auth/AuthStatus.tsx:

```typescript
import { useAuth } from "react-oidc-context";
 
export function AuthStatus() {
  const auth = useAuth();
 
  if (auth.isLoading) return <span>Đang tải phiên đăng nhập...</span>;
  if (auth.error) return <span>Lỗi đăng nhập: {auth.error.message}</span>;
 
  if (auth.isAuthenticated) {
    return (
      <div>
        <span>Xin chào, {auth.user?.profile.name ?? auth.user?.profile.sub}</span>
        <button onClick={() => auth.removeUser()}>Đăng xuất</button>
      </div>
    );
  }
 
  return <button onClick={() => auth.signinRedirect()}>Đăng nhập</button>;
}
```

Bảo vệ toàn bộ route Admin (trừ trang giới thiệu nếu có) bằng withAuthenticationRequired — apps/admin/src/auth/ProtectedLayout.tsx:

```typescript
import { Outlet } from "react-router-dom";
import { withAuthenticationRequired } from "react-oidc-context";
 
function AdminLayout() {
  return <Outlet />; // sidebar, header thật sẽ thêm ở bài 6.3
}
 
export const ProtectedLayout = withAuthenticationRequired(AdminLayout, {
  OnRedirecting: () => <div>Đang chuyển sang trang đăng nhập...</div>,
});
```

Gắn vào router (apps/admin/src/router.tsx) — mọi route con của ProtectedLayout đều yêu cầu đăng nhập:

```typescript
import { createBrowserRouter } from "react-router-dom";
import { ProtectedLayout } from "./auth/ProtectedLayout";
 
export const router = createBrowserRouter([
  {
    path: "/",
    element: <ProtectedLayout />,
    children: [
      // các route Category/Course/Lesson của bài 6.3 sẽ khai báo ở đây
    ],
  },
]);
```

> **📘 Ghi chú giảng viên:** *Điểm hay bị nhầm: withAuthenticationRequired chỉ chặn ở phía UI (client-side) — nó không thay thế cho việc API endpoint backend phải tự kiểm tra Bearer token. Nhắc lại nguyên tắc đã học ở Module 3: không được chỉ ẩn UI mà quên chặn ở API, nếu không sẽ lặp lại đúng lỗi bảo mật mà outline đã cảnh báo ở bài 7.7 cho Next.js. Ở bài này API đã tự bảo vệ từ Module 3, nên route React chỉ cần lo trải nghiệm người dùng.*

## 4. Gắn access_token vào api-client & xử lý silent renew

*Thời lượng: 15 phút | Loại: Lab*

packages/api-client (sinh ra ở bài 5.2 bằng @hey-api/openapi-ts) export sẵn một client instance có hàm setConfig({ auth, baseUrl }) — trường auth nhận vào 1 hàm trả về chuỗi token, hàm này chỉ được gọi cho những request thật sự cần auth. Đọc token từ sessionStorage bằng chính API của oidc-client-ts, không cần lấy qua React component:

```typescript
import { User } from "oidc-client-ts";
import { client } from "@tedumarket/api-client/client.gen";
 
const authority = import.meta.env.VITE_OIDC_AUTHORITY;
const clientId = import.meta.env.VITE_OIDC_CLIENT_ID;
 
function getAccessToken(): string | undefined {
  const key = `oidc.user:${authority}:${clientId}`;
  const raw = sessionStorage.getItem(key);
  if (!raw) return undefined;
  return User.fromStorageString(raw)?.access_token;
}
 
client.setConfig({
  baseUrl: import.meta.env.VITE_API_BASE_URL,
  auth: () => getAccessToken(),
});
```

Gọi client.setConfig(...) này 1 lần khi app khởi động (ví dụ ngay trong main.tsx, sau khi import oidcConfig) — mọi lời gọi SDK sinh ra từ api-client (Module 5.2) từ đó sẽ tự đính kèm header Authorization: Bearer \<token> cho những endpoint được đánh dấu cần auth trong OpenAPI schema (Module 4.1).

Xử lý sự kiện token sắp hết hạn để chủ động gọi lại signinSilent, kết hợp với automaticSilentRenew đã bật ở bước 2 cho chắc chắn — thêm vào component gốc App.tsx:

```typescript
import { useEffect } from "react";
import { useAuth } from "react-oidc-context";
 
function App() {
  const auth = useAuth();
 
  useEffect(() => {
    // addAccessTokenExpiring trả về hàm cleanup — bắt buộc return trong useEffect
    return auth.events.addAccessTokenExpiring(() => {
      auth.signinSilent().catch((err) => {
        console.error("Silent renew thất bại, cần đăng nhập lại", err);
      });
    });
  }, [auth.events, auth.signinSilent]);
 
  // ... phần render Router giữ nguyên
}
```

> **📘 Ghi chú giảng viên:** *Nếu silent renew liên tục fail với lỗi login_required hoặc interaction_required, 90% nguyên nhân là cookie session của ASP.NET Core Identity đã hết hạn hoặc SameSite/domain cookie không cho phép load trong iframe. Đây là lúc quay lại kiểm tra cấu hình cookie authentication ở bài 3.2 — không phải lỗi ở phía React.*

# Bài tập thực hành

> **✏️ Thực hành:** Hoàn thiện luồng đăng nhập/đăng xuất thật cho apps/admin dựa trên OpenIddict Client đã đăng ký ở bài 3.3, đảm bảo: (1) mọi route trong ProtectedLayout tự động redirect sang trang login OpenIddict khi chưa đăng nhập; (2) sau khi đăng nhập thành công, quay lại đúng route đang định vào; (3) hiển thị tên người dùng (profile.name) và nút đăng xuất trên góc màn hình; (4) mở DevTools → Application → Session Storage, copy access_token, decode ở jwt.io để xác nhận đúng các claim role/InstructorId đã cấu hình ở bài 3.5.

### Input

- OpenIddict Client đã đăng ký ở bài 3.3 (client_id, redirect_uri, scope thật của môi trường dev).
- apps/admin đã chạy được từ bài 6.1 (pnpm dev, gọi thử API chưa auth thành công).

### Expected output

- Truy cập bất kỳ route nào của Admin khi chưa đăng nhập → tự động redirect sang trang đăng nhập OpenIddict, không cần code chặn thủ công.
- Đăng nhập xong → quay lại đúng Admin app, thấy tên người dùng, gọi thử 1 API cần auth (ví dụ GET /api/v1/categories) thành công với status 200.
- Đợi qua thời gian access token gần hết hạn (hoặc set tạm AccessTokenLifetime ngắn ở bài 3.2 để test nhanh) → không bị văng ra, silent renew chạy ngầm, xem được sự kiện trong console.

### Hint cho học viên bị kẹt

- Lỗi redirect_uri mismatch → so lại chính xác redirect_uri React đang gửi (xem tab Network, request tới /connect/authorize) với RedirectUris đã đăng ký ở bài 3.3.
- Lỗi invalid_scope → scope trong oidc-config.ts phải là tập con của Permissions.Scopes đã cấp cho Client ở bài 3.3, không được tự thêm scope mới ở đây.
- Không thấy nút Đăng xuất có tác dụng thật (vẫn còn vào lại được route cũ) → removeUser() chỉ xoá token phía client, muốn logout cả phiên OpenIddict cần gọi signoutRedirect() tới /connect/logout — có thể để lại cho bài sau nếu outline chưa yêu cầu, nhưng nên thử để hiểu khác biệt.

Solution tham khảo: dùng đúng 4 đoạn code mẫu ở mục Nội dung chính phía trên, ráp theo thứ tự oidc-config.ts → main.tsx → AuthStatus.tsx / ProtectedLayout.tsx → cấu hình client.setConfig trong api-client.

# Tổng kết

> **✅ Tóm tắt:** AuthProvider của react-oidc-context nối thẳng vào OpenIddict Client Public + PKCE đã đăng ký ở bài 3.3 — không cần tự viết lại PKCE. withAuthenticationRequired bảo vệ route ở tầng UI, còn API vẫn là tầng chặn thật sự (đã có từ Module 3). automaticSilentRenew + addAccessTokenExpiring giữ phiên làm việc liên tục. client.setConfig({ auth }) của packages/api-client là điểm nối duy nhất để mọi lời gọi API tự động mang theo access_token.

### Bước tiếp theo

Bài 6.3 — CRUD UI: Category, Course, Lesson sẽ dùng lại đúng luồng đăng nhập và access_token vừa dựng ở bài này để gọi các Command/Query đã xây từ Module 0–1, kết hợp React Query với hooks sinh ra từ api-client.

### Phụ lục — Cheat sheet react-oidc-context

- useAuth() — hook đọc trạng thái/điều khiển: isLoading, isAuthenticated, user, error, signinRedirect, signinSilent, removeUser, events.
- withAuthenticationRequired(Component, { OnRedirecting }) — HOC bảo vệ route.
- automaticSilentRenew — tự renew ngầm trước khi access token hết hạn.
- onSigninCallback — bắt buộc khai báo để dọn code/state khỏi URL sau khi đăng nhập, tránh xử lý callback lặp lại.
- PKCE (Proof Key for Code Exchange) — cơ chế thay thế client secret cho public client, dùng cặp code_verifier/code_challenge sinh động mỗi lần đăng nhập.
