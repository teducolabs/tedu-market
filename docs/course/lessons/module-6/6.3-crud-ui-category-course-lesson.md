## 2. Pattern dùng chung: gọi …Options()/…Mutation() và đọc lỗi ProblemDetails

*Thời lượng: 12 phút | Loại: Demo*

Viết pattern này 1 lần, dùng lại y hệt cho cả 3 resource ở phần 3–5 — đúng tinh thần luyện lại pattern đến khi thành phản xạ mà outline đã áp dụng xuyên suốt Module 0–1.

### 2.1. Đọc lại 2 file đã sinh sẵn từ bài 5.2

packages/api-client/src/react-query.gen.ts export sẵn getCategoriesOptions(), getCoursesOptions(), getCourseDetailOptions() cho phía đọc, và createCategoryMutation(), updateCategoryMutation(), deleteCategoryMutation(), createCourseMutation(), updateCourseMutation(), addLessonMutation(), updateLessonMutation(), removeLessonMutation(), reorderLessonsMutation() cho phía ghi — tên hàm sinh tự động từ operationId đã đặt bằng WithName() ở Module 1/4, đúng convention "append Options / Mutation" của plugin @tanstack/react-query mà tài liệu chính thức Hey API mô tả.

> **⚠️ Lưu ý:** Hàm …Mutation() sinh ra là 1 mutation OPTIONS FACTORY (trả về object { mutationFn, ... }) để spread vào useMutation({ ...xMutation(), onSuccess... }) — không phải 1 React hook gọi trực tiếp như useXMutation(). Bản 0.83.1 đang dùng ở bài 5.2 chưa có dạng hook sẵn (tính năng đó chỉ mới xuất hiện ở nhánh phát triển sau này của thư viện) — nếu nâng cấp @hey-api/openapi-ts sau này, kiểm tra lại CHANGELOG trước khi đổi cách gọi.

### 2.2. Helper đọc lỗi ProblemDetails

errorCode/traceId đã chuẩn hóa ở bài 4.5 cho MỌI lỗi. Với lỗi 400 (ValidationProblem từ FluentValidation, bài 0.5), ProblemDetails có thêm field errors — 1 dictionary field name (PascalCase, đúng tên property C#) → mảng message. Viết 1 helper dùng chung:

*apps/admin/src/lib/api-error.ts*

```typescript
import type { ClientOptions } from "@tedu-market/api-client";
 
// Shape rút gọn của ProblemDetails/HttpValidationProblemDetails (bài 4.5)
export interface ProblemDetails {
  title?: string;
  detail?: string;
  status?: number;
  traceId?: string;
  errorCode?: string;
  errors?: Record<string, string[]>;
}
 
// FluentValidation trả tên field PascalCase (khớp property C#, vd "Name", "Title"),
// state trong form React lại đặt camelCase (name, title) — hạ chữ cái đầu để map đúng.
export function toFieldErrors(problem?: ProblemDetails): Record<string, string> {
  if (!problem?.errors) return {};
  return Object.fromEntries(
    Object.entries(problem.errors).map(([field, messages]) => [
      field.charAt(0).toLowerCase() + field.slice(1),
      messages[0],
    ]),
  );
}
 
// Lỗi nghiệp vụ (409 CategoryInUseException, CourseLessonOrderInvalidException...)
// không có "errors" field — chỉ hiển thị detail kèm errorCode để dễ đối chiếu log.
export function toBusinessMessage(problem?: ProblemDetails): string {
  if (!problem) return "Có lỗi không xác định, thử lại sau.";
  return problem.errorCode
    ? `${problem.detail ?? problem.title} (mã lỗi: ${problem.errorCode})`
    : problem.detail ?? problem.title ?? "Có lỗi không xác định.";
}
```

SDK do @hey-api/client-fetch sinh trả { data, error } cho mọi lời gọi (đã xác nhận đúng ở bài 5.4) — error chính là ProblemDetails JSON parse sẵn. useMutation của react-query.gen.ts tự throw khi error khác null, nên onError của useMutation nhận trực tiếp object ProblemDetails, dùng thẳng 2 helper trên.

## 3. Category CRUD hoàn chỉnh

*Thời lượng: 15 phút | Loại: Demo*

Category là resource đơn giản nhất — không phân trang thật (bài 4.5 đã bọc GetCategoriesQuery trong PagedResult\<CategoryDto> với PageSize=int.MaxValue), không có nested resource. Làm mẫu đầy đủ List → Create → Update → Delete ở đây, Course/Lesson ở phần 4–5 chỉ khác ở chỗ có phân trang thật và có nested Lesson.

### 3.1. CategoryListPage — danh sách + xóa

*apps/admin/src/routes/categories/CategoryListPage.tsx*

```typescript
import { useQuery, useMutation, useQueryClient } from "@tanstack/react-query";
import { Link } from "react-router-dom";
import { getCategoriesOptions, deleteCategoryMutation } from "@tedu-market/api-client/react-query.gen";
import { toBusinessMessage, type ProblemDetails } from "../../lib/api-error";
 
export function CategoryListPage() {
  const queryClient = useQueryClient();
  const categoriesQuery = useQuery(getCategoriesOptions());
 
  const deleteMutation = useMutation({
    ...deleteCategoryMutation(),
    onSuccess: () => {
      // Query key do plugin sinh tự động từ operationId + params — invalidate
      // theo prefix "getCategories" là đủ để refetch mọi biến thể tham số.
      queryClient.invalidateQueries({ queryKey: ["getCategories"] });
    },
    onError: (error: ProblemDetails) => alert(toBusinessMessage(error)),
  });
 
  if (categoriesQuery.isPending) return <p>Đang tải danh sách Category...</p>;
  if (categoriesQuery.isError) return <p>Không tải được danh sách Category.</p>;
 
  return (
    <div>
      <div style={{ display: "flex", justifyContent: "space-between" }}>
        <h1>Category</h1>
        <Link to="/categories/new">+ Thêm Category</Link>
      </div>
      <table>
        <thead><tr><th>Tên</th><th /></tr></thead>
        <tbody>
          {categoriesQuery.data.items.map((c) => (
            <tr key={c.id}>
              <td>{c.name}</td>
              <td>
                <Link to={`/categories/${c.id}/edit`}>Sửa</Link>
                {" · "}
                <button
                  onClick={() => {
                    if (confirm(`Xóa Category "${c.name}"?`)) {
                      deleteMutation.mutate({ path: { id: c.id } });
                    }
                  }}
                >
                  Xóa
                </button>
              </td>
            </tr>
          ))}
        </tbody>
      </table>
    </div>
  );
}
```

> **📘 Ghi chú giảng viên:** *categoriesQuery.data.items — không phải categoriesQuery.data trực tiếp — vì response là PagedResult\<CategoryDto> (bài 4.5), field Items (C#, PascalCase) serialize JSON camelCase thành items (bài 5.4 đã xác nhận .NET 10 Minimal API mặc định JsonNamingPolicy.CamelCase). Học viên quên .items là lỗi TypeScript đầu tiên gần như chắc chắn gặp ở bài này — nhưng đây là lỗi tốt: compile-time, không phải runtime, đúng giá trị cốt lõi của Module 5.*

### 3.2. CategoryFormPage — dùng chung cho Create và Update

Không có endpoint GetCategoryDetail riêng (outline chỉ có GetCategoriesQuery, bài 0.8) — khi Sửa, lấy Category cần sửa từ CHÍNH cache list đã có, không gọi thêm 1 API riêng.

*apps/admin/src/routes/categories/CategoryFormPage.tsx*

```typescript
import { useState } from "react";
import { useNavigate, useParams } from "react-router-dom";
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import {
  getCategoriesOptions,
  createCategoryMutation,
  updateCategoryMutation,
} from "@tedu-market/api-client/react-query.gen";
import { toFieldErrors, type ProblemDetails } from "../../lib/api-error";
 
export function CategoryFormPage() {
  const { id } = useParams(); // có id -> Sửa, không có -> Tạo mới
  const isEdit = Boolean(id);
  const navigate = useNavigate();
  const queryClient = useQueryClient();
 
  // Dùng lại cache list đã fetch ở CategoryListPage thay vì gọi thêm API detail
  const categoriesQuery = useQuery(getCategoriesOptions());
  const editing = categoriesQuery.data?.items.find((c) => c.id === id);
 
  const [name, setName] = useState(editing?.name ?? "");
  const [fieldErrors, setFieldErrors] = useState<Record<string, string>>({});
 
  const createMutation = useMutation(createCategoryMutation());
  const updateMutation = useMutation(updateCategoryMutation());
  const pending = createMutation.isPending || updateMutation.isPending;
 
  function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    setFieldErrors({});
    const options = isEdit
      ? { path: { id: id! }, body: { id: id!, name } }
      : { body: { name } };
    const mutation = isEdit ? updateMutation : createMutation;
 
    mutation.mutate(options as never, {
      onSuccess: () => {
        queryClient.invalidateQueries({ queryKey: ["getCategories"] });
        navigate("/categories");
      },
      onError: (error: ProblemDetails) => setFieldErrors(toFieldErrors(error)),
    });
  }
 
  return (
    <form onSubmit={handleSubmit}>
      <h1>{isEdit ? "Sửa Category" : "Thêm Category"}</h1>
      <label>
        Tên Category
        <input value={name} onChange={(e) => setName(e.target.value)} />
      </label>
      {fieldErrors.name && <p style={{ color: "red" }}>{fieldErrors.name}</p>}
      <button type="submit" disabled={pending}>
        {pending ? "Đang lưu..." : "Lưu"}
      </button>
    </form>
  );
}
```

> **⚠️ Lưu ý:** mutation.mutate(options as never, ...) — ép kiểu tạm thời vì createCategoryMutation()/updateCategoryMutation() có type input khác nhau (create không có path.id, update có), trong khi form dùng chung 1 biến mutation. Cách sạch hơn (không ép kiểu) là tách hẳn 2 nhánh if/else gọi createMutation.mutate(...) / updateMutation.mutate(...) riêng — bài để type ép này lại có chủ đích, hỏi thẳng học viên ở phần Bài tập nên chọn cách nào cho code thật.

Xóa 1 Category còn Course tham chiếu: bài 1.9 đã dạy CategoryInUseException → 409. Nút Xóa ở CategoryListPage phía trên đã bắt onError và gọi toBusinessMessage(error) — thử xóa 1 Category đang có Course để thấy đúng message kèm errorCode (vd category_in_use), không phải lỗi mất kiểm soát.

## 4. Course CRUD: danh sách có phân trang + form

*Thời lượng: 15 phút | Loại: Demo*

### 4.1. CourseListPage — phân trang thật

Khác Category, GetCoursesQuery (bài 1.6) có phân trang/filter/sort thật bằng OFFSET/FETCH — component phải tự quản lý page trong URL query string để bấm Back/Forward hay refresh không mất trạng thái:

*apps/admin/src/routes/courses/CourseListPage.tsx*

```typescript
import { useQuery } from "@tanstack/react-query";
import { Link, useSearchParams } from "react-router-dom";
import { getCoursesOptions } from "@tedu-market/api-client/react-query.gen";
 
const PAGE_SIZE = 20;
 
export function CourseListPage() {
  const [searchParams, setSearchParams] = useSearchParams();
  const page = Number(searchParams.get("page") ?? "1");
 
  const coursesQuery = useQuery(
    getCoursesOptions({ query: { page, pageSize: PAGE_SIZE } }),
  );
 
  if (coursesQuery.isPending) return <p>Đang tải danh sách Course...</p>;
  if (coursesQuery.isError) return <p>Không tải được danh sách Course.</p>;
 
  const { items, totalPages } = coursesQuery.data;
 
  return (
    <div>
      <div style={{ display: "flex", justifyContent: "space-between" }}>
        <h1>Course (trang {page}/{totalPages})</h1>
        <Link to="/courses/new">+ Thêm Course</Link>
      </div>
      <table>
        <thead><tr><th>Tiêu đề</th><th>Category</th><th /></tr></thead>
        <tbody>
          {items.map((course) => (
            <tr key={course.id}>
              <td><Link to={`/courses/${course.slug}`}>{course.title}</Link></td>
              <td>{course.categoryName}</td>
              <td><Link to={`/courses/${course.slug}/edit`}>Sửa</Link></td>
            </tr>
          ))}
        </tbody>
      </table>
      <button disabled={page <= 1} onClick={() => setSearchParams({ page: String(page - 1) })}>
        « Trang trước
      </button>
      <button disabled={page >= totalPages} onClick={() => setSearchParams({ page: String(page + 1) })}>
        Trang sau »
      </button>
    </div>
  );
}
```

> **📘 Ghi chú giảng viên:** *Dùng useSearchParams thay vì useState(page) cho state phân trang — lý do thật, không phải sở thích cá nhân: refresh trang hoặc bấm nút Back của trình duyệt vẫn giữ đúng trang đang xem, vì page nằm trên URL (?page=2) chứ không nằm trong bộ nhớ component. Đây cũng là lý do queryKey do react-query.gen.ts sinh ra bao gồm cả query params — mỗi trang phân trang là 1 cache entry riêng, chuyển qua lại giữa các trang đã xem không phải gọi lại API.*

### 4.2. CourseFormPage — liên kết đến CourseDetailPage

Route dùng slug (không dùng id) — khớp đúng GetCourseDetailQuery(slug) đã viết ở bài 1.7 (route công khai GET /api/v1/courses/{slug}), Admin dùng lại đúng endpoint đó thay vì đòi hỏi thêm 1 query GetCourseById chỉ để phục vụ riêng trang Admin. instructorId lấy từ claim instructor_id đã cấu hình ở bài 3.5, có sẵn trong auth.user.profile sau khi đăng nhập (bài 6.2):

*apps/admin/src/routes/courses/CourseFormPage.tsx*

```typescript
import { useState } from "react";
import { useAuth } from "react-oidc-context";
import { useNavigate, useParams } from "react-router-dom";
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import {
  getCategoriesOptions,
  getCourseDetailOptions,
  createCourseMutation,
  updateCourseMutation,
} from "@tedu-market/api-client/react-query.gen";
import { toFieldErrors, type ProblemDetails } from "../../lib/api-error";
 
export function CourseFormPage() {
  const { slug } = useParams();
  const isEdit = Boolean(slug);
  const auth = useAuth();
  const instructorId = auth.user?.profile.instructor_id as string;
  const navigate = useNavigate();
  const queryClient = useQueryClient();
 
  const categoriesQuery = useQuery(getCategoriesOptions());
  const courseQuery = useQuery({
    ...getCourseDetailOptions({ path: { slug: slug! } }),
    enabled: isEdit, // chỉ gọi khi đang Sửa, tránh gọi API với slug undefined
  });
 
  const [title, setTitle] = useState(courseQuery.data?.title ?? "");
  const [categoryId, setCategoryId] = useState(courseQuery.data?.categoryId ?? "");
  const [fieldErrors, setFieldErrors] = useState<Record<string, string>>({});
 
  const createMutation = useMutation(createCourseMutation());
  const updateMutation = useMutation(updateCourseMutation());
 
  function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    setFieldErrors({});
    const body = { title, categoryId, instructorId };
 
    if (isEdit) {
      updateMutation.mutate(
        { path: { id: courseQuery.data!.id }, body: { id: courseQuery.data!.id, ...body } },
        {
          onSuccess: () => {
            queryClient.invalidateQueries({ queryKey: ["getCourses"] });
            queryClient.invalidateQueries({ queryKey: ["getCourseDetail"] });
            navigate(`/courses/${slug}`);
          },
          onError: (error: ProblemDetails) => setFieldErrors(toFieldErrors(error)),
        },
      );
    } else {
      createMutation.mutate(
        { body },
        {
          onSuccess: (created) => {
            queryClient.invalidateQueries({ queryKey: ["getCourses"] });
            navigate(`/courses/${created.slug}`);
          },
          onError: (error: ProblemDetails) => setFieldErrors(toFieldErrors(error)),
        },
      );
    }
  }
 
  return (
    <form onSubmit={handleSubmit}>
      <h1>{isEdit ? "Sửa Course" : "Thêm Course"}</h1>
      <label>
        Tiêu đề
        <input value={title} onChange={(e) => setTitle(e.target.value)} />
      </label>
      {fieldErrors.title && <p style={{ color: "red" }}>{fieldErrors.title}</p>}
      <label>
        Category
        <select value={categoryId} onChange={(e) => setCategoryId(e.target.value)}>
          <option value="">-- Chọn Category --</option>
          {categoriesQuery.data?.items.map((c) => (
            <option key={c.id} value={c.id}>{c.name}</option>
          ))}
        </select>
      </label>
      <button type="submit">Lưu</button>
    </form>
  );
}
```

> **⚠️ Lưu ý:** auth.user?.profile.instructor_id as string ép kiểu tạm — profile của react-oidc-context gõ kiểu Record\<string, unknown> vì claim tùy biến (custom claim) không nằm trong chuẩn OIDC. Cách chặt chẽ hơn cho code thật: viết 1 interface AppUserProfile mở rộng IdTokenClaims (thêm field instructor_id) và ép kiểu 1 lần duy nhất ở auth/oidc-config.ts (bài 6.2), không rải as string mỗi nơi dùng.

## 5. CourseDetailPage: quản lý Lesson đúng Aggregate boundary

*Thời lượng: 10 phút | Loại: Lab (học viên tự ráp theo hướng dẫn)*

Đây là phần thể hiện rõ nhất lý do outline gộp Lesson vào cùng trang Course: mọi nút bấm ở đây gọi thẳng 1 trong 4 Command đã học ở bài 1.3 (AddLessonCommand, UpdateLessonCommand, RemoveLessonCommand, ReorderLessonsCommand) — không có khái niệm "sửa Lesson" tách rời khỏi Course trên UI, đúng với việc Domain layer không cho phép điều đó.

### 5.1. Khung trang + danh sách Lesson

*apps/admin/src/routes/courses/CourseDetailPage.tsx*

```typescript
import { useState } from "react";
import { useAuth } from "react-oidc-context";
import { useParams } from "react-router-dom";
import { useMutation, useQuery, useQueryClient } from "@tanstack/react-query";
import {
  getCourseDetailOptions,
  addLessonMutation,
  updateLessonMutation,
  removeLessonMutation,
  reorderLessonsMutation,
} from "@tedu-market/api-client/react-query.gen";
import { toBusinessMessage, type ProblemDetails } from "../../lib/api-error";
```

# Bài tập thực hành

> **✏️ Thực hành:** Thêm optimistic update cho nút Xóa ở CategoryListPage: ẩn ngay dòng Category khỏi bảng lúc vừa bấm Xóa (trước khi server trả lời), và tự động hiện lại nếu server trả lỗi (409 CategoryInUseException) — không đợi round-trip xong mới cập nhật UI.

### Input

- CategoryListPage.tsx đã hoàn chỉnh ở mục 3.1.
- useMutation của TanStack Query v5 có 3 callback hỗ trợ optimistic update: onMutate (chạy TRƯỚC khi request gửi đi, nơi để lưu lại state cũ và cập nhật cache tạm), onError (rollback nếu request lỗi), onSettled (luôn chạy sau cùng, dùng để đảm bảo cache đồng bộ lại với server).

### Expected output

- Bấm Xóa → dòng Category biến mất khỏi bảng NGAY LẬP TỨC, không có độ trễ chờ network.
- Nếu server trả 200 (xóa thành công) → không có gì thay đổi thêm, danh sách đã đúng từ trước.
- Nếu server trả 409 (Category còn Course) → dòng Category tự động hiện lại đúng vị trí cũ, kèm thông báo lỗi.

### Hint cho học viên bị kẹt

- onMutate nhận variables (chính options truyền vào mutate(...)) — dùng queryClient.getQueryData(["getCategories"]) để lấy snapshot hiện tại TRƯỚC khi sửa, rồi queryClient.setQueryData để loại bỏ Category khỏi cache.
- onMutate phải return snapshot đó ra ngoài — object return từ onMutate chính là context, TanStack Query tự truyền lại cho onError như tham số thứ 3.
- onError dùng context nhận được để setQueryData lại đúng snapshot cũ — đây chính là bước "rollback".
- Không quên onSettled gọi invalidateQueries như cũ — optimistic update chỉ là hiệu ứng tạm thời, vẫn cần đồng bộ lại với server thật sau cùng để tránh cache lệch nếu có người khác cũng đang sửa Category đó.

Solution tham khảo: thay khối deleteMutation ở mục 3.1 bằng bản có đủ onMutate/onError/onSettled theo đúng 4 hint phía trên — cấu trúc dùng lại y hệt, chỉ thêm object thứ 2 truyền vào useMutation.

### Cheatsheet query key mặc định của plugin @tanstack/react-query

- Query: key bắt đầu bằng tên hàm SDK gốc (không có hậu tố Options) + params — vd getCategories() → ["getCategories"].
- invalidateQueries({ queryKey: ["getCategories"] }) không truyền exact: true sẽ khớp MỌI query có prefix này, kể cả khi có thêm params (vd phân trang) — đúng hành vi mong muốn ở bài này.
- Muốn xem chính xác key thật đang dùng: mở React Query Devtools (chưa cài ở bài này, có thể thêm bằng @tanstack/react-query-devtools nếu học viên muốn debug sâu hơn).
