# **Nội dung chính**

## **1. Ôn lại Query side & thiết kế route cho Order/Revenue**

*Thời lượng: 10 phút | Loại: Lý thuyết*

Ở bài 2.8, bạn đã viết GetOrderHistoryQuery và GetInstructorRevenueQuery — cả hai đều dùng Dapper, đọc thẳng từ read model, không đụng Aggregate Order của Command side. Bài 4.5 (Chuẩn hóa response & error format) đã review lại toàn bộ endpoint từ Module 0–3, nên 2 query này đã có sẵn Minimal API endpoint tương ứng, được annotate OpenAPI ở bài 4.1 và versioning ở bài 4.3. Bài này không viết thêm code backend — chỉ tiêu thụ (consume) 2 endpoint đó từ React Admin.

Theo đúng quy ước đặt tên ở mục 7 outline (/api/v1/{số nhiều thực thể}), route cho 2 query này:

```
GET /api/v1/orders?instructorId={id}&status={status}&from={date}&to={date}&page={n}&pageSize={n}
  → GetOrderHistoryQuery — trả OrderListItemDto (mã đơn, học viên, khóa học, số tiền, trạng thái, ngày tạo)
 
GET /api/v1/instructors/{instructorId}/revenue?from={date}&to={date}
```

→ GetInstructorRevenueQuery — trả InstructorRevenuePointDto[] (month, totalRevenue, orderCount)

> **📘 Ghi chú giảng viên:** *Tôi luôn nhấn mạnh lại ở đây: GetInstructorRevenueQuery group theo tháng ngay trong câu SQL Dapper (GROUP BY date_trunc('month', paid_at)), không phải fetch hết Order rồi group ở client bằng JavaScript. Học viên mới hay có xu hướng "lười" query, fetch raw data về rồi xử lý ở frontend — đây chính là điểm hỏng của Query side đã học ở bài 0.8 và 1.6: Query side tồn tại để tối ưu tốc độ đọc, group-by ở DB luôn rẻ hơn ship hàng nghìn dòng JSON qua network rồi loop ở browser.*

operationId của 2 endpoint này (đặt ở bài 4.1 bằng .WithName()) là GetOrders và GetInstructorRevenue. Plugin @tanstack/react-query của @hey-api/openapi-ts (bài 5.2) sinh ra 2 hàm queryOptions tương ứng, đặt tên theo operationId + hậu tố Options, camelCase:

```typescript
// packages/api-client/src/react-query.gen.ts (tự động sinh — không sửa tay)
export const getOrdersOptions = (options) => queryOptions({
  queryKey: ['GetOrders', options],
  queryFn: () => client.GET('/api/v1/orders', options),
});
 
export const getInstructorRevenueOptions = (options) => queryOptions({
  queryKey: ['GetInstructorRevenue', options],
  queryFn: () => client.GET('/api/v1/instructors/{instructorId}/revenue', options),
});
```

> **📘 Ghi chú giảng viên:** *Đây là điểm bài 5.4 đã chứng minh bằng video: nếu backend đổi field của OrderListItemDto, chạy pnpm generate:client lại (bài 5.3) thì file react-query.gen.ts này tự cập nhật, và TypeScript báo lỗi compile-time ngay tại nơi bạn destructure field cũ. Không cần nhớ để tự sửa tay.*

## **2. Trang Order List**

*Thời lượng: 15 phút | Loại: Demo + Lab*

Tạo apps/admin/src/pages/orders/OrdersPage.tsx. Giữ nguyên cấu trúc component + cách dùng useQuery đã lặp lại ở bài 6.3 (CRUD UI Category/Course/Lesson) — khác biệt duy nhất là trang này chỉ đọc (read-only), không có Command nào cả vì Order là immutable (đã học ở bài 2.1: Order bất biến ngay khi tạo, không có UpdateOrderCommand).

```tsx
// apps/admin/src/pages/orders/OrdersPage.tsx
import { useState } from 'react';
import { useQuery } from '@tanstack/react-query';
import { getOrdersOptions } from '@tedu-market/api-client';
 
const STATUS_LABEL: Record<string, string> = {
  Pending: 'Chờ thanh toán',
  Paid: 'Đã thanh toán',
};
 
export function OrdersPage() {
  const [status, setStatus] = useState<string | undefined>(undefined);
  const [page, setPage] = useState(1);
 
  const { data, isPending, isError, error } = useQuery(
    getOrdersOptions({
      query: { status, page, pageSize: 20 },
    }),
  );
 
  if (isPending) return <OrdersTableSkeleton />;
  if (isError) return <ErrorBanner detail={error} />; // parse ProblemDetails — hoàn thiện ở bài 6.6
 
  return (
    <div>
      <OrderStatusFilter value={status} onChange={setStatus} />
      <table className="tedu-table">
        <thead>
          <tr>
            <th>Mã đơn</th><th>Học viên</th><th>Khóa học</th>
            <th>Số tiền</th><th>Trạng thái</th><th>Ngày tạo</th>
          </tr>
        </thead>
        <tbody>
          {data.items.map((order) => (
            <tr key={order.id}>
              <td>{order.code}</td>
              <td>{order.studentName}</td>
              <td>{order.courseTitle}</td>
              <td>{formatVnd(order.totalAmount)}</td>
              <td><StatusBadge>{STATUS_LABEL[order.status]}</StatusBadge></td>
              <td>{formatDate(order.createdAt)}</td>
            </tr>
          ))}
        </tbody>
      </table>
      <Pagination page={page} totalPages={data.totalPages} onChange={setPage} />
    </div>
  );
}
 
function formatVnd(amount: number) {
  return new Intl.NumberFormat('vi-VN', { style: 'currency', currency: 'VND' }).format(amount);
}
```

> **📘 Ghi chú giảng viên:** *Điểm hay bị hỏi: "Sao không có nút Sửa/Xóa Order như bài 6.3 có nút Sửa/Xóa Course?". Nhắc lại lý do nghiệp vụ từ bài 2.1 — Order là bản ghi lịch sử, sửa Order sau khi tạo phá vỡ tính toàn vẹn kế toán. Nếu cần thay đổi trạng thái, phải đi qua đúng luồng nghiệp vụ (webhook SePay ở bài 2.5, hoặc một Command riêng như CancelOrderCommand nếu khóa học có tính năng hủy đơn) — không có chuyện PATCH thẳng field status từ UI Admin.*

OrderStatusFilter, StatusBadge, Pagination, ErrorBanner là các component dùng chung đã tạo từ bài 6.3 — import lại từ apps/admin/src/components/, không viết lại.

## **3. Dashboard doanh thu với Recharts**

*Thời lượng: 15 phút | Loại: Demo + Lab*

Cài Recharts (bản 2.x trở lên — đã hỗ trợ React 19 từ v2.13): pnpm --filter admin add recharts. Recharts render bằng SVG thuần, component hóa hoàn toàn kiểu React nên không cần thêm adapter như Chart.js.

```tsx
// apps/admin/src/pages/orders/RevenueDashboard.tsx
import { useQuery } from '@tanstack/react-query';
import {
  ResponsiveContainer, BarChart, Bar, XAxis, YAxis,
  CartesianGrid, Tooltip,
} from 'recharts';
import { getInstructorRevenueOptions } from '@tedu-market/api-client';
 
export function RevenueDashboard({ instructorId }: { instructorId: string }) {
  const { data, isPending, isError } = useQuery(
    getInstructorRevenueOptions({
      path: { instructorId },
      query: { from: startOfYearIso(), to: todayIso() },
    }),
  );
 
  if (isPending) return <ChartSkeleton />;
  if (isError) return <ErrorBanner />;
 
  const totalRevenue = data.reduce((sum, point) => sum + point.totalRevenue, 0);
 
  return (
    <section>
      <h3>Doanh thu 12 tháng gần nhất — {formatVnd(totalRevenue)}</h3>
      <ResponsiveContainer width="100%" height={320}>
        <BarChart data={data} margin={{ top: 8, right: 16, left: 8, bottom: 8 }}>
          <CartesianGrid strokeDasharray="3 3" stroke="#eee" />
          <XAxis dataKey="month" tickFormatter={formatMonth} />
          <YAxis tickFormatter={(v) => formatVnd(v)} width={90} />
          <Tooltip
            formatter={(value: number) => formatVnd(value)}
            labelFormatter={formatMonth}
          />
          <Bar dataKey="totalRevenue" fill="#1E4D8C" radius={[4, 4, 0, 0]} />
        </BarChart>
      </ResponsiveContainer>
    </section>
  );
}
```

> **📘 Ghi chú giảng viên:** *data ở đây gõ type sẵn từ InstructorRevenuePointDto do api-client sinh ra — không cần khai báo interface tay trong component React. Đây chính là giá trị cốt lõi của Module 5: đổi shape DTO ở C# → chạy generate:client → TypeScript báo lỗi ngay ở dòng data.totalRevenue nếu tên field đổi, thay vì runtime mới phát hiện field undefined như khi tự viết fetch() tay.*

Ghép 2 component lại trong 1 trang duy nhất:

```tsx
// apps/admin/src/pages/orders/index.tsx
export function OrderManagementPage() {
  const { instructorId } = useCurrentInstructor(); // đọc claims từ token, bài 6.2 + 3.5
  return (
    <div className="tedu-page">
      <RevenueDashboard instructorId={instructorId} />
      <OrdersPage />
    </div>
  );
}
```

> **📘 Ghi chú giảng viên:** *useCurrentInstructor() đọc claim InstructorId đã nhét vào Access Token từ bài 3.5 (Custom Claims & Scope) — không gọi thêm API để lấy profile Instructor. Đây là lý do bài 3.5 nhấn mạnh đưa Role/InstructorId vào token: Resource Server và cả frontend đều đọc claim thẳng, không round-trip thêm.*

# **Bài tập thực hành**

>
> **✏️ Thực hành:** Thêm cột "Số đơn hàng" (orderCount) hiển thị dạng LineChart chồng lên BarChart doanh thu bằng ComposedChart của Recharts (kết hợp \<Bar> và \<Line> trong cùng 1 chart, dùng chung trục X). Hint: import ComposedChart, Line từ 'recharts' thay vì BarChart. Solution tham khảo trong ghi chú giảng viên bài kế tiếp nếu bị kẹt quá 15 phút.

# **Tổng kết**

- Order List và Revenue Dashboard chỉ là lớp hiển thị (view layer) — toàn bộ logic tính toán, group-by đã nằm sẵn trong GetOrderHistoryQuery/GetInstructorRevenueQuery (Dapper, bài 2.8).
- Order là bản ghi bất biến (bài 2.1) nên trang quản lý Order trong Admin chỉ đọc, không có Command sửa/xóa trực tiếp.
- Mọi lời gọi API đều đi qua hàm {operationId}Options() do @hey-api/openapi-ts sinh ra (bài 5.2) và useQuery của @tanstack/react-query v5 — dùng isPending (không phải isLoading, đã đổi tên từ v5) để kiểm tra trạng thái tải lần đầu.
- Recharts (SVG, tương thích React 19 từ v2.13) đủ dùng cho biểu đồ doanh thu cơ bản — component hóa hoàn toàn, không cần imperative API.
- InstructorId lấy từ claim trong Access Token (bài 3.5), không gọi thêm API riêng để xác định "tôi là ai".

> **✅ Tóm tắt:** Trang Order List + Dashboard doanh thu chạy được thật trong apps/admin, dữ liệu type-safe end-to-end từ Dapper query đến component React.
