## **1. Vị trí bài học trong lộ trình**

*5 phút · Lý thuyết ngắn*

Từ Module 5, bạn đã có 2 thứ chạy được: monorepo Turborepo với apps/admin, apps/web là 2 thư mục rỗng (bài 5.1), và packages/api-client — 1 package TypeScript build sẵn, export type-safe function cho mọi endpoint của TeduMarket.Api (bài 5.2, generate bằng @hey-api/openapi-ts từ openapi.json ở Module 4.1).

Bài này là lần đầu tiên packages/api-client được dùng thật, không còn nằm im trong package.json. Bạn dựng bộ khung React thật cho apps/admin, và chứng minh luồng type-safe end-to-end mà Module 5.4 đã demo bằng video giờ hoạt động trong 1 app React thật — không phải video minh họa nữa.

Auth (OIDC + PKCE) chưa xuất hiện ở bài này — đó là bài 6.2. Ở đây bạn chỉ gọi 1 API public, không cần token, để tách riêng vấn đề "kết nối FE-BE có chạy không" khỏi vấn đề "auth có đúng không". Gộp 2 việc này vào 1 bài là lý do phổ biến nhất khiến học viên debug sai chỗ — không biết lỗi đến từ network/CORS hay từ token.

> **📘 Ghi chú giảng viên:** *Tôi hay nhấn mạnh điểm này ngay đầu bài: nếu đến bài 6.2 mà học viên vẫn nhầm lỗi 401 (do chưa có token) với lỗi CORS hay lỗi network (do sai base URL), thường là vì bài 6.1 chưa thực sự chạy được API public trước. Đừng để học viên nhảy cóc sang 6.2 khi bài này chưa xanh.*

## **2. Scaffold apps/admin bằng Vite**

*10 phút · Demo + Lab*

Thư mục apps/admin đã tồn tại từ bài 5.1 nhưng đang rỗng (hoặc chỉ có 1 file .gitkeep). Vite hỗ trợ scaffold thẳng vào thư mục hiện tại bằng dấu "." làm tên project, nên bạn không cần tạo thư mục mới rồi copy.

Từ thư mục gốc monorepo (frontend/):

```bash
cd apps/admin
pnpm create vite . --template react-ts
```

Vite hỏi xác nhận ghi đè thư mục không rỗng — chọn Yes vì thư mục hiện chỉ có .gitkeep. Sau khi scaffold xong, quay lại thư mục gốc monorepo và cài đặt — luôn cài ở root, không cài riêng trong apps/admin, vì đây là pnpm workspace dùng 1 lockfile chung (đã thiết lập nguyên tắc này từ bài 5.1):

```bash
cd ../..
pnpm install
```

Mở apps/admin/package.json, đổi "name" thành scoped name theo namespace chung của monorepo — dùng nhất quán @tedu-market/admin cho toàn bộ các bài sau:

```json
{
  "name": "@tedu-market/admin",
  "private": true,
  ...
}
```

Chạy thử:

```bash
pnpm --filter @tedu-market/admin dev
```

Vite dev server mặc định chạy ở http://localhost:5173. Mở trình duyệt, thấy trang React mẫu (logo Vite + React xoay) là scaffold thành công.

> **📘 Ghi chú giảng viên:** *Học viên hay quên --filter khi chạy lệnh từ root và gõ nhầm 'pnpm dev' — lệnh này chạy dev script của mọi package cùng lúc nếu turbo.json cấu hình vậy, dễ gây nhầm lẫn log. Tôi luôn demo cả 2 cách: pnpm --filter \<tên-package> \<script> để chạy đúng 1 package, và pnpm dev ở root (chạy qua turbo, dùng cho các bài sau khi cần chạy đồng thời admin + web).*

## **3. Kết nối apps/admin với packages/api-client**

*5 phút · Demo*

Thêm packages/api-client làm dependency của apps/admin bằng pnpm workspace protocol — không dùng version number, vì package này không publish lên npm registry, chỉ sống trong monorepo:

```json
# apps/admin/package.json
"dependencies": {
  "@tedu-market/api-client": "workspace:*",
  "react": "^19.0.0",
  "react-dom": "^19.0.0"
}
```

workspace:\* báo cho pnpm: chỉ resolve package này từ workspace hiện tại, không bao giờ tải từ npm registry, và cài đặt thất bại ngay nếu package không tồn tại trong workspace — an toàn hơn version number thường vì tránh trường hợp lỡ có package trùng tên ngoài registry.

```bash
pnpm install
```

Xác nhận pnpm đã link đúng bằng cách kiểm tra symlink:

```
ls -la node_modules/@tedu-market/api-client
```

Kết quả phải là symlink trỏ vào ../../packages/api-client, không phải một bản copy — đây chính là cơ chế giúp bài 5.3 (pnpm generate:client) có hiệu lực ngay lập tức cho cả admin lẫn web mà không cần publish lại package.

## **4. Cấu hình client & gọi API đầu tiên**

*10 phút · Demo + Lab*

Tạo file cấu hình client riêng, set base URL 1 lần duy nhất khi app khởi động:

```typescript
// apps/admin/src/lib/api-client.ts
import { client } from "@tedu-market/api-client/client.gen";
 
client.setConfig({
  baseUrl: import.meta.env.VITE_API_BASE_URL ?? "http://localhost:5000",
});
```

Vite không dùng process.env như Node — biến môi trường phía client phải bắt đầu bằng tiền tố VITE\_ và đọc qua import.meta.env. Tạo file .env tại apps/admin/:

```
VITE_API_BASE_URL=http://localhost:5000
```

> **📘 Ghi chú giảng viên:** *Cổng thật của TeduMarket.Api lấy từ launchSettings.json bạn cấu hình ở bài 0.2/0.7 — có thể là 5000 (http) hoặc 7000-dạng (https, self-signed cert). Nếu dùng https dev cert, trình duyệt sẽ chặn request đến khi bạn trust cert đó — tôi luôn khuyên học viên dùng profile http khi làm việc với FE ở giai đoạn dev để tránh phải xử lý cert, chuyển sang https khi đến Module 9.*

Gọi thử API GetCategoriesQuery (bài 0.8) — endpoint public, không cần token, phù hợp để verify luồng trước khi có auth:

```tsx
// apps/admin/src/App.tsx
import { useEffect, useState } from "react";
import "./lib/api-client"; // đảm bảo client.setConfig() chạy trước mọi call
 
function App() {
  const [status, setStatus] = useState<"idle" | "loading" | "success" | "error">("idle");
  const [categories, setCategories] = useState<unknown[]>([]);
 
  useEffect(() => {
    setStatus("loading");
    // Tên hàm SDK chính xác phụ thuộc operationId bạn đặt ở bài 4.1
    // (WithName trên Minimal API). Mở packages/api-client/src/sdk.gen.ts
    // để lấy đúng tên — dưới đây giả định getCategories().
    import("@tedu-market/api-client/sdk.gen").then(({ getCategories }) => {
      getCategories()
        .then((res) => {
          setCategories(res.data ?? []);
          setStatus("success");
        })
        .catch(() => setStatus("error"));
    });
  }, []);
 
  return (
    <div>
      <h1>TEDU Market Admin</h1>
      <p>Trạng thái gọi API: {status}</p>
      <ul>
        {categories.map((c: any) => (
          <li key={c.id}>{c.name}</li>
        ))}
      </ul>
    </div>
  );
}
 
export default App;
```

Chạy dev server, mở DevTools tab Network — thấy request GET tới http://localhost:5000/api/v1/categories trả 200 và danh sách category hiển thị ra UI là đạt deliverable của bài.

> **📘 Ghi chú giảng viên:** *Đoạn import("@tedu-market/api-client/sdk.gen") động ở trên chỉ để né việc tôi không biết trước tên hàm chính xác lúc viết bài mẫu này. Trong lớp thật, sau khi generate xong ở Module 5.2, bạn mở thẳng file sdk.gen.ts, copy đúng tên hàm rồi import tĩnh bình thường ở đầu file — không dùng dynamic import cho việc này, chỉ dynamic import khi có lý do thật sự (code-splitting).*

### **Lỗi thường gặp khi mới nối FE monorepo với BE**

| **Triệu chứng** | **Nguyên nhân & cách sửa** |
|---|---|
| Cannot find module '@tedu-market/api-client' | Chưa chạy pnpm install ở root sau khi thêm dependency, hoặc packages/api-client chưa build (thiếu thư mục dist). |
| Network Error / CORS policy blocked | Origin http://localhost:5173 chưa có trong CORS policy đã cấu hình ở bài 3.9 — quay lại thêm origin này vào danh sách allowed origins. |
| ERR_CONNECTION_REFUSED | Backend chưa chạy, hoặc VITE_API_BASE_URL trỏ sai cổng so với launchSettings.json. |
| Sửa code trong packages/api-client nhưng apps/admin không thấy thay đổi | pnpm link là symlink tới source, nhưng nếu api-client build ra dist/ thì phải chạy lại build (hoặc pnpm generate:client ở bài 5.3) rồi khởi động lại Vite dev server — Vite không tự rebuild dependency ngoài watch scope của nó. |

### **Bài tập thực hành**

> **✏️ Thực hành:** Nâng cấp trạng thái loading/error ở trên thành UI rõ ràng thay vì chỉ hiển thị chữ "loading"/"error": khi status === 'loading' hiện dòng chữ "Đang tải danh sách khóa học..."; khi status === 'error' hiện thông báo lỗi kèm 1 nút "Thử lại" gọi lại đúng hàm fetch. Test bằng cách tắt backend (dừng docker compose hoặc dừng dotnet run) rồi bấm Thử lại để chắc chắn trạng thái error hiển thị đúng, sau đó bật lại backend và bấm Thử lại lần nữa để chắc chắn quay về success.

Input có sẵn: component App.tsx ở trên, endpoint GET /api/v1/categories từ bài 0.8.

Expected output: 3 trạng thái UI phân biệt rõ ràng (loading/success/error), nút Thử lại hoạt động đúng trong cả 2 chiều (backend tắt → bật).

Hint: tách logic fetch ra 1 function riêng (không để trong useEffect trực tiếp) để nút Thử lại có thể gọi lại cùng 1 function; nhớ set lại status thành 'loading' mỗi lần gọi lại, không chỉ set khi mount lần đầu.
