# Nội dung chính

## Phần 1 — Ôn lại: GetCourseDetailQuery trả về gì (Lý thuyết · 10 phút)

Ở bài 1.7, bạn đã viết GetCourseDetailQuery bằng Dapper multi-mapping để lấy Course + Lesson + Instructor trong đúng 1 câu SQL, tránh vấn đề N+1 khi phải query rời rạc từng bảng. Bài này không viết lại backend — chỉ tiêu thụ đúng query đó từ Next.js.

Theo quy ước đặt tên ở mục 7 outline (Endpoint route: /api/v1/{số nhiều thực thể}), endpoint tương ứng là:

```
GET /api/v1/courses/{slug}
```

Lưu ý kỹ thuật cần bổ sung: outline Module 1 (bài 1.1–1.4) chưa liệt kê rõ cột Slug trên Course entity, nhưng route SEO-friendly /courses/[slug] ở bài này bắt buộc cần nó. Nếu Course của bạn hiện chỉ có Id (Guid), hãy bổ sung ngay:

- Property Slug (string, not null, unique) trên Course entity — sinh tự động từ CourseName lúc CreateCourseCommand chạy (bài 1.2), có thể cho phép Instructor sửa tay.
- Unique index trên cột Slug trong CourseConfiguration.cs (đã có ở bài 1.4) — thêm builder.HasIndex(x => x.Slug).IsUnique().
- GetCourseDetailQuery đổi tham số đầu vào từ CourseId sang Slug — đây chính là khóa dùng cho URL, không phải Id nội bộ.

> **📘 Ghi chú giảng viên:** *Tôi hay dừng ở đây và hỏi học viên: 'Tại sao không dùng luôn Id (Guid) làm URL cho nhanh?' — để dẫn vào lý do SEO: URL /courses/xay-dung-api-voi-aspnet-core thân thiện với người dùng và công cụ tìm kiếm hơn hẳn /courses/3fa85f64-5717-4562-b3fc-2c963f66afa6. Đây cũng là lý do trang 7.2 (danh sách) phải trả kèm Slug trong response, không chỉ Id.*

Vì Module 4 và Module 5 đã chuẩn hóa OpenAPI schema rồi generate client, bạn không viết fetch() tay — packages/api-client đã có sẵn hàm type-safe tương ứng với operationId bạn đặt tên ở bài 4.1. Trong bài này, giả định operationId là GetCourseBySlug, nên hàm sinh ra là getCourseBySlug.

## Phần 2 — generateMetadata: SEO động theo Course (Lý thuyết + Demo)

Đây là điểm khác biệt lớn nhất so với bài 7.2 (trang danh sách chỉ có metadata tĩnh chung chung). Ở Next.js 15 App Router, mỗi route có thể export một hàm generateMetadata bất đồng bộ, nhận vào params và trả về object Metadata — và quan trọng: kể từ Next.js 15, params là một Promise, phải await trước khi dùng, không còn truy cập trực tiếp như bản 14 trở về trước.

```tsx
// app/courses/[slug]/page.tsx
import type { Metadata } from "next";
 
type Props = {
  params: Promise<{ slug: string }>;
};
 
export async function generateMetadata(
  { params }: Props
): Promise<Metadata> {
  const { slug } = await params; // Next.js 15: params là Promise, bắt buộc await
  // ...
}
```

Next.js tự động memoize (dùng React cache) các lời gọi fetch() có cùng URL/tham số xảy ra trong cùng một request — nghĩa là generateMetadata và component Page bên dưới cùng gọi getCourseBySlug({ slug }) nhưng chỉ tốn đúng 1 round-trip thật sự xuống backend, không phải 2. Điều này chỉ đúng nếu client bạn generate ở Module 5.2 dùng plugin @hey-api/client-fetch (dựa trên fetch() gốc) — nếu đổi sang client-axios thì cơ chế memoize này không áp dụng, phải tự cache bằng React cache() nếu cần.

> **📘 Ghi chú giảng viên:** *Điểm hay bị hiểu nhầm: học viên tưởng gọi API 2 lần (1 lần trong generateMetadata, 1 lần trong Page) là lãng phí, phải tự viết logic cache tay. Không cần — đây chính là lý do outline chọn @hey-api/client-fetch chứ không phải axios ở Module 5.2, tận dụng đúng cơ chế fetch dedupe built-in của Next.js.*

## Phần 3 — Demo + Lab: dựng trang /courses/[slug] hoàn chỉnh (20 phút)

### Bước 1 — Tạo route

Tạo file app/courses/[slug]/page.tsx trong apps/web (cùng cấp với app/courses/page.tsx đã có từ bài 7.2).

### Bước 2 — Gọi Query, xử lý not-found

Import notFound từ next/navigation. Khi getCourseBySlug trả về error (404 từ backend, ví dụ CourseNotFoundException đã map ProblemDetails ở bài 0.9), gọi notFound() — Next.js tự render trang 404 chuẩn, không phải tự viết if/else trả JSX lỗi tay.

### Bước 3 — Code đầy đủ

```tsx
// app/courses/[slug]/page.tsx
import { notFound } from "next/navigation";
import type { Metadata } from "next";
import { getCourseBySlug } from "@tedu-market/api-client";
 
type Props = {
  params: Promise<{ slug: string }>;
};
 
export async function generateMetadata(
  { params }: Props
): Promise<Metadata> {
  const { slug } = await params;
  const { data: course } = await getCourseBySlug({ path: { slug } });
 
  if (!course) {
    return { title: "Không tìm thấy khóa học | TEDU Market" };
  }
 
  return {
    title: `${course.name} | TEDU Market`,
    description: course.shortDescription,
    openGraph: {
      title: course.name,
      description: course.shortDescription,
      images: course.thumbnailUrl ? [course.thumbnailUrl] : [],
    },
  };
}
 
export default async function CourseDetailPage({ params }: Props) {
  const { slug } = await params;
  const { data: course, error } = await getCourseBySlug({ path: { slug } });
 
  if (error || !course) {
    notFound();
  }
 
  return (
    <main>
      <section className="course-hero">
        <h1>{course.name}</h1>
        <p>{course.shortDescription}</p>
        <span>Giảng viên: {course.instructorName}</span>
        <strong>{course.price.toLocaleString("vi-VN")} đ</strong>
      </section>
 
      <section className="course-lessons">
        <h2>Nội dung khóa học ({course.lessons.length} bài học)</h2>
        <ol>
          {course.lessons.map((lesson) => (
            <li key={lesson.id}>{lesson.title}</li>
          ))}
        </ol>
      </section>
    </main>
  );
}
```

# Bài tập thực hành

> **✏️ Thực hành:** Thêm khối 'Khóa học liên quan' vào cuối trang chi tiết — hiển thị tối đa 4 khóa học khác cùng Category, không bao gồm chính khóa học đang xem.

Input: categoryId lấy từ course vừa fetch được ở Bước 3. Expected output: một danh sách tối đa 4 CourseCard cùng Category, sắp xếp theo ngày tạo mới nhất, loại trừ course hiện tại.

Hint: không viết Query mới — dùng lại GetCoursesListQuery đã có từ bài 1.6/7.2, chỉ thêm filter theo categoryId và pageSize. Nhớ gọi getCoursesList (hàm SDK tương ứng) song song với getCourseBySlug bằng Promise.all thay vì await tuần tự, để không làm chậm thêm request.

```csharp
const [{ data: course }, { data: related }] = await Promise.all([
  getCourseBySlug({ path: { slug } }),
  getCoursesList({ query: { categoryId, pageSize: 5 } }),
]);
 
const relatedCourses = related?.items
  .filter((c) => c.slug !== slug)
  .slice(0, 4);
```

Solution đầy đủ: lưu ý categoryId chỉ có được SAU khi đã có course, nên đoạn Promise.all ở trên chỉ đúng nếu bạn tách 2 lần gọi — gọi getCourseBySlug trước để lấy categoryId, sau đó mới gọi getCoursesList. Nếu học viên viết y hệt đoạn trên mà không sửa, đây là lỗi phổ biến cần bạn chỉ ra khi chấm bài.

# Tổng kết

> **✅ Tóm tắt:** Trang chi tiết Course là Server Component async, gọi thẳng GetCourseDetailQuery (1.7) qua packages/api-client (5.2); generateMetadata là hàm async riêng, params là Promise nên phải await; not-found xử lý bằng notFound() của Next.js, không tự viết UI lỗi tay; Next.js tự memoize fetch trùng lặp trong cùng request nhờ client-fetch.
