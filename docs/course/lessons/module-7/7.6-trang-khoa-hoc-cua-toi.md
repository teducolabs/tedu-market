## **Nội dung chính**

### **1. Enrollment đến từ đâu? (Lý thuyết ngắn · 5 phút)**

Trước khi viết trang "Khóa học của tôi", bạn cần chắc chắn nhớ đúng luồng đã xây ở Module 2: khi webhook SePay xác nhận chuyển khoản (bài 2.5), Order chuyển Pending → Paid. Cùng transaction đó, một OrderPaidEvent được ghi vào bảng Outbox (bài 2.6) — không tạo Enrollment trực tiếp ngay lúc này, để tránh Order Paid thành công nhưng Enrollment lại thất bại giữa chừng.

**Sửa lại một điểm trong outline:** bài 2.7 xử lý Outbox bằng BackgroundService thuần của .NET (native, không thêm hạ tầng), không phải "Hangfire job" như bản outline gốc còn ghi — quyết định này đã chốt lại khi làm bài 2.6/2.7. Bài 7.6 dùng đúng theo quyết định mới: dữ liệu Enrollment do BackgroundService đọc Outbox và tạo ra.

Bảng Enrollment (bounded context Enrollment, mục 4 outline) tối thiểu cần các cột: StudentId, CourseId, EnrolledAt. Đây chính là 3 cột bạn sẽ JOIN sang bảng Courses để lấy dữ liệu hiển thị.

> **📘 Ghi chú giảng viên:** *Tôi hay dừng ở đây và cho học viên tự query trực tiếp bảng Enrollments bằng psql trước, xem đúng có dữ liệu sau khi test luồng Checkout ở bài 7.5 chưa. Nếu bảng trống, đừng vội viết Query — quay lại kiểm tra BackgroundService ở bài 2.7 đã chạy đúng chưa, viết Query trên dữ liệu sai chỉ tổ mất thời gian debug ngược.*

### **2. Backend: GetEnrollmentsListQuery (Demo · 10 phút)**

Tính đến giờ bạn đã có GetOrderHistoryQuery (bài 2.8) trả về Order, nhưng chưa có Query nào trả về danh sách khóa học đã sở hữu kèm thông tin hiển thị (tên khóa học, ảnh thumbnail, ngày mua). Bổ sung Query mới, đặt ở TeduMarket.Application, đúng convention Get{Thực thể}ListQuery — Enrollment số nhiều là Enrollments, nên tên Query là GetEnrollmentsListQuery.

```csharp
// TeduMarket.Application/Enrollments/Queries/GetEnrollmentsListQuery.cs
namespace TeduMarket.Application.Enrollments.Queries;
 
public sealed record GetEnrollmentsListQuery(Guid StudentId)
    : IRequest<IReadOnlyList<EnrollmentSummaryDto>>;
 
public sealed record EnrollmentSummaryDto(
    Guid CourseId,
    string CourseTitle,
    string? ThumbnailUrl,
    DateTime EnrolledAt);
 
public sealed class GetEnrollmentsListQueryHandler(IDbConnectionFactory connectionFactory)
    : IRequestHandler<GetEnrollmentsListQuery, IReadOnlyList<EnrollmentSummaryDto>>
{
    public async Task<IReadOnlyList<EnrollmentSummaryDto>> Handle(
        GetEnrollmentsListQuery request, CancellationToken cancellationToken)
    {
        // Query Side dùng Dapper raw SQL — không đụng Entity Command side (Module 0.8)
        const string sql = """
            SELECT c."Id"            AS "CourseId",
                   c."Title"          AS "CourseTitle",
                   c."ThumbnailUrl"   AS "ThumbnailUrl",
                   e."EnrolledAt"     AS "EnrolledAt"
            FROM "Enrollments" e
            INNER JOIN "Courses" c ON c."Id" = e."CourseId"
            WHERE e."StudentId" = @StudentId
            ORDER BY e."EnrolledAt" DESC;
            """;
 
        await using var connection = connectionFactory.CreateConnection();
        var rows = await connection.QueryAsync<EnrollmentSummaryDto>(
            sql, new { request.StudentId });
 
        return rows.ToList();
    }
}
```

Endpoint đăng ký theo đúng quy ước /api/v1/{số nhiều thực thể} — /api/v1/enrollments. StudentId không truyền từ client mà lấy thẳng từ claim NameIdentifier ("sub") có sẵn trong Access Token do OpenIddict phát ra (bài 3.2) — học viên không thể xem enrollment của người khác dù có cố truyền id khác lên URL, vì server tự lấy id từ token.

```csharp
// TeduMarket.Api/Endpoints/EnrollmentEndpoints.cs
namespace TeduMarket.Api.Endpoints;
 
public static class EnrollmentEndpoints
{
    public static IEndpointRouteBuilder MapEnrollmentEndpoints(this IEndpointRouteBuilder app)
    {
        var group = app.MapGroup("/api/v1/enrollments")
            .WithTags("Enrollments")
            .RequireAuthorization();
 
        group.MapGet("/", async (ISender sender, ClaimsPrincipal user, CancellationToken ct) =>
        {
            var studentId = Guid.Parse(user.FindFirstValue(ClaimTypes.NameIdentifier)!);
            var result = await sender.Send(new GetEnrollmentsListQuery(studentId), ct);
            return Results.Ok(result);
        })
        .WithName("GetEnrollments") // tên này quyết định tên hàm SDK sinh ra ở bài 5.2
        .Produces<IReadOnlyList<EnrollmentSummaryDto>>(StatusCodes.Status200OK);
 
        return app;
    }
}
```

Test nhanh qua /scalar (bài 4.2): đăng nhập lấy Access Token, gọi GET /api/v1/enrollments, xác nhận trả về đúng danh sách khóa học đã mua ở bài 7.5. Chạy được ở Scalar rồi mới sang phần frontend — tránh vừa debug API vừa debug Next.js cùng lúc.

### **4. Next.js: bảo vệ route Server Component (Demo + Lab · 8 phút)**

Bài 7.4 đã lưu session học viên an toàn phía server sau khi đăng nhập OIDC. Ở đây bạn đọc lại session đó bằng cookies() từ next/headers — lưu ý từ Next.js 15, cookies() là hàm bất đồng bộ, bắt buộc await, khác với bản trước đó.

```typescript
// apps/web/lib/session.ts
import { cookies } from "next/headers";
 
export type ServerSession = {
  accessToken: string;
  userId: string;
};
 
// Đổi đúng tên cookie/shape session bạn đã lưu ở bài 7.4
const SESSION_COOKIE = "tedu_session";
 
export async function getServerSession(): Promise<ServerSession | null> {
  const cookieStore = await cookies(); // cookies() bất đồng bộ từ Next.js 15
  const raw = cookieStore.get(SESSION_COOKIE)?.value;
 
  if (!raw) {
    return null;
  }
 
  return JSON.parse(raw) as ServerSession;
}
```

Trang /my-courses gọi getServerSession() ngay đầu Server Component. Chưa đăng nhập → redirect() từ next/navigation, hàm này chạy được trong Server Component (khác useRouter() chỉ dùng trong Client Component ở bài 6.2).

```tsx
// apps/web/app/my-courses/page.tsx
import { redirect } from "next/navigation";
import { getServerSession } from "@/lib/session";
import { getEnrollments } from "@tedu-market/api-client";
import { EnrollmentCard } from "./_components/enrollment-card";
import { EmptyState } from "./_components/empty-state";
 
export default async function MyCoursesPage() {
  const session = await getServerSession();
 
  if (!session) {
    redirect("/login?next=/my-courses");
  }
 
  const { data: enrollments } = await getEnrollments({
    headers: { Authorization: `Bearer ${session.accessToken}` },
  });
 
  return (
    <main className="mx-auto max-w-5xl px-4 py-10">
      <h1 className="mb-6 text-2xl font-semibold">Khóa học của tôi</h1>
 
      {enrollments.length === 0 ? (
        <EmptyState />
      ) : (
        <div className="grid grid-cols-1 gap-6 sm:grid-cols-2 lg:grid-cols-3">
          {enrollments.map((enrollment) => (
            <EnrollmentCard key={enrollment.courseId} enrollment={enrollment} />
          ))}
        </div>
      )}
    </main>
  );
}
```

> **📘 Ghi chú giảng viên:** *Điểm hay bị hỏi: "Sao không dùng middleware.ts để chặn /my-courses luôn cho gọn?" — được, nhưng middleware chạy ở Edge Runtime, không đọc được cookies() từ next/headers theo cách Server Component đọc (bài 7.4 dùng session lưu ở server, không phải JWT tự verify ở Edge). Với khóa này, check trong chính Server Component là đủ và đơn giản hơn — nói rõ đây là lựa chọn có chủ đích, không phải bạn quên biết middleware tồn tại.*

### **5. UI danh sách khóa học đã mua (Demo · 5 phút)**

EnrollmentCard chỉ là component hiển thị thuần — ảnh thumbnail, tên khóa học, ngày mua, link sang trang chi tiết khóa học đã xây ở bài 7.3.

```tsx
// apps/web/app/my-courses/_components/enrollment-card.tsx
import Link from "next/link";
import Image from "next/image";
 
type Props = {
  enrollment: {
    courseId: string;
    courseTitle: string;
    thumbnailUrl: string | null;
    enrolledAt: string;
  };
};
 
export function EnrollmentCard({ enrollment }: Props) {
  return (
    <Link
      href={`/courses/${enrollment.courseId}`}
      className="block rounded-lg border p-4 transition hover:shadow-md"
    >
      {enrollment.thumbnailUrl && (
        <Image
          src={enrollment.thumbnailUrl}
          alt={enrollment.courseTitle}
          width={320}
          height={180}
          className="mb-3 rounded"
        />
      )}
      <h3 className="font-medium">{enrollment.courseTitle}</h3>
      <p className="text-sm text-gray-500">
        Đã mua ngày {new Date(enrollment.enrolledAt).toLocaleDateString("vi-VN")}
      </p>
    </Link>
  );
}
```

> **📘 Ghi chú giảng viên:** *Route /courses/[slug] ở bài 7.3 dùng slug, không phải courseId trong URL — nếu bạn làm đúng theo 7.3, sửa link ở đây thành slug (cần trả thêm field Slug từ GetEnrollmentsListQuery) thay vì courseId thô như ví dụ minh họa. Tôi để courseId ở đây cho đơn giản, nhắc học viên tự đối chiếu lại field thật của bài 7.3.*

## **Bài tập / Thực hành**

> **✏️ Thực hành:** Xử lý đúng 2 trạng thái của trang /my-courses: (1) học viên chưa mua khóa học nào — hiển thị EmptyState kèm nút "Khám phá khóa học" trỏ về /courses; (2) học viên đã mua — danh sách hiển thị đúng thứ tự mua gần nhất lên đầu (đã có ORDER BY EnrolledAt DESC ở Query, chỉ cần xác nhận UI không tự sort lại).

Input: 1 tài khoản Student chưa từng checkout, 1 tài khoản đã checkout thành công ít nhất 2 khóa học ở thời điểm khác nhau (test lại luồng bài 7.5).

Expected output: tài khoản thứ nhất thấy EmptyState; tài khoản thứ hai thấy đúng 2 card, khóa học mua sau hiển thị trước.

Hint: nếu enrollments trả về rỗng nhưng bạn chắc chắn đã Checkout thành công ở bài 7.5, kiểm tra theo thứ tự: Order có ở trạng thái Paid không (Scalar) → Outbox có message đã Processed chưa (bài 2.6) → BackgroundService (bài 2.7) có đang chạy không, đọc log Serilog nếu bạn đã làm sớm phần logging ở bài 9.7.

Solution (rút gọn phần EmptyState):

```tsx
// apps/web/app/my-courses/_components/empty-state.tsx
import Link from "next/link";
 
export function EmptyState() {
  return (
    <div className="rounded-lg border border-dashed p-10 text-center">
      <p className="mb-4 text-gray-600">Bạn chưa có khóa học nào.</p>
      <Link
        href="/courses"
        className="rounded bg-blue-600 px-4 py-2 text-white hover:bg-blue-700"
      >
        Khám phá khóa học
      </Link>
    </div>
  );
}
```

## **Tổng kết**

> **✅ Tóm tắt:** Enrollment không tạo trực tiếp lúc thanh toán — nó đến từ Outbox (2.6) do BackgroundService (2.7) xử lý bất đồng bộ; sửa đúng lại theo quyết định kiến trúc mới nhất, không phải Hangfire như outline gốc.

- GetEnrollmentsListQuery là Query mới, tuân đúng convention Get{Thực thể}ListQuery, dùng Dapper raw SQL join Enrollment + Course — nối tiếp pattern Query Side đã lặp lại từ bài 0.8, 1.6, 1.7, 2.8.
- Endpoint GET /api/v1/enrollments lấy StudentId từ claim trong Access Token, không tin dữ liệu client truyền lên — đây là điểm bảo mật quan trọng sẽ được nhấn mạnh lại kỹ hơn ở bài 7.7.
- Server Component tự kiểm tra session (cookies() bất đồng bộ từ Next.js 15) và redirect() khi chưa đăng nhập — khác cách check ở Client Component (bài 6.2) dùng OIDC context.
- Trang /my-courses xử lý đủ 2 trạng thái: có dữ liệu và rỗng — chi tiết nhỏ nhưng ảnh hưởng trực tiếp trải nghiệm học viên mới mua khóa học đầu tiên.

**Bước tiếp theo:** Bài 7.7 — Xem bài học (Lesson Player). Trang /my-courses hôm nay chỉ mới liệt kê khóa học đã mua; bài sau sẽ kiểm tra quyền truy cập qua Enrollment ngay ở tầng API trước khi trả nội dung Lesson — tránh lỗi bảo mật kinh điển: chỉ ẩn nút bấm trên UI mà quên chặn endpoint, khiến học viên chưa mua vẫn gọi thẳng API để lấy nội dung bài học.
