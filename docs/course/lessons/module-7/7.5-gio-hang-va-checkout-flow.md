## **Phần 1 — Ôn kiến trúc & lý do cần Route Handler proxy**

*Lý thuyết · 10 phút*

Bài 2.1 đã tách 2 aggregate: Cart — mutable, gắn với User, sống trong lúc mua hàng; và Order — immutable, sinh ra ngay khi Checkout thành công. Bài 2.2 đã có AddToCartCommand và CheckoutCommand chạy được qua Postman, gọi thẳng /api/v1/carts và /api/v1/orders/checkout. Bài này không viết lại logic nghiệp vụ — chỉ nối 2 command đó vào giao diện thật.

Nhắc lại điểm mấu chốt từ bài 7.4: access token của Student được lưu trong cookie httpOnly phía server, đọc bằng hàm getSession() đã viết ở 7.4 — chạy được trong Server Component, Route Handler và Server Action. Cookie httpOnly nghĩa là JavaScript chạy trong trình duyệt, kể cả Client Component, không đọc được giá trị này. Đây là chủ đích thiết kế, không phải giới hạn cần né tránh.

Vấn đề: trang giỏ hàng cần tương tác tức thì — thêm/xóa không reload trang — đúng kiểu Client Component. Nhưng Client Component chạy trong trình duyệt, không có access token để tự gắn header Authorization khi gọi thẳng /api/v1/carts, trong khi endpoint này đang được OpenIddict bảo vệ (Module 3).

Giải pháp: dựng một Route Handler cùng origin, đóng vai trò lớp Backend-for-Frontend (BFF) rất mỏng. Client Component gọi vào Route Handler này bằng fetch same-origin (cookie httpOnly tự động đính kèm theo request của trình duyệt, JavaScript vẫn không đọc được giá trị bên trong). Route Handler đọc session ở phía server, gọi backend thật kèm Bearer token, rồi trả JSON thuần về cho Client Component. Access token không bao giờ chạm tới mã JavaScript chạy trong trình duyệt.

> **📘 Ghi chú giảng viên:** *Tôi hay dừng ở đây và hỏi học viên: “Vậy React Admin ở Module 6.2 sao không làm kiểu này?”. Vì React Admin là SPA thuần, không có server riêng để giấu token, nên chấp nhận giữ token trong bộ nhớ trình duyệt (không phải localStorage) và bù lại bằng Authorization Code + PKCE đúng chuẩn (Module 3.3). Next.js có server, nên tận dụng luôn — không có lý do gì để token chạm trình duyệt ở đây.*

## **Phần 2 — Route Handler quản lý giỏ hàng**

*Demo + Lab · 15 phút*

Tạo 2 route trong apps/web:

- app/api/cart/route.ts — GET (lấy giỏ hàng hiện tại), POST (thêm khóa học vào giỏ).
- app/api/cart/[courseId]/route.ts — DELETE (xóa 1 dòng khỏi giỏ).

### **app/api/cart/route.ts**

```csharp
import { NextResponse } from 'next/server';
import { getSession } from '@/lib/auth/session'; // đã viết ở bài 7.4
import { getCart, addCartItem } from '@tedu-market/api-client';
 
export async function GET() {
  const session = await getSession();
  if (!session) {
    return NextResponse.json({ title: 'Unauthorized' }, { status: 401 });
  }
 
  const { data, error, response } = await getCart({
    headers: { Authorization: `Bearer ${session.accessToken}` },
  });
 
  if (error) {
    // forward nguyên trạng ProblemDetails đã chuẩn hóa ở bài 4.5
    return NextResponse.json(error, { status: response.status });
  }
 
  return NextResponse.json(data);
}
 
export async function POST(request: Request) {
  const session = await getSession();
  if (!session) {
    return NextResponse.json({ title: 'Unauthorized' }, { status: 401 });
  }
 
  const body = await request.json(); // { courseId: string }
 
  const { data, error, response } = await addCartItem({
    headers: { Authorization: `Bearer ${session.accessToken}` },
    body,
  });
 
  if (error) {
    return NextResponse.json(error, { status: response.status });
  }
 
  return NextResponse.json(data, { status: 201 });
}
```

### **app/api/cart/[courseId]/route.ts**

```csharp
import { NextResponse } from 'next/server';
import { getSession } from '@/lib/auth/session';
import { removeCartItem } from '@tedu-market/api-client';
 
export async function DELETE(
  _request: Request,
  { params }: { params: Promise<{ courseId: string }> } // params là Promise ở Next.js 15
) {
  const session = await getSession();
  if (!session) {
    return NextResponse.json({ title: 'Unauthorized' }, { status: 401 });
  }
 
  const { courseId } = await params;
 
  const { error, response } = await removeCartItem({
    headers: { Authorization: `Bearer ${session.accessToken}` },
    path: { courseId },
  });
 
  if (error) {
    return NextResponse.json(error, { status: response.status });
  }
 
  return new NextResponse(null, { status: 204 });
}
```

> **📘 Ghi chú giảng viên:** *Từ Next.js 15, params trong Route Handler và Page là một Promise — phải await params thay vì đọc trực tiếp như Next.js 14. Điểm này học viên đã gặp ở bài 7.3 (trang chi tiết khóa học), giờ lặp lại lần 2 để thành phản xạ. Một điểm khác cũng đổi cùng đợt: GET Route Handler ở Next.js 15 không còn tự động cache như Next.js 14 nữa, nên không cần thêm export const dynamic = 'force-dynamic' như trước.*

## **Phần 3 — Client Component giỏ hàng tương tác**

*Demo + Lab · 15 phút*

Client Component gọi vào Route Handler nội bộ ở Phần 2 bằng fetch('/api/cart') như một API bình thường của chính Next.js — KHÔNG gọi trực tiếp hàm generated trong packages/api-client ở bước này, vì Route Handler đã đóng vai trò gateway rồi. Dùng @tanstack/react-query để quản lý cache và trạng thái loading/error, đúng pattern đã học ở Module 6.3/6.6 cho React Admin.

### **app/cart/cart-client.tsx**

```csharp
'use client';
 
import { useQuery, useMutation, useQueryClient } from '@tanstack/react-query';
import { useTransition } from 'react';
import { checkoutAction } from '@/app/checkout/actions';
 
type CartItem = { courseId: string; title: string; price: number };
type Cart = { items: CartItem[]; total: number };
 
async function fetchCart(): Promise<Cart> {
  const res = await fetch('/api/cart');
  if (!res.ok) throw new Error('Không tải được giỏ hàng');
  return res.json();
}
 
export function CartClient() {
  const queryClient = useQueryClient();
  const [isPending, startTransition] = useTransition();
 
  const { data: cart, isLoading } = useQuery({
    queryKey: ['cart'],
    queryFn: fetchCart,
  });
 
  const removeItem = useMutation({
    mutationFn: (courseId: string) =>
      fetch(`/api/cart/${courseId}`, { method: 'DELETE' }),
    onSuccess: () => queryClient.invalidateQueries({ queryKey: ['cart'] }),
  });
 
  function handleCheckout() {
    if (!cart || cart.items.length === 0) return;
    startTransition(() => {
      checkoutAction();
    });
  }
 
  if (isLoading) return <p>Đang tải giỏ hàng...</p>;
 
  return (
    <div>
      {cart!.items.map((item) => (
        <div key={item.courseId}>
          <span>{item.title}</span>
          <button onClick={() => removeItem.mutate(item.courseId)}>Xóa</button>
        </div>
      ))}
      <p>Tổng tiền: {cart!.total.toLocaleString('vi-VN')} đ</p>
      <button onClick={handleCheckout} disabled={isPending}>
        {isPending ? 'Đang xử lý...' : 'Tiến hành thanh toán'}
      </button>
    </div>
  );
}
```

> **📘 Ghi chú giảng viên:** *checkoutAction là Server Action (Phần 4), được gọi qua onClick + startTransition thay vì \<form action={checkoutAction}>. Lý do: nút này cần validate giỏ hàng rỗng trước khi gọi, còn form action thuần chỉ phù hợp khi submit luôn không cần điều kiện chặn trước.*

## **Phần 4 — Server Action Checkout kèm Idempotency-Key**

*Demo + Lab · 10 phút*

Server Action chạy trên server nên có thể gọi trực tiếp hàm generated trong packages/api-client (khác với Client Component ở Phần 3, phải đi vòng qua Route Handler). checkoutAction sinh idempotencyKey mới cho mỗi lần bấm nút, gắn vào header Idempotency-Key đúng theo cơ chế đã xây ở bài 2.9 — chống việc tạo 2 Order nếu khách double-click hoặc mất mạng rồi thử lại.

### **app/checkout/actions.ts**

```csharp
'use server';
 
import { redirect } from 'next/navigation';
import { getSession } from '@/lib/auth/session';
import { checkout, initiatePayment } from '@tedu-market/api-client';
 
export async function checkoutAction() {
  const session = await getSession();
  if (!session) {
    redirect('/login');
  }
 
  const idempotencyKey = crypto.randomUUID(); // chống double-submit, bài 2.9
 
  const { data: order, error } = await checkout({
    headers: {
      Authorization: `Bearer ${session.accessToken}`,
      'Idempotency-Key': idempotencyKey,
    },
  });
 
  if (error) {
    throw new Error('Checkout thất bại: ' + error.title);
  }
 
  await initiatePayment({
    headers: { Authorization: `Bearer ${session.accessToken}` },
    path: { orderId: order.id },
  });
 
  redirect(`/orders/${order.id}/payment`);
}
```

> **📘 Ghi chú giảng viên:** *Lỗi hay gặp: học viên bọc toàn bộ Server Action trong một try/catch rồi tưởng redirect() bị lỗi. redirect() hoạt động bằng cách throw một lỗi đặc biệt (NEXT_REDIRECT) để Next.js chặn lại và điều hướng — không phải lỗi thật. Nếu cần bắt lỗi gọi API, chỉ bọc phần gọi checkout/initiatePayment, không bọc luôn dòng redirect() phía dưới.*

## **Phần 5 — Trang thanh toán: mã QR VietQR & polling trạng thái**

*Demo · 10 phút*

Trang /orders/[orderId]/payment là Server Component, fetch chi tiết thanh toán (mã QR, số tiền, trạng thái ban đầu) ngay lúc SSR — hiển thị nhanh, không cần chờ JavaScript tải xong. Phần cần cập nhật liên tục (trạng thái Pending → Paid) tách riêng thành một Client Component nhỏ, poll qua Route Handler mới.

### **app/orders/[orderId]/payment/page.tsx**

```csharp
import { getSession } from '@/lib/auth/session';
import { getOrderPaymentStatus } from '@tedu-market/api-client';
import { PaymentStatusPoller } from './payment-status-poller';
 
export default async function OrderPaymentPage({
  params,
}: {
  params: Promise<{ orderId: string }>;
}) {
  const { orderId } = await params;
  const session = await getSession();
 
  const { data: payment } = await getOrderPaymentStatus({
    headers: { Authorization: `Bearer ${session!.accessToken}` },
    path: { orderId },
  });
 
  const qrUrl =
    `https://img.vietqr.io/image/${payment.bankCode}-${payment.accountNumber}` +
    `-compact2.png?amount=${payment.amount}&addInfo=${payment.paymentCode}`;
 
  return (
    <div>
      <h1>Quét mã để thanh toán</h1>
      <img src={qrUrl} alt="Mã QR VietQR" />
      <p>Nội dung chuyển khoản: {payment.paymentCode}</p>
      <PaymentStatusPoller orderId={orderId} initialStatus={payment.status} />
    </div>
  );
}
```

### **app/orders/[orderId]/payment/payment-status-poller.tsx**

```csharp
'use client';
 
import { useEffect, useState } from 'react';
import { useRouter } from 'next/navigation';
 
export function PaymentStatusPoller({
  orderId,
  initialStatus,
}: {
  orderId: string;
  initialStatus: string;
}) {
  const [status, setStatus] = useState(initialStatus);
  const router = useRouter();
 
  useEffect(() => {
    if (status === 'Paid') {
      router.push('/my-courses'); // bài 7.6
      return;
    }
 
    const timer = setInterval(async () => {
      const res = await fetch(`/api/orders/${orderId}/payment-status`);
      const data = await res.json();
      setStatus(data.status);
    }, 3000);
 
    return () => clearInterval(timer); // dọn interval khi unmount
  }, [status, orderId, router]);
 
  return (
    <p>Trạng thái: {status === 'Pending' ? 'Đang chờ chuyển khoản...' : status}</p>
  );
}
```

Route Handler app/api/orders/[orderId]/payment-status/route.ts viết theo đúng pattern Phần 2 — đọc session, gọi getOrderPaymentStatus kèm Bearer token, trả JSON. Không lặp lại code ở đây vì học viên tự làm được từ những gì đã học.

> **📘 Ghi chú giảng viên:** *Nhắc học viên dọn interval trong cleanup function của useEffect — quên bước này là lỗi kinh điển, gây leak nhiều interval chạy song song mỗi lần component re-render. Khi status chuyển Paid, Enrollment thật ra đã được tạo từ trước đó vài giây bởi Hosted Service đọc Outbox (bài 2.7) — trang này chỉ đang chờ tin, không phải nơi tạo Enrollment.*

### **So sánh nơi lưu token & cách gọi API**

|  | **React Admin — SPA (6.2)** | **Next.js Student (7.4 / 7.5)** |
|---|---|---|
| Nơi lưu access token | Bộ nhớ trình duyệt (qua react-oidc-context), không dùng localStorage | Cookie httpOnly, chỉ đọc được ở server |
| Client Component gọi API có auth | Gọi thẳng backend, tự đính Bearer token | Không gọi thẳng — luôn qua Route Handler cùng origin |
| Rủi ro chính cần phòng | XSS đọc token trong bộ nhớ JS | CSRF — chắn bằng SameSite cookie + kiểm tra origin |

Bước tiếp theo: Bài 7.6 — Trang “Khóa học của tôi”, hiển thị dữ liệu Enrollment vừa được tạo tự động ở bước Hosted Service (bài 2.7).
