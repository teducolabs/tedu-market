## **Phần 1 — Server Component và Client Component khác nhau ở đâu**

*Lý thuyết · 10 phút*

Ở Module 6, apps/admin là ứng dụng React thuần (Vite) — toàn bộ component đều chạy trong trình duyệt (Client-Side Rendering). Với Next.js App Router, mặc định mọi component trong thư mục app/ là Server Component — một khái niệm không tồn tại ở Module 6, nên đây là điểm khác biệt đầu tiên bạn cần nắm chắc trước khi viết dòng code nào.

Server Component chạy trên server (Node.js) lúc Next.js render trang, có thể là một async function và await trực tiếp lệnh gọi API hoặc truy vấn DB — không cần useEffect, không cần useState để chờ dữ liệu. Code bên trong Server Component (bao gồm cả logic gọi API) không bao giờ được đóng gói xuống JavaScript bundle gửi cho trình duyệt.

Client Component là component có dòng đầu tiên 'use client' — nó vẫn được render lần đầu ở server (để trả về HTML nhanh), nhưng sau đó được "hydrate" và tiếp tục chạy lại trong trình duyệt để xử lý tương tác (onClick, useState, useEffect). Client Component không được viết async trực tiếp trong phần thân component — muốn gọi API phải dùng useEffect thủ công hoặc một thư viện như TanStack Query.

| **Tiêu chí** | **Server Component** | **Client Component** |
|---|---|---|
| Nơi chạy logic gọi API | Trên server (Node.js), lúc render | Trong trình duyệt, sau khi hydrate |
| Cú pháp component | async function, await trực tiếp | Không async; dùng hook (useQuery, useEffect) |
| Thấy trong Network tab (F12)? | Không — request không xuất phát từ browser | Có — request thật từ browser |
| Dùng khi nào trong TEDU Market | Trang listing/detail Course (7.2, 7.3) — cần SEO | Giỏ hàng, form checkout (7.5) — cần state, tương tác |

> **📘 Ghi chú giảng viên:** *Tôi hay dừng ở bảng so sánh này và hỏi học viên: "Nếu bạn mở DevTools > Network và F5 lại trang /courses, có thấy request gọi /api/v1/courses không?" — với Server Component thì KHÔNG, vì browser chỉ nhận HTML đã render sẵn. Đây là chỗ học viên hay bối rối nhất vì quen tư duy SPA từ Module 6, nghĩ mọi API call đều phải thấy được ở Network tab.*

## **Phần 2 — Khởi tạo apps/web trong monorepo**

*Demo · 10 phút*

Toàn bộ thao tác dưới đây chạy tại thư mục gốc tedu-market-frontend (ngang hàng với apps/admin, packages/api-client đã có từ Module 5–6) — đúng cách Turborepo khuyến nghị thêm một ứng dụng mới vào monorepo có sẵn.

### **2.1. Chạy create-next-app ngay trong thư mục apps/**

```bash
# Tại thư mục gốc tedu-market-frontend/
pnpm dlx create-next-app@latest apps/web
```

Trả lời các câu hỏi khởi tạo:

- TypeScript: Yes
- ESLint: Yes
- Tailwind CSS: tuỳ chọn của bạn — outline không bắt buộc, bài này không phụ thuộc Tailwind
- src/ directory: Yes (để cấu trúc app/ nằm trong src/app/, đồng nhất với thói quen tách rõ code khỏi file cấu hình root)
- App Router: Yes (mặc định của Next.js 15, không có lựa chọn Pages Router nữa)
- Import alias: giữ mặc định @/\*

Sau khi tạo xong, mở apps/web/package.json và đổi "name" thành "web" nếu create-next-app đặt tên khác — package.json name phải khớp với cách turbo.json và các script --filter tham chiếu đến app này (turbo dùng đúng field name trong package.json, không dùng tên thư mục).

### **2.2. Cài lại dependency ở root để Turborepo nhận app mới**

```bash
# Tại thư mục gốc tedu-market-frontend/
pnpm install
```

pnpm-workspace.yaml (Module 5.1) đã khai báo apps/\* nên apps/web tự động được nhận vào workspace — không cần sửa gì thêm ở pnpm-workspace.yaml hay turbo.json, app mới thừa hưởng pipeline build/dev/lint đã cấu hình sẵn.

## **Phần 3 — Gắn packages/api-client vào apps/web**

*Demo · 5 phút*

### **3.1. Khai báo workspace dependency**

Thêm vào apps/web/package.json:

```json
// apps/web/package.json
{
  "name": "web",
  "dependencies": {
    "@tedu-market/api-client": "workspace:*",
    "@tanstack/react-query": "^5.x"
  }
}
```

```bash
pnpm install
```

@tedu-market/api-client là tên package packages/api-client đã export ở Module 5.2. Nếu ở Module 5.1 bạn đặt tên scope khác cho monorepo, dùng đúng tên đó — chỉ cần nhất quán.

### **3.2. Xác nhận baseUrl chạy đúng cho cả Server lẫn Client Component**

Ở Module 5.2, packages/api-client được generate bằng @hey-api/openapi-ts với client mặc định @hey-api/client-fetch. Điểm cần xác nhận lại trước khi gọi API lần đầu trong apps/web: baseUrl của client KHÔNG được set bằng cách gọi setConfig() rải rác trong app/layout.tsx — vì Next.js App Router không đảm bảo thứ tự render layout cha trước con, một Server Component con có thể gọi API trước khi layout cha kịp set baseUrl.

Cách đúng — dùng runtimeConfigPath đã cấu hình sẵn từ lúc generate (Module 5.2), packages/api-client có sẵn 1 file cấu hình kiểu:

```typescript
// packages/api-client/src/hey-api.ts
import type { CreateClientConfig } from './client/client.gen';
 
export const createClientConfig: CreateClientConfig = (config) => ({
  ...config,
  baseUrl: process.env.NEXT_PUBLIC_API_URL ?? 'http://localhost:5000',
});
```

client.gen.ts tự gọi createClientConfig() trước khi khởi tạo client — đảm bảo baseUrl luôn sẵn sàng dù request gọi ra từ Server Component hay Client Component, không phụ thuộc thứ tự render.

```bash
# apps/web/.env.local
NEXT_PUBLIC_API_URL=http://localhost:5000
```

> **📘 Ghi chú giảng viên:** *Nếu học viên thấy lỗi "Invalid URL" hoặc request bay thẳng đến http://localhost:3000/api/v1/courses (tức là gọi nhầm vào chính Next.js server) — 99% do baseUrl chưa được set trước khi client được import lần đầu. Đừng để học viên tự chế cách gọi setConfig() trong layout.tsx, dẫn ngay về runtimeConfigPath.*

## **Phần 4 — Lab: gọi API từ Server Component**

*Lab · 10 phút*

Tạo trang app/courses/page.tsx (Server Component mặc định — không có 'use client' ở đầu file):

```tsx
// apps/web/src/app/courses/page.tsx
import { getCourses } from '@tedu-market/api-client';
 
export default async function CoursesPage() {
  const { data: courses } = await getCourses();
 
  return (
    <main>
      <h1>Danh sách khóa học</h1>
      <ul>
        {courses?.items?.map((course) => (
          <li key={course.id}>{course.title}</li>
        ))}
      </ul>
    </main>
  );
}
```

getCourses tương ứng endpoint GET /api/v1/courses (GetCoursesQuery, Module 1.6) — tên hàm SDK do openapi-ts sinh ra dựa trên operationId đã gán ở Module 4.1 bằng .WithName("GetCourses"). Nếu bạn đặt WithName khác, mở packages/api-client/src/client/sdk.gen.ts để lấy đúng tên hàm.

Chạy thử:

```bash
# Tại thư mục gốc tedu-market-frontend/
pnpm dev --filter=web
```

Mở http://localhost:3000/courses. Mở DevTools > Network, lọc theo Fetch/XHR, F5 lại trang — bạn sẽ không thấy request nào gọi /api/v1/courses. Request thật sự xảy ra ở terminal chạy pnpm dev (log của Next.js server), vì đây là Server Component.

> **✏️ Thực hành:** Tự thêm 1 route apps/web/src/app/instructors/page.tsx (Server Component), gọi 1 hàm SDK khác từ @tedu-market/api-client tương ứng nghiệp vụ Instructor (Module 1.9), hiển thị số lượng bản ghi trả về (courses.length hoặc instructors.length). Input: backend đang chạy sẵn với dữ liệu seed từ Module 1.5. Expected output: trang /instructors chạy được, in ra đúng số bản ghi hiện có trong Postgres — không phải số cố định hard-code. Hint nếu bị kẹt: nếu trang trắng và console báo lỗi 'use client' hook trong async component, kiểm tra lại file có lỡ dán nhầm 'use client' ở dòng đầu không — Server Component không được có dòng này.

## **Phần 5 — Đối chiếu: cùng dữ liệu đó nhưng gọi từ Client Component**

*Demo (mở rộng để so sánh) · 5 phút*

Phần này chỉ để bạn tận mắt thấy sự khác biệt qua Network tab — chưa cần hoàn thiện, vì Client Component có state thật sự (giỏ hàng, checkout) sẽ học kỹ ở Bài 7.5. Trước tiên cần 1 QueryClientProvider bọc toàn app, theo đúng pattern chính thức của TanStack Query cho App Router:

```tsx
// apps/web/src/app/providers.tsx
'use client';
 
import { isServer, QueryClient, QueryClientProvider } from '@tanstack/react-query';
 
function makeQueryClient() {
  return new QueryClient({
    defaultOptions: { queries: { staleTime: 60 * 1000 } },
  });
}
 
let browserQueryClient: QueryClient | undefined;
 
function getQueryClient() {
  if (isServer) return makeQueryClient();
  if (!browserQueryClient) browserQueryClient = makeQueryClient();
  return browserQueryClient;
}
 
export default function Providers({ children }: { children: React.ReactNode }) {
  const queryClient = getQueryClient();
  return <QueryClientProvider client={queryClient}>{children}</QueryClientProvider>;
}
```

Bọc trong app/layout.tsx:

```tsx
// apps/web/src/app/layout.tsx
import Providers from './providers';
 
export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="vi">
      <body>
        <Providers>{children}</Providers>
      </body>
    </html>
  );
}
```

Sau đó viết 1 Client Component gọi cùng endpoint /api/v1/courses, nhưng lần này qua hook do plugin @tanstack/react-query của openapi-ts sinh ra (đã bật ở Module 5.2):

```tsx
// apps/web/src/app/courses/CourseListClient.tsx
'use client';
 
import { useGetCoursesQuery } from '@tedu-market/api-client';
 
export default function CourseListClient() {
  const { data, isLoading } = useGetCoursesQuery();
 
  if (isLoading) return <p>Đang tải...</p>;
 
  return (
    <ul>
      {data?.items?.map((c) => (
        <li key={c.id}>{c.title}</li>
      ))}
    </ul>
  );
}
```

Đặt tạm \<CourseListClient /> vào cuối trang /courses để so sánh. Lần này mở DevTools > Network, F5 lại — bạn sẽ thấy request GET /api/v1/courses xuất hiện thật sự trong tab Network, phát ra từ trình duyệt sau khi trang đã hydrate. Đây chính là bằng chứng trực quan cho bảng so sánh ở Phần 1.

> **📘 Ghi chú giảng viên:** *Sau demo này tôi thường gỡ luôn \<CourseListClient /> khỏi trang — nó chỉ tồn tại để học viên nhìn thấy sự khác biệt trong Network tab. Bài 7.2 sẽ xây lại trang /courses hoàn chỉnh (ISR + SEO metadata) dựa trên bản Server Component đã làm ở Phần 4, không dựa trên bản Client Component demo này.*
