## 1. Vì sao Handler CQRS dễ test hơn Controller truyền thống

*Lý thuyết · ~15 phút*

Từ Module 0, mọi logic nghiệp vụ của TEDU Market đều đi qua một Command hoặc Query Handler thay vì nằm trong Controller. Bài này giới thiệu sớm kỹ thuật Unit Test cho tầng Application — sớm hơn hẳn cách dạy truyền thống thường dồn hết phần testing vào cuối khóa. Lý do: càng luyện pattern này sớm, học viên càng viết Handler theo hướng "dễ test" ngay từ đầu, thay vì phải sửa lại kiến trúc khi đã đi được nửa khóa.

### 1.1. Testing pyramid và vị trí của bài này

Có 3 tầng kiểm thử chính trong TEDU Market, đi từ nhanh/nhiều đến chậm/ít:

- Unit Test (bài này, Module 1.10 và mở rộng ở Module 8.1–8.2): test 1 Handler hoặc 1 đoạn logic Domain, mock toàn bộ dependency ngoài (Repository). Chạy trong mili-giây, không cần Postgres.
- Integration Test (Module 8.3): test thật với WebApplicationFactory + Testcontainers — Postgres container tự dựng lên khi chạy test. Phát hiện lỗi migration, lỗi SQL mà Unit Test không thấy được.
- End-to-End: ngoài phạm vi khóa học — test qua UI thật (React Admin/Next.js).

### 1.2. So sánh trực tiếp: test Controller vs test Handler

**Controller truyền thống (ASP.NET Core MVC/API kiểu cũ):** method nhận HttpContext ngầm định, đọc dữ liệu qua [FromBody]/[FromRoute], trả về IActionResult (Ok(), BadRequest(), NotFound()...). Muốn unit test, phải mock ControllerContext, HttpContext, đôi khi cả ModelState — phần lớn công sức test đổ vào việc "giả lập môi trường HTTP" chứ không phải test logic nghiệp vụ.

**Handler CQRS (MediatR):** method Handle(TRequest request, CancellationToken cancellationToken) nhận vào một object thuần (Command/Query là record), trả về một kiểu dữ liệu rõ ràng (Guid, DTO, hoặc không trả gì). Handler không biết gì về HTTP, không có ModelState, không có IActionResult. Test = tạo Command, gọi Handle(), assert kết quả trả về + verify Repository được gọi đúng cách.

> **📘 Ghi chú giảng viên:** *Học viên hay hỏi "vậy còn test 404, 400 thì sao?" — đây chính là điểm cần làm rõ: Handler không trả HTTP status code. Handler ném Exception nghiệp vụ (CourseNotFoundException...), việc map Exception đó sang HTTP 404/400 là trách nhiệm của middleware ở Api layer (đã làm ở bài 0.9), và middleware đó có thể test riêng bằng Integration Test (Module 8.3). Handler chỉ chịu trách nhiệm đúng 1 việc: orchestrate logic nghiệp vụ — đây là lý do CQRS dễ test hơn, không phải vì "MediatR có phép màu gì" mà vì ranh giới trách nhiệm bị ép phải tách rõ.*

Unit Test ở bài này nghĩa là: mock 100% dependency ngoài của Handler (ở đây là ICourseRepository) — chỉ còn logic thuần của Handler được thực thi thật. Không có Postgres, không có network, không có file I/O nào chạy khi test này chạy.

## 3. Unit Test cho CreateCourseCommandHandler

*Demo + Lab · ~10 phút*

Nhắc lại nhanh (đã học ở bài 1.1, 1.2) — CreateCourseCommand và Handler của nó:

```csharp
// TeduMarket.Application/Courses/Commands/CreateCourse/CreateCourseCommand.cs
namespace TeduMarket.Application.Courses.Commands.CreateCourse;
 
public sealed record CreateCourseCommand(
    string Title,
    Guid CategoryId,
    Guid InstructorId,
    decimal Price,
    string Currency) : IRequest<Guid>;
 
public sealed class CreateCourseCommandHandler(ICourseRepository courseRepository)
    : IRequestHandler<CreateCourseCommand, Guid>
{
    public async Task<Guid> Handle(CreateCourseCommand request, CancellationToken cancellationToken)
    {
        var course = Course.Create(
            request.Title,
            request.CategoryId,
            request.InstructorId,
            new Pricing(request.Price, request.Currency));
 
        await courseRepository.AddAsync(course, cancellationToken);
        await courseRepository.SaveChangesAsync(cancellationToken);
 
        return course.Id;
    }
}
```

Viết test — Arrange/Act/Assert, mock ICourseRepository bằng NSubstitute:

```csharp
// tests/TeduMarket.Application.UnitTests/Courses/Commands/CreateCourseCommandHandlerTests.cs
namespace TeduMarket.Application.UnitTests.Courses.Commands;
 
public class CreateCourseCommandHandlerTests
{
    private readonly ICourseRepository _courseRepository = Substitute.For<ICourseRepository>();
 
    [Fact]
    public async Task Handle_ValidCommand_ShouldSaveCourseAndReturnId()
    {
        // Arrange
        var command = new CreateCourseCommand(
            Title: "Clean Architecture với ASP.NET Core 10",
            CategoryId: Guid.NewGuid(),
            InstructorId: Guid.NewGuid(),
            Price: 799_000m,
            Currency: "VND");
 
        var handler = new CreateCourseCommandHandler(_courseRepository);
 
        // Act
        var courseId = await handler.Handle(command, CancellationToken.None);
 
        // Assert
        courseId.ShouldNotBe(Guid.Empty);
 
        await _courseRepository.Received(1).AddAsync(
            Arg.Is<Course>(c => c.Title == command.Title
                && c.InstructorId == command.InstructorId
                && c.CategoryId == command.CategoryId),
            Arg.Any<CancellationToken>());
 
        await _courseRepository.Received(1).SaveChangesAsync(Arg.Any<CancellationToken>());
    }
}
```

> **📘 Ghi chú giảng viên:** *Test này KHÔNG kiểm tra rule "Title không được rỗng" — rule đó thuộc trách nhiệm của CreateCourseCommandValidator chạy trong ValidationBehavior (bài 0.5), request sai sẽ bị chặn TRƯỚC KHI chạm tới Handler. Nếu một bạn viết test Handler với Title rỗng rồi assert throw exception, bạn đang test nhầm tầng — nên tách file test riêng cho Validator (gợi ý ở phần bài tập). Ranh giới này chính là giá trị thực của Pipeline Behavior: mỗi thành phần chỉ cần test đúng phần việc của nó.*

## 4. Unit Test cho UpdateCourseCommandHandler

*Demo + Lab · ~10 phút*

Nhắc lại bài 1.2: UpdateCourseCommand có kèm rule nghiệp vụ "chỉ Instructor sở hữu Course mới được sửa" — ở bài 1.2 đây là check tạm bằng cách so sánh InstructorId truyền vào với Course.InstructorId ngay trong Handler (bài 3.8 sẽ thay bằng CourseOwnerRequirement + IAuthorizationHandler đúng chuẩn OAuth2). Ba tình huống Handler phải xử lý đúng: Course tồn tại và đúng chủ sở hữu → update thành công; Course không tồn tại → ném CourseNotFoundException; Course tồn tại nhưng sai chủ sở hữu → ném CourseNotOwnedException. Cả hai exception đặt tên theo đúng quy ước mục 7 ({Thực thể}{LoạiLỗi}Exception), định nghĩa ở Domain layer, được middleware ở bài 0.9 map sang ProblemDetails.

```csharp
// TeduMarket.Application/Courses/Commands/UpdateCourse/UpdateCourseCommand.cs
namespace TeduMarket.Application.Courses.Commands.UpdateCourse;
 
public sealed record UpdateCourseCommand(
    Guid CourseId,
    Guid InstructorId,
    string Title,
    decimal Price,
    string Currency) : IRequest;
 
public sealed class UpdateCourseCommandHandler(ICourseRepository courseRepository)
    : IRequestHandler<UpdateCourseCommand>
{
    public async Task Handle(UpdateCourseCommand request, CancellationToken cancellationToken)
    {
        var course = await courseRepository.GetByIdAsync(request.CourseId, cancellationToken)
            ?? throw new CourseNotFoundException(request.CourseId);
 
        if (course.InstructorId != request.InstructorId)
        {
            throw new CourseNotOwnedException(request.CourseId, request.InstructorId);
        }
 
        course.UpdateDetails(request.Title, new Pricing(request.Price, request.Currency));
 
        await courseRepository.SaveChangesAsync(cancellationToken);
    }
}
```

Bộ 3 test case tương ứng — đây là bộ test tối thiểu cho một Handler có rule rẽ nhánh:

```csharp
// tests/TeduMarket.Application.UnitTests/Courses/Commands/UpdateCourseCommandHandlerTests.cs
namespace TeduMarket.Application.UnitTests.Courses.Commands;
 
public class UpdateCourseCommandHandlerTests
{
    private readonly ICourseRepository _courseRepository = Substitute.For<ICourseRepository>();
 
    [Fact]
    public async Task Handle_CourseExistsAndOwnedByInstructor_ShouldUpdateAndSaveChanges()
    {
        // Arrange
        var instructorId = Guid.NewGuid();
        var existingCourse = Course.Create(
            "Tên cũ", Guid.NewGuid(), instructorId, new Pricing(500_000m, "VND"));
 
        _courseRepository.GetByIdAsync(existingCourse.Id, Arg.Any<CancellationToken>())
            .Returns(existingCourse);
 
        var command = new UpdateCourseCommand(
            existingCourse.Id, instructorId, "Tên mới", 899_000m, "VND");
        var handler = new UpdateCourseCommandHandler(_courseRepository);
 
        // Act
        await handler.Handle(command, CancellationToken.None);
 
        // Assert
        existingCourse.Title.ShouldBe("Tên mới");
        await _courseRepository.Received(1).SaveChangesAsync(Arg.Any<CancellationToken>());
    }
 
    [Fact]
    public async Task Handle_CourseNotFound_ShouldThrowCourseNotFoundException()
    {
        // Arrange
        var courseId = Guid.NewGuid();
        _courseRepository.GetByIdAsync(courseId, Arg.Any<CancellationToken>())
            .Returns((Course?)null);
 
        var command = new UpdateCourseCommand(courseId, Guid.NewGuid(), "Bất kỳ", 100_000m, "VND");
        var handler = new UpdateCourseCommandHandler(_courseRepository);
 
        // Act & Assert
        await Should.ThrowAsync<CourseNotFoundException>(
            () => handler.Handle(command, CancellationToken.None));
    }
 
    [Fact]
    public async Task Handle_InstructorDoesNotOwnCourse_ShouldThrowCourseNotOwnedException()
    {
        // Arrange
        var ownerId = Guid.NewGuid();
        var otherInstructorId = Guid.NewGuid();
        var existingCourse = Course.Create(
            "Tên cũ", Guid.NewGuid(), ownerId, new Pricing(500_000m, "VND"));
 
        _courseRepository.GetByIdAsync(existingCourse.Id, Arg.Any<CancellationToken>())
            .Returns(existingCourse);
 
        var command = new UpdateCourseCommand(
            existingCourse.Id, otherInstructorId, "Tên mới", 899_000m, "VND");
        var handler = new UpdateCourseCommandHandler(_courseRepository);
 
        // Act & Assert
        await Should.ThrowAsync<CourseNotOwnedException>(
            () => handler.Handle(command, CancellationToken.None));
 
        // Không được lưu bất kỳ thay đổi nào khi bị chặn quyền
        await _courseRepository.DidNotReceive().SaveChangesAsync(Arg.Any<CancellationToken>());
    }
}
```

> **📘 Ghi chú giảng viên:** *Test thứ 3 (DidNotReceive) là chỗ tôi hay dừng lại lâu nhất khi giảng trực tiếp. Học viên thường chỉ nghĩ tới việc "assert đúng Exception được ném ra" mà quên kiểm tra tác dụng phụ: nếu Handler lỡ gọi SaveChangesAsync() TRƯỚC dòng throw (ví dụ đặt sai thứ tự code), test negative case với Should.ThrowAsync vẫn PASS bình thường vì exception vẫn được ném — nhưng dữ liệu đã bị lưu sai trước đó rồi. DidNotReceive() là cách duy nhất bắt được lỗi thứ tự này.*

## Bài tập thực hành

> **✏️ Thực hành:** Viết bộ Unit Test cho AddLessonToCourseCommandHandler (đã xây ở bài 1.3, thao tác qua Course.AddLesson(...) để giữ đúng Aggregate consistency boundary). Yêu cầu tối thiểu 2 test case.

### Input / Expected output

- Test case 1 — Happy path: mock GetByIdAsync trả về 1 Course có sẵn 0 Lesson. Gọi handler.Handle() với AddLessonToCourseCommand(CourseId, Title, VideoUrl, Order). Expected: existingCourse.Lessons.Count phải bằng 1 sau khi Handle chạy xong; repository.SaveChangesAsync được gọi đúng 1 lần.
- Test case 2 — Course không tồn tại: mock GetByIdAsync trả về null. Expected: Handle ném CourseNotFoundException, và SaveChangesAsync KHÔNG được gọi (dùng DidNotReceive giống ví dụ ở mục 4).

### Hint

- Cấu trúc test giống hệt UpdateCourseCommandHandlerTests ở mục 4 — chỉ đổi Command và điều kiện Assert.
- Vì Course.AddLesson(...) là method trên chính Aggregate (không phải trên Lesson), sau khi Handle chạy xong bạn assert thẳng trên object existingCourse đã mock trả về, giống cách assert existingCourse.Title.ShouldBe(...) ở test happy-path của UpdateCourseCommandHandlerTests.

### Solution (gợi ý khung sườn)

```csharp
[Fact]
public async Task Handle_CourseExists_ShouldAddLessonAndSaveChanges()
{
    var existingCourse = Course.Create(
        "ASP.NET Core 10 từ đầu", Guid.NewGuid(), Guid.NewGuid(), new Pricing(0m, "VND"));
 
    _courseRepository.GetByIdAsync(existingCourse.Id, Arg.Any<CancellationToken>())
        .Returns(existingCourse);
 
    var command = new AddLessonToCourseCommand(
        existingCourse.Id, "Bài 1: Giới thiệu", "https://cdn.tedu.com.vn/video1.mp4", Order: 1);
    var handler = new AddLessonToCourseCommandHandler(_courseRepository);
 
    await handler.Handle(command, CancellationToken.None);
 
    existingCourse.Lessons.Count.ShouldBe(1);
    await _courseRepository.Received(1).SaveChangesAsync(Arg.Any<CancellationToken>());
}
```

## Tổng kết

- Handler CQRS dễ test hơn Controller vì input là Command/Query thuần, output rõ ràng, không phụ thuộc HttpContext — test chỉ cần mock đúng 1 dependency: Repository interface.
- Bộ công cụ chuẩn cho TEDU Market: xUnit v3 (framework) + NSubstitute (mock) + Shouldly (assertion) — cả 3 miễn phí cho mục đích thương mại.
- Project tests/TeduMarket.Application.UnitTests chỉ reference TeduMarket.Application — reference này chính là bài kiểm tra sống cho việc tuân thủ Dependency Inversion.
- Test negative case không chỉ assert đúng Exception — phải verify luôn KHÔNG có side-effect nào xảy ra (DidNotReceive) trước khi exception được ném.
- Unit Test (Application, mock hết) khác Integration Test (Module 8.3, Postgres thật qua Testcontainers) — hai tầng bổ sung cho nhau, không thay thế nhau.

> **✅ Tóm tắt:** Bài 1.10 khép lại Module 1 bằng việc đưa Unit Test vào phản xạ làm việc hằng ngày. Module 2 — Order & Payment sẽ liên tục quay lại đúng pattern này (mock ICartRepository, IOrderRepository) cho các Handler phức tạp hơn nhiều: Checkout, ApplyCoupon, xử lý Idempotency.

## Phụ lục — Cheatsheet NSubstitute & Shouldly

| **Việc cần làm** | **NSubstitute** | **Shouldly** |
|---|---|---|
| Tạo mock | Substitute.For\<IFoo>() | — |
| Set giá trị trả về | sub.Method(arg).Returns(value) | — |
| Match tham số bất kỳ | Arg.Any\<T>() | — |
| Match tham số có điều kiện | Arg.Is\<T>(x => ...) | — |
| Verify gọi đúng N lần | await sub.Received(N).Method(...) | — |
| Verify KHÔNG được gọi | sub.DidNotReceive().Method(...) | — |
| So sánh giá trị | — | actual.ShouldBe(expected) |
| Assert không null | — | value.ShouldNotBeNull() |
| Assert throw exception (async) | — | await Should.ThrowAsync\<TEx>(() => ...) |
