## **Nội dung chính**

### **1. Ôn nhanh pattern CQRS — lần lặp thứ 2 để pattern thấm**

*10 phút · Lý thuyết*

Ở bài 0.4–0.5 bạn đã dựng đúng 1 lần chuỗi: Command (record bất biến) → Validator (FluentValidation) → ValidationBehavior (chặn tự động trước Handler) → Handler (gọi factory method của Aggregate, lưu qua Repository). Bài này lặp lại đúng chuỗi đó cho Course — khác biệt duy nhất so với Category là Course phức tạp hơn: có factory Course.Create(...) nhận Value Object Pricing, và có business rule thật cần kiểm tra khi Update (không phải chỉ validate định dạng input).

Business rule của UpdateCourse — "chỉ Instructor sở hữu Course mới được sửa" — outline gọi đây là check "tạm" (mục 5, "Business rule: ... check tạm ở Handler bằng InstructorId truyền vào"). Nghĩa là: ở bài này, Handler tự so sánh InstructorId người gọi truyền lên với InstructorId đã lưu trong Course — không có JWT, không có claims thật, ai gọi API cũng có thể tự xưng là Instructor bất kỳ. Đây là "nợ kỹ thuật có chủ đích" giống tinh thần bài 0.5 — sẽ được thay bằng CourseOwnerRequirement + IAuthorizationHandler đúng chuẩn ở bài 3.8, sau khi có OpenIddict và claims thật ở Module 3.

> **📘 Ghi chú giảng viên:** *Tôi hay hỏi thẳng ở đây: "Check InstructorId kiểu này có an toàn không?" — không, vì client tự gửi InstructorId, không có gì chống giả mạo. Nhưng mục đích bài này KHÔNG phải bảo mật, mà là tập cho học viên thói quen: business rule luôn nằm trong Handler (hoặc Domain), không nằm rải rác ở Validator hay Endpoint. Bài 3.8 sẽ thay đúng 1 dòng if bằng Authorization Policy thật, code Handler xung quanh không đổi — đó là giá trị của việc tách lớp đúng ngay từ đầu.*

### **2. Command CreateCourse: record, Handler, Validator**

*15 phút · Demo*

Theo đúng quy ước namespace đã dùng cho Category (TeduMarket.Application.Categories.Commands.CreateCategory), tạo thư mục Courses/Commands/CreateCourse trong TeduMarket.Application:

```csharp
// TeduMarket.Application/Courses/Commands/CreateCourse/CreateCourseCommand.cs
namespace TeduMarket.Application.Courses.Commands.CreateCourse;
 
public sealed record CreateCourseCommand(
    Guid CategoryId,
    Guid InstructorId,
    string Title,
    decimal Price,
    string Currency = "VND") : IRequest<Guid>;
```

Handler gọi thẳng Course.Create(...) đã viết ở bài 1.1 — Handler không tự kiểm tra "Title có rỗng không", vì đó là việc của Validator (mục dưới); Handler chỉ điều phối: dựng Pricing, dựng Course, lưu qua Repository:

```csharp
// TeduMarket.Application/Courses/Commands/CreateCourse/CreateCourseCommandHandler.cs
using TeduMarket.Application.Courses.Repositories;
using TeduMarket.Domain.Courses;
 
namespace TeduMarket.Application.Courses.Commands.CreateCourse;
 
public sealed class CreateCourseCommandHandler(ICourseRepository courseRepository)
    : IRequestHandler<CreateCourseCommand, Guid>
{
    public async Task<Guid> Handle(CreateCourseCommand request, CancellationToken cancellationToken)
    {
        var pricing = Pricing.Create(request.Price, request.Currency);
        var course = Course.Create(
            request.CategoryId, request.InstructorId, request.Title, pricing);
 
        await courseRepository.AddAsync(course, cancellationToken);
        await courseRepository.SaveChangesAsync(cancellationToken);
 
        return course.Id;
    }
}
```

Validator chặn input sai TRƯỚC KHI chạm Handler, đúng cơ chế ValidationBehavior\<TRequest,TResponse> đã dựng ở bài 0.5 — không cần đăng ký gì thêm, MediatR tự quét assembly và gắn validator vào pipeline:

```csharp
// TeduMarket.Application/Courses/Commands/CreateCourse/CreateCourseCommandValidator.cs
namespace TeduMarket.Application.Courses.Commands.CreateCourse;
 
public sealed class CreateCourseCommandValidator : AbstractValidator<CreateCourseCommand>
{
    public CreateCourseCommandValidator()
    {
        RuleFor(x => x.CategoryId).NotEmpty();
        RuleFor(x => x.InstructorId).NotEmpty();
        RuleFor(x => x.Title).NotEmpty().MaximumLength(200);
        RuleFor(x => x.Price).GreaterThanOrEqualTo(0);
        RuleFor(x => x.Currency).NotEmpty().Length(3);
    }
}
```

> **📘 Ghi chú giảng viên:** *Điểm hay bị hỏi: "Price >= 0 ở Validator, còn Pricing.Create(...) ở bài 1.1 cũng ném ArgumentOutOfRangeException nếu amount \< 0 — trùng lặp à?" — Không hẳn trùng: Validator chặn SỚM, trả lỗi 400 có cấu trúc field-by-field qua HTTP (giá trị cho client); invariant trong Pricing.Create bảo vệ Domain ở MỌI đường gọi khác, kể cả khi không đi qua Command này (ví dụ code test, background job sau này). Có cả hai không phải dư thừa — đây chính là điểm giáo trình đã nhấn ở bài 1.1 mục 3 (Validation vs Invariant).*

### **3. Repository + mở rộng AppDbContext — bản EF Config TẠM THỜI cho Course**

*10 phút · Demo*

Định nghĩa interface ở Application, theo đúng convention I{Aggregate}Repository (mục 7 outline):

```csharp
// TeduMarket.Application/Courses/Repositories/ICourseRepository.cs
namespace TeduMarket.Application.Courses.Repositories;
 
public interface ICourseRepository
{
    Task AddAsync(Course course, CancellationToken cancellationToken = default);
 
    Task<Course?> GetByIdAsync(Guid id, CancellationToken cancellationToken = default);
 
    Task SaveChangesAsync(CancellationToken cancellationToken = default);
}
```

Implement ở Infrastructure, giống hệt cấu trúc CategoryRepository đã viết ở bài 0.6:

```csharp
// TeduMarket.Infrastructure/Persistence/Repositories/CourseRepository.cs
using Microsoft.EntityFrameworkCore;
using TeduMarket.Application.Courses.Repositories;
using TeduMarket.Domain.Courses;
 
namespace TeduMarket.Infrastructure.Persistence.Repositories;
 
public sealed class CourseRepository(AppDbContext context) : ICourseRepository
{
    public async Task AddAsync(Course course, CancellationToken cancellationToken = default)
    {
        await context.Courses.AddAsync(course, cancellationToken);
    }
 
    public Task<Course?> GetByIdAsync(Guid id, CancellationToken cancellationToken = default)
        => context.Courses.FirstOrDefaultAsync(c => c.Id == id, cancellationToken);
 
    public Task SaveChangesAsync(CancellationToken cancellationToken = default)
        => context.SaveChangesAsync(cancellationToken);
}
```

Bổ sung DbSet\<Course> và cấu hình Fluent API vào AppDbContext đã có từ bài 0.6. Đây là điểm quan trọng nhất bài học về mặt kỹ thuật: Course có Pricing (Value Object) và Lessons (quan hệ 1-nhiều với Lesson) — nhưng "Fluent Configuration cho Aggregate phức tạp" đầy đủ (Owned Type có cấu hình cột, quan hệ Course–Lesson, cascade delete) là nội dung của CHÍNH bài 1.4, chưa học tới. Bài này chỉ cấu hình TẠM đủ để Create/Update chạy được — vì Course.Create() luôn khởi tạo danh sách Lesson rỗng và bài này không đụng gì tới Lesson:

```csharp
// TeduMarket.Infrastructure/Persistence/AppDbContext.cs (bổ sung so với bài 0.6)
using TeduMarket.Domain.Courses;
 
public sealed class AppDbContext(DbContextOptions<AppDbContext> options) : DbContext(options)
{
    public DbSet<Category> Categories => Set<Category>();
    public DbSet<Course> Courses => Set<Course>();
 
    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<Category>(builder =>
        {
            builder.ToTable("Categories");
            builder.HasKey(c => c.Id);
            builder.Property(c => c.Name).IsRequired().HasMaxLength(200);
        });
 
        // ⚠️ TẠM THỜI — chỉ đủ để CreateCourse/UpdateCourse persist được ở bài này.
        // OwnsOne(Pricing) dùng cấu hình mặc định (chưa đặt tên cột, chưa precision).
        // Ignore(Lessons) vì bài 1.2 chưa thao tác gì tới Lesson — Course.Create()
        // luôn khởi tạo danh sách rỗng. Bài 1.4 sẽ GỠ dòng Ignore này, thay bằng
        // cấu hình quan hệ Course–Lesson 1-nhiều đầy đủ (HasMany, cascade delete,
        // backing field _lessons) và bổ sung precision/tên cột cho Pricing.
        modelBuilder.Entity<Course>(builder =>
        {
            builder.ToTable("Courses");
            builder.HasKey(c => c.Id);
            builder.Property(c => c.Title).IsRequired().HasMaxLength(200);
            builder.OwnsOne(c => c.Pricing);
            builder.Ignore(c => c.Lessons);
        });
 
        base.OnModelCreating(modelBuilder);
    }
}
```

Đăng ký DI cho ICourseRepository trong extension method AddInfrastructure đã có từ bài 0.6:

```csharp
// TeduMarket.Infrastructure/DependencyInjection.cs — thêm 1 dòng
services.AddScoped<ICourseRepository, CourseRepository>();
```

> **⚠️ Lưu ý:** Nếu học viên đã chạy EnsureCreatedAsync (bài 0.6) để tạo schema tạm, cần chạy lại (hoặc xoá database dev và tạo lại) sau khi thêm DbSet\<Course> — EnsureCreatedAsync chỉ tạo schema đúng 1 lần lúc bảng chưa tồn tại, không tự đồng bộ khi model đổi. Đây chính xác là vấn đề mà bài 1.5 (Migration Workflow) sẽ giải quyết triệt để; ở bài 1.2 này cứ xoá và tạo lại database dev khi cần.

### **4. Command UpdateCourse: business rule ownership tạm thời**

*15 phút · Demo*

UpdateCourse cần 2 việc mà CreateCourse không có: (1) tìm đúng Course đang tồn tại, (2) kiểm tra người gọi có phải chủ sở hữu. Cả hai đều là tình huống lỗi nghiệp vụ thật — cần 2 exception mới, đặt ở Domain theo đúng convention {Thực thể}{LoạiLỗi}Exception (mục 7 outline).

CourseNotFoundException tái sử dụng base NotFoundException đã có từ bài 0.9 — GlobalExceptionHandler đã map sẵn NotFoundException → 404, không cần sửa gì thêm:

```csharp
// TeduMarket.Domain/Exceptions/CourseNotFoundException.cs
namespace TeduMarket.Domain.Exceptions;
 
public sealed class CourseNotFoundException(Guid courseId)
    : NotFoundException($"Không tìm thấy Course với Id: {courseId}")
{
    public Guid CourseId { get; } = courseId;
}
```

> **⚠️ Lưu ý:** Chính thức hoá DomainException: bài 1.1 đã viết CourseCannotPublishException : DomainException(message), nhưng lớp DomainException đó CHƯA từng được định nghĩa ở bài 0.9 — bài 0.9 chỉ tạo NotFoundException. Đây là một khoảng hở giữa 2 bài đã phát hành, cần vá ngay ở bài này trước khi dùng tiếp cho CourseNotOwnedException, nếu không code bài 1.1 sẽ không biên dịch được.

Tạo DomainException — base thứ 2 trong Domain layer, song song với NotFoundException, dành cho vi phạm business invariant nói chung (khác "không tìm thấy"):

```csharp
// TeduMarket.Domain/Exceptions/DomainException.cs
namespace TeduMarket.Domain.Exceptions;
 
/// <summary>
/// Base exception cho vi phạm business invariant nói chung — khác NotFoundException
/// (dành riêng cho "không tìm thấy entity"). Message dùng trực tiếp làm "detail"
/// trong ProblemDetails, viết cho người dùng cuối đọc được. CourseCannotPublishException
/// (bài 1.1) là ví dụ đầu tiên; CourseNotOwnedException (bài này) là ví dụ thứ 2.
/// </summary>
public abstract class DomainException(string message) : Exception(message);
```

```csharp
// TeduMarket.Domain/Exceptions/CourseNotOwnedException.cs
namespace TeduMarket.Domain.Exceptions;
 
public sealed class CourseNotOwnedException(Guid courseId, Guid instructorId)
    : DomainException(
        $"Course {courseId} không thuộc quyền sở hữu của Instructor {instructorId}.")
{
    public Guid CourseId { get; } = courseId;
    public Guid InstructorId { get; } = instructorId;
}
```

Vì DomainException là loại mới, GlobalExceptionHandler (bài 0.9, TeduMarket.Api/ExceptionHandling/GlobalExceptionHandler.cs) cần thêm 1 nhánh switch — nếu không, mọi DomainException sẽ rơi vào nhánh mặc định 500, sai hoàn toàn về ngữ nghĩa HTTP:

```csharp
// TeduMarket.Api/ExceptionHandling/GlobalExceptionHandler.cs — cập nhật MapException
private static (int StatusCode, string Title) MapException(Exception exception) => exception switch
{
    ValidationException => (StatusCodes.Status400BadRequest, "Dữ liệu không hợp lệ"),
    NotFoundException => (StatusCodes.Status404NotFound, "Không tìm thấy tài nguyên"),
    DomainException => (StatusCodes.Status409Conflict, "Vi phạm quy tắc nghiệp vụ"),
    _ => (StatusCodes.Status500InternalServerError, "Đã có lỗi xảy ra khi xử lý yêu cầu")
};
```

> **📘 Ghi chú giảng viên:** *409 Conflict cho DomainException là lựa chọn tạm — đúng ngữ nghĩa REST cho "request hợp lệ về định dạng nhưng xung đột với trạng thái hiện tại của resource" (Course chưa có Lesson thì không publish được; Course không thuộc Instructor này thì không sửa được). Từ bài 3.8 trở đi, khi có IAuthorizationHandler thật, việc "không phải chủ sở hữu" sẽ được policy chặn ở tầng Authorization và trả về đúng 403 Forbidden — lúc đó CourseNotOwnedException gần như không còn cơ hội bị ném ra nữa (vì request đã bị chặn từ trước khi vào Handler), nhưng ta vẫn giữ exception này lại như một lớp phòng thủ thứ 2 (defense in depth).*

Bổ sung method UpdateDetails(...) vào Course Aggregate (bài 1.1) — sửa Title/Pricing phải đi qua method của Aggregate Root, không set trực tiếp property từ bên ngoài, đúng nguyên tắc đã học ở bài 1.1 mục 2:

```csharp
// TeduMarket.Domain/Courses/Course.cs — bổ sung method mới
public void UpdateDetails(string title, Pricing pricing)
{
    if (string.IsNullOrWhiteSpace(title))
        throw new ArgumentException(
            "Tên khóa học không được để trống.", nameof(title));
 
    Title = title;
    Pricing = pricing;
}
```

Command, Handler, Validator cho Update — theo đúng convention {Động từ}{Thực thể}Command / {Tên Command}Handler / {Tên Command}Validator:

```csharp
// TeduMarket.Application/Courses/Commands/UpdateCourse/UpdateCourseCommand.cs
namespace TeduMarket.Application.Courses.Commands.UpdateCourse;
 
public sealed record UpdateCourseCommand(
    Guid CourseId,
    Guid InstructorId,
    string Title,
    decimal Price,
    string Currency = "VND") : IRequest;
```

```csharp
// TeduMarket.Application/Courses/Commands/UpdateCourse/UpdateCourseCommandHandler.cs
using TeduMarket.Application.Courses.Repositories;
using TeduMarket.Domain.Courses;
using TeduMarket.Domain.Exceptions;
 
namespace TeduMarket.Application.Courses.Commands.UpdateCourse;
 
public sealed class UpdateCourseCommandHandler(ICourseRepository courseRepository)
    : IRequestHandler<UpdateCourseCommand>
{
    public async Task Handle(UpdateCourseCommand request, CancellationToken cancellationToken)
    {
        var course = await courseRepository.GetByIdAsync(request.CourseId, cancellationToken)
            ?? throw new CourseNotFoundException(request.CourseId);
 
        // Business rule tạm thời (outline mục 5) — thay bằng IAuthorizationHandler ở bài 3.8.
        if (course.InstructorId != request.InstructorId)
            throw new CourseNotOwnedException(course.Id, request.InstructorId);
 
        var pricing = Pricing.Create(request.Price, request.Currency);
        course.UpdateDetails(request.Title, pricing);
 
        await courseRepository.SaveChangesAsync(cancellationToken);
    }
}
```

> **📘 Ghi chú giảng viên:** *Để ý: Handler KHÔNG gọi courseRepository.AddAsync hay bất kỳ "UpdateAsync" nào — course lấy ra từ GetByIdAsync đã được EF Core tự động track (change tracking). Gọi course.UpdateDetails(...) chỉ thay đổi property trong bộ nhớ; SaveChangesAsync() ở cuối mới thật sự sinh câu UPDATE xuống Postgres. Đây là điểm khác biệt quan trọng so với Create (cần AddAsync để EF biết đây là dòng MỚI) — học viên mới hay quên gọi AddAsync ở Create hoặc thừa gọi ở Update, cả hai đều gây lỗi khó hiểu lúc chạy.*


### **5. Minimal API Endpoint: POST & PUT /api/v1/courses**

*10 phút · Demo + Lab*

Khác với CategoryEndpoints ở bài 0.7 (lúc đó GlobalExceptionHandler chưa tồn tại nên phải try/catch ValidationException thủ công), từ bài 0.9 trở đi mọi exception (ValidationException, NotFoundException, DomainException) đều tự động bay tới GlobalExceptionHandler — Endpoint chỉ còn nhiệm vụ mỏng: nhận request, gửi Command, map response thành công:

```csharp
// TeduMarket.Api/Endpoints/CourseEndpoints.cs
using MediatR;
using Microsoft.AspNetCore.Http.HttpResults;
using TeduMarket.Application.Courses.Commands.CreateCourse;
using TeduMarket.Application.Courses.Commands.UpdateCourse;
 
namespace TeduMarket.Api.Endpoints;
 
public static class CourseEndpoints
{
    public static IEndpointRouteBuilder MapCourseEndpoints(this IEndpointRouteBuilder app)
    {
        var group = app.MapGroup("/api/v1/courses").WithTags("Courses");
 
        group.MapPost("/", CreateCourse);
        group.MapPut("/{id:guid}", UpdateCourse);
 
        return app;
    }
 
    private static async Task<Created<CreateCourseResponse>> CreateCourse(
        CreateCourseRequest request, ISender sender, CancellationToken cancellationToken)
    {
        var command = new CreateCourseCommand(
            request.CategoryId, request.InstructorId, request.Title,
            request.Price, request.Currency);
 
        var courseId = await sender.Send(command, cancellationToken);
 
        return TypedResults.Created(
            $"/api/v1/courses/{courseId}", new CreateCourseResponse(courseId));
    }
 
    private static async Task<NoContent> UpdateCourse(
        Guid id, UpdateCourseRequest request, ISender sender, CancellationToken cancellationToken)
    {
        var command = new UpdateCourseCommand(
            id, request.InstructorId, request.Title, request.Price, request.Currency);
 
        await sender.Send(command, cancellationToken);
 
        return TypedResults.NoContent();
    }
}
 
public sealed record CreateCourseRequest(
    Guid CategoryId, Guid InstructorId, string Title, decimal Price, string Currency = "VND");
 
public sealed record CreateCourseResponse(Guid Id);
 
public sealed record UpdateCourseRequest(
    Guid InstructorId, string Title, decimal Price, string Currency = "VND");
```

Đăng ký trong Program.cs, ngay cạnh app.MapCategoryEndpoints() đã có từ bài 0.7:

```csharp
// Program.cs
app.MapCategoryEndpoints();
app.MapCourseEndpoints();
 
app.Run();
```

### **6. Kiểm chứng end-to-end: 4 tình huống thật**

*10 phút · Lab*

Chạy dotnet run, test lần lượt qua curl/Postman, tự quan sát 4 tình huống trả về đúng status code:

- 201 — POST /api/v1/courses với body hợp lệ → trả về { "id": "..." }, header Location trỏ tới /api/v1/courses/{id}.
- 400 — POST /api/v1/courses với title rỗng → ProblemDetails 400, extension "errors" chỉ đúng field Title (ValidationBehavior chặn trước khi vào Handler).
- 404 — PUT /api/v1/courses/{id-không-tồn-tại} → ProblemDetails 404, detail chứa đúng Id vừa gọi.
- 409 — PUT /api/v1/courses/{id-có-thật} với InstructorId khác InstructorId lúc Create → ProblemDetails 409, detail nêu rõ Course không thuộc Instructor đó.

```bash
curl -i -X POST http://localhost:5000/api/v1/courses \
  -H "Content-Type: application/json" \
  -d '{"categoryId":"<category-id>","instructorId":"<instructor-id>",
       "title":"ASP.NET Core Zero to Hero","price":499000,"currency":"VND"}'
 
# HTTP/1.1 201 Created
# { "id": "<course-id>" }
 
curl -i -X PUT http://localhost:5000/api/v1/courses/<course-id> \
  -H "Content-Type: application/json" \
  -d '{"instructorId":"<instructor-id-khac>","title":"Tên mới","price":599000,"currency":"VND"}'
 
# HTTP/1.1 409 Conflict
# {
#   "title": "Vi phạm quy tắc nghiệp vụ",
#   "status": 409,
#   "detail": "Course <course-id> không thuộc quyền sở hữu của Instructor <instructor-id-khac>."
# }
```

## **Bài tập thực hành**

> **✏️ Thực hành:** Viết thêm test case "chạy trơn": tạo 1 Course với InstructorId = A, sau đó gọi UpdateCourse với đúng InstructorId = A và dữ liệu hợp lệ. Quan sát response 204 No Content, sau đó gọi GET (khi bài 1.7 có Query Detail) hoặc kiểm tra trực tiếp trong Postgres bằng psql/DBeaver để xác nhận Title/Pricing đã đổi thật. Ghi lại: EF Core biết đây là UPDATE chứ không phải INSERT nhờ đâu — không có dòng code nào trong Handler nói "đây là update" cả.

Input: 1 Course đã tồn tại (từ bước Create ở trên) + InstructorId đúng chủ sở hữu.

Expected output: PUT trả 204 No Content; dữ liệu trong bảng Courses đổi đúng theo body gửi lên.

> **📘 Ghi chú giảng viên:** *Hint cho học viên bị kẹt: EF Core Change Tracker tự nhận biết "update" vì entity trả về từ GetByIdAsync đã ở trạng thái Unchanged trong context — khi property đổi giá trị (qua UpdateDetails), trạng thái tự chuyển sang Modified; SaveChangesAsync chỉ cần dò các entity Modified để sinh câu UPDATE, không cần Handler khai báo gì thêm. Đây là lý do vì sao Repository của TEDU Market không có method UpdateAsync riêng.*

## **Tổng kết**

> **✅** Command CreateCourse & UpdateCourse lặp lại đúng chuỗi Command/Validator/ValidationBehavior/Handler đã học ở Module 0 — lần lặp thứ 2 để pattern trở thành phản xạ, không phải học lại từ đầu.
>
> **✅** AppDbContext có cấu hình EF Core TẠM THỜI cho Course (OwnsOne Pricing mặc định, Ignore Lessons) — đủ chạy Create/Update ở bài này; bài 1.4 sẽ gỡ Ignore, thêm cấu hình quan hệ Course–Lesson đầy đủ khi bài 1.3 bắt đầu thao tác thật với Lesson.
>
> **✅** Business rule "chỉ Instructor sở hữu mới được sửa" hiện kiểm tra tạm bằng so sánh InstructorId truyền tay — không an toàn, sẽ được thay bằng IAuthorizationHandler + Policy thật ở bài 3.8 sau khi có OpenIddict.
>
> **✅** Domain layer giờ có 2 exception base song song: NotFoundException (bài 0.9, → 404) và DomainException (chính thức hoá ở bài này, → 409) — GlobalExceptionHandler đã cập nhật để map cả hai đúng ngữ nghĩa HTTP.
>
> **✅** CourseEndpoints không cần try/catch ValidationException thủ công như CategoryEndpoints ở bài 0.7 — GlobalExceptionHandler (bài 0.9) đã xử lý tập trung cho mọi Command/Query từ đây về sau.
