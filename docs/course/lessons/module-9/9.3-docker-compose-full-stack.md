## Nội dung chính

### 1. Bối cảnh: từ 3 Dockerfile rời rạc đến 1 hệ thống chạy được

*Thời lượng: 5 phút | Loại: Lý thuyết ngắn*

Sau bài 9.1 và 9.2, bạn có 3 Dockerfile build được 3 image riêng: TeduMarket.Api (multi-stage .NET 10), apps/admin (React build tĩnh serve qua Nginx) và apps/web (Next.js standalone output). Ba image này build độc lập được, nhưng chưa ai nói với nhau: API không biết Postgres/Redis ở đâu, Admin và Web không biết gọi API ở địa chỉ nào.

docker-compose.prod.yml là bản khai báo toàn bộ hệ thống — 6 service, cách chúng nói chuyện với nhau qua 1 Docker network nội bộ, thứ tự khởi động, và nguồn cấu hình (secret) tách khỏi source code. Đây là bước cuối trước khi đưa Nginx vào làm reverse proxy ở bài 9.4, nên ở bài này các service vẫn tạm expose port thẳng ra host để bạn tự kiểm tra bằng tay.

> **📘 Ghi chú giảng viên:** *Tôi hay nhấn mạnh điểm này: docker-compose.prod.yml không phải chỉ là "docker-compose.yml đổi tên". File dev ở bài 0.10 chỉ có Postgres + Redis, chạy image build từ source theo kiểu bind-mount để hot-reload. File prod ở đây build/chạy image đã đóng gói sẵn (immutable), không mount source code, và bắt buộc phải có chiến lược secret — hai file phục vụ hai mục đích hoàn toàn khác nhau dù cú pháp giống nhau.*

### 2. Thiết kế docker-compose.prod.yml

*Thời lượng: 10 phút | Loại: Demo*

6 service cần khai báo:

- postgres (postgres:17-alpine) — ghi dữ liệu Write model, đúng version PostgreSQL 17 đã chốt từ đầu khóa.
- redis (redis:8-alpine) — cache/distributed store, hạ tầng đã giới thiệu ở bài 0.10, dùng thêm cho rate limiting (Module 4.4) và output cache trong production.
- seq (datalust/seq) — log server, container chạy sẵn ở bài này nhưng Serilog trong Api CHƯA point tới đây — việc đó để dành cho bài 9.7.
- api — image build từ backend/src/TeduMarket.Api/Dockerfile (bài 9.1).
- admin — image build từ frontend/apps/admin/Dockerfile (bài 9.2).
- web — image build từ frontend/apps/web/Dockerfile (bài 9.2).

Ba nguyên tắc bắt buộc áp dụng cho file compose production:

- Không có "version:" ở đầu file — key này đã obsolete từ Compose Specification (Compose V2 bỏ qua và cảnh báo nếu còn khai báo). Dùng "name:" ở top-level nếu muốn đặt tên project cố định.
- Mọi secret (mật khẩu Postgres/Redis/Seq) đọc từ biến môi trường qua file .env.prod — không được hard-code trong docker-compose.prod.yml, vì file này commit vào git còn .env.prod thì .gitignore.
- depends_on dùng dạng có điều kiện (condition: service_healthy) cho service có healthcheck, thay vì dạng danh sách cũ (chỉ đảm bảo thứ tự start container, không đảm bảo Postgres đã sẵn sàng nhận kết nối).

> **📘 Ghi chú giảng viên:** *Điểm học viên hay hỏi: "Sao api không có healthcheck luôn cho chuẩn?" — Nếu Dockerfile ở bài 9.1 dùng base image dạng chiseled/distroless để tối ưu kích thước (mcr.microsoft.com/dotnet/aspnet:10.0-noble-chiseled) thì container đó KHÔNG có shell, không có curl/wget — HEALTHCHECK kiểu CMD-SHELL sẽ luôn fail dù app chạy tốt. Tôi để api chỉ depends_on postgres/redis theo service_healthy (không tự thêm healthcheck cho chính api) và nêu rõ đây là bài tập mở rộng, để học viên tự quyết định theo base image thật họ đã chọn ở bài 9.1.*

### 3. Lab: viết và chạy docker-compose.prod.yml

*Thời lượng: 15 phút | Loại: Demo + Lab*

Bước 1 — Tạo file .env.prod ở thư mục gốc repo (cùng cấp docker-compose.prod.yml), KHÔNG commit file này:

```bash
# .env.prod — KHÔNG commit, thêm vào .gitignore
POSTGRES_DB=teduMarket
POSTGRES_USER=teduMarket
POSTGRES_PASSWORD=doi-mat-khau-nay-truoc-khi-len-prod
REDIS_PASSWORD=doi-mat-khau-redis-nay
SEQ_FIRSTRUN_ADMINPASSWORDHASH=<chay: docker run --rm -i datalust/seq config hash>
API_PUBLIC_URL=https://api.teduMarket.dev
IMAGE_TAG=latest
```

Bước 2 — Tạo docker-compose.prod.yml ở thư mục gốc repo:

```yaml
name: tedu-market
 
services:
  postgres:
    image: postgres:17-alpine
    restart: unless-stopped
    environment:
      POSTGRES_DB: ${POSTGRES_DB}
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
    volumes:
      - postgres-data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U $${POSTGRES_USER} -d $${POSTGRES_DB}"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks: [tedu-market]
 
  redis:
    image: redis:8-alpine
    restart: unless-stopped
    command: ["redis-server", "--requirepass", "${REDIS_PASSWORD}"]
    volumes:
      - redis-data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD}", "ping"]
      interval: 10s
      timeout: 5s
      retries: 5
    networks: [tedu-market]
 
  seq:
    image: datalust/seq:latest
    restart: unless-stopped
    environment:
      ACCEPT_EULA: "Y"
      SEQ_FIRSTRUN_ADMINPASSWORDHASH: ${SEQ_FIRSTRUN_ADMINPASSWORDHASH}
    volumes:
      - seq-data:/data
    ports:
      - "5341:80"   # tạm mở để test UI, bài 9.4 sẽ đóng cổng này lại sau Nginx
    networks: [tedu-market]
 
  api:
    build:
      context: ./backend
      dockerfile: src/TeduMarket.Api/Dockerfile
    image: teduMarket/api:${IMAGE_TAG}
    restart: unless-stopped
    environment:
      ASPNETCORE_ENVIRONMENT: Production
      ASPNETCORE_URLS: http://+:8080
      ConnectionStrings__Default: "Host=postgres;Database=${POSTGRES_DB};Username=${POSTGRES_USER};Password=${POSTGRES_PASSWORD}"
      ConnectionStrings__Redis: "redis:6379,password=${REDIS_PASSWORD}"
      Seq__ServerUrl: "http://seq:80"
      OpenIddict__Issuer: "${API_PUBLIC_URL}"
    depends_on:
      postgres:
        condition: service_healthy
      redis:
        condition: service_healthy
      seq:
        condition: service_started
    ports:
      - "8080:8080"   # tạm mở trực tiếp, bài 9.4 thay bằng Nginx nội bộ
    networks: [tedu-market]
 
  admin:
    build:
      context: ./frontend
      dockerfile: apps/admin/Dockerfile
    image: teduMarket/admin:${IMAGE_TAG}
    restart: unless-stopped
    depends_on: [api]
    ports:
      - "8081:80"     # tạm mở, 9.4 gắn vào admin.teduMarket.dev
    networks: [tedu-market]
 
  web:
    build:
      context: ./frontend
      dockerfile: apps/web/Dockerfile
    image: teduMarket/web:${IMAGE_TAG}
    restart: unless-stopped
    environment:
      PORT: "3000"
      HOSTNAME: "0.0.0.0"
      NEXT_PUBLIC_API_URL: "${API_PUBLIC_URL}"
    depends_on: [api]
    ports:
      - "3000:3000"   # tạm mở, 9.4 gắn vào www.teduMarket.dev
    networks: [tedu-market]
 
volumes:
  postgres-data:
  redis-data:
  seq-data:
 
networks:
  tedu-market:
    driver: bridge
```

> **📘 Ghi chú giảng viên:** *Dấu $$ trong test của healthcheck (VD: $${POSTGRES_USER}) không phải lỗi gõ nhầm — Compose tự thay thế ${VAR} bằng giá trị từ .env.prod ngay khi parse file, nên nếu muốn biến đó được giữ nguyên để container tự resolve lúc runtime (bên trong chuỗi test của healthcheck) phải escape bằng $$. Đây là lỗi tôi thấy học viên dính nhiều nhất khi mới viết healthcheck.*

Bước 3 — Build và chạy toàn bộ hệ thống:

```yaml
docker compose --env-file .env.prod -f docker-compose.prod.yml up --build -d
docker compose -f docker-compose.prod.yml ps
```

Bước 4 — Verify từng service (đợi postgres/redis chuyển sang "healthy" trước):

```bash
curl http://localhost:8080/api/v1/categories   # API — Module 0.8 đã có endpoint này
curl -I http://localhost:8081                  # Admin (React static qua Nginx)
curl -I http://localhost:3000                  # Web (Next.js standalone)
# Mở trình duyệt http://localhost:5341 để xem Seq UI
```

Nếu api không lên được, kiểm tra \`docker compose -f docker-compose.prod.yml logs api\` trước — 90% lỗi ở bước này là do ConnectionStrings sai tên host (phải là tên service "postgres"/"redis" trong network nội bộ, không phải "localhost") hoặc .env.prod chưa được nạp đúng.

## Bài tập thực hành

> **✏️ Đề bài:** Thêm giới hạn tài nguyên (mem_limit hoặc deploy.resources.limits) cho service api và postgres trong docker-compose.prod.yml, sao cho api tối đa 512MB RAM và postgres tối đa 1GB RAM. Chạy lại \`docker compose up\` và dùng \`docker stats\` để xác nhận giới hạn có hiệu lực.
>
> **✏️ Hint:** Với Compose plugin v2 (không dùng Swarm), cách đơn giản nhất là dùng khóa "mem_limit: 512m" trực tiếp trong định nghĩa service — không cần khối "deploy:" (khối đó chỉ có tác dụng đầy đủ khi chạy qua "docker stack deploy").
>
> **✏️ Mở rộng (không bắt buộc):** Nếu Dockerfile api ở bài 9.1 dùng base image có shell (ví dụ \*-alpine, không phải \*-chiseled), hãy thêm HEALTHCHECK cho service api bằng một endpoint /health tối thiểu (map thêm 1 route trả 200 OK, không cần đụng vào Minimal API endpoint nghiệp vụ) và cấu hình admin, web depends_on api theo condition: service_healthy thay vì chỉ chờ container start.

## Tổng kết

- docker-compose.prod.yml gộp 6 service (postgres, redis, seq, api, admin, web) trên 1 Docker network nội bộ, không mount source code, không có key "version:" đã obsolete.
- Secret (mật khẩu DB/Redis/Seq) tách hoàn toàn khỏi file compose, nạp qua .env.prod — file này không commit vào git.
- depends_on dùng condition: service_healthy cho postgres/redis (nhờ healthcheck pg_isready/redis-cli ping) để api không khởi động sớm hơn hạ tầng nó cần.
- Toàn bộ port hiện đang expose thẳng ra host chỉ mang tính tạm thời để verify tay — đây là điểm sẽ đổi ngay ở bài kế tiếp.
- Seq container đã chạy nhưng chưa nhận log gì — Serilog sink trỏ vào Seq là việc của bài 9.7.

> **✅ Tóm tắt:** Hệ thống production giờ chạy được bằng đúng 1 lệnh \`docker compose up\`, nhưng vẫn lộ port trực tiếp và chưa có domain/HTTPS. Bước tiếp theo — bài 9.4 (Nginx Reverse Proxy Multi-app) — sẽ đưa Nginx vào làm cổng vào duy nhất, route theo 3 subdomain (api., admin., www.) và gỡ hầu hết port mapping trực tiếp ra khỏi file này.
