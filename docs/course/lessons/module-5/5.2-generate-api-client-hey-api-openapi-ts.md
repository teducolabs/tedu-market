## 1. Vì sao không viết tay fetch() cho từng endpoint

Đến hết Module 4, backend đã có hơn 20 endpoint dưới /api/v1 — Category, Course, Lesson, Order, Coupon, Payment... Nếu viết tay từng lời gọi fetch() ở apps/admin và apps/web, bạn phải tự định nghĩa lại type request/response cho mỗi endpoint ở cả 2 nơi. Vấn đề không nằm ở việc viết fetch() khó — mà ở chỗ giữ đồng bộ type theo thời gian.

Ví dụ cụ thể: ở bài 2.3 (Coupon & Pricing Rule), Pricing Value Object có thể đổi từ một số thập phân đơn giản sang object có amount và currency riêng. Nếu apps/admin tự định nghĩa type Course tay, TypeScript ở đó không hề biết backend đã đổi field — lỗi chỉ lộ ra lúc chạy thật (runtime), thường là khi đã lên production, chứ không phải lúc bạn gõ code.

@hey-api/openapi-ts giải quyết đúng vấn đề này: openapi.json mà bài 4.1 sinh ra là nguồn sự thật duy nhất mô tả chính xác request/response của mọi endpoint đã chuẩn hoá ở bài 4.5. Công cụ đọc file này và sinh 3 nhóm artifact:

- types.gen.ts — interface TypeScript cho mọi DTO xuất hiện trong schema.
- sdk.gen.ts — function gọi API type-safe, đặt tên theo operationId của từng endpoint — chính là giá trị của WithName() đã làm kỹ ở bài 4.1.
- client.gen.ts cùng 2 thư mục client/ và core/ — runtime HTTP client, mặc định dùng Fetch API chuẩn của trình duyệt/Node.js, không cần cài thêm axios.

> **📘 Ghi chú giảng viên:** *Tôi hay so sánh với cách làm cũ hơn (NSwag, openapi-generator-cli chạy trên nền Java) để học viên hiểu vì sao khóa chọn @hey-api/openapi-ts: công cụ cũ sinh code qua template cứng, khó tuỳ biến, phải cài JRE riêng trên máy CI. @hey-api/openapi-ts viết hoàn toàn bằng TypeScript, chạy ngay trong Node.js đã có sẵn, và quan trọng nhất — có hệ sinh thái plugin (TanStack Query, Zod, MSW...) cắm thẳng vào pipeline generate, không phải sinh code xong rồi tự viết thêm một lớp bọc tay.*

Đây chính là cơ chế kỹ thuật hiện thực hoá quyết định kiến trúc số 3 ở outline: packages/api-client generate 1 lần, dùng chung cho cả apps/admin lẫn apps/web — đổi API ở backend, generate lại 1 lệnh, cả 2 app nhận type mới cùng lúc. Bài 5.4 sẽ chứng minh trực tiếp bằng cách đổi 1 field ở backend và cho học viên thấy lỗi compile-time xuất hiện đồng thời ở cả 2 app.

## 2. Cài đặt @hey-api/openapi-ts vào packages/api-client

Vào đúng package đã tạo khung ở bài 5.1 — chưa đổi cấu trúc thư mục, chỉ thêm code thật vào chỗ trống:

```bash
cd packages/api-client
```

@hey-api/openapi-ts hiện vẫn ở giai đoạn initial development (chưa ra bản 1.0), nên tài liệu chính thức khuyến nghị pin đúng version thay vì dùng range ^ hay ~:

```bash
pnpm add -D -E @hey-api/openapi-ts typescript tsx
```

> **📘 Ghi chú giảng viên:** *Cờ -E (exact) khoá cứng đúng version vừa cài trong package.json, không cho pnpm tự nâng version phụ ở lần cài sau. Với một package còn breaking change giữa các bản 0.x như @hey-api/openapi-ts, đây không phải thói quen thừa — nó tránh việc 2 máy trong team generate ra code khác nhau chỉ vì cài package ở 2 thời điểm khác nhau.*

Cập nhật package.json của packages/api-client — thay script build đang là echo placeholder từ bài 5.1, và thêm script generate:

```json
// packages/api-client/package.json
{
  "name": "@tedu-market/api-client",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "main": "./dist/index.js",
  "types": "./dist/index.d.ts",
  "scripts": {
    "generate": "openapi-ts",
    "build": "tsc -p tsconfig.json"
  },
  "dependencies": {
    "@tanstack/react-query": "^5.62.0"
  },
  "devDependencies": {
    "@hey-api/openapi-ts": "0.83.1",
    "typescript": "^5.7.0",
    "tsx": "^4.19.0"
  }
}
```

> **📘 Ghi chú giảng viên:** *@tanstack/react-query nằm ở dependencies, không phải devDependencies — vì file react-query.gen.ts sắp sinh ra sẽ import trực tiếp type từ package này. apps/admin (Module 6) cần nó có mặt thật lúc chạy ứng dụng, không chỉ lúc generate code.*

### Viết openapi-ts.config.ts

Tạo file cấu hình ngay ở gốc packages/api-client — @hey-api/openapi-ts dùng jiti loader tự tìm file này, không cần khai báo đường dẫn ở nơi khác:

```typescript
// packages/api-client/openapi-ts.config.ts
import { defineConfig } from '@hey-api/openapi-ts';
 
export default defineConfig({
  input: 'https://localhost:{port}/openapi/v1.json',
  output: 'src',
  plugins: [
    '@hey-api/typescript',
    '@hey-api/sdk',
    '@hey-api/client-fetch',
    '@tanstack/react-query',
  ],
});
```

> **📘 Ghi chú giảng viên:** *Thay {port} bằng port https thật của TeduMarket.Api — xem trong launchSettings.json (đã cấu hình từ bài 0.2), giống cách bạn từng gọi /connect/token bằng https://localhost:{port} ở bài 3.2. Nếu gặp lỗi SSL vì chứng chỉ dev tự ký (self-signed) của .NET khi generate, set biến môi trường NODE_TLS_REJECT_UNAUTHORIZED=0 trước khi chạy lệnh — chỉ dùng ở máy dev cá nhân, tuyệt đối không mang cách này qua CI hay production.*

Giải thích vai trò từng plugin trong mảng plugins:

- @hey-api/typescript: sinh types.gen.ts — interface cho request/response DTO của toàn bộ endpoint đã xây từ Module 0 đến Module 4.
- @hey-api/sdk: sinh sdk.gen.ts — mỗi endpoint thành 1 function độc lập (mặc định tree-shakeable), đặt tên theo operationId — chính là giá trị của việc gọi WithName() kỹ càng ở bài 4.1.
- @hey-api/client-fetch: sinh client.gen.ts và 2 thư mục client/, core/ — runtime dùng Fetch API chuẩn. Đây vốn là client mặc định nên thật ra không bắt buộc liệt kê, nhưng ghi tường minh để sau này dễ đổi sang Axios mà không phải đoán cấu hình ẩn.
- @tanstack/react-query: sinh react-query.gen.ts — mỗi endpoint dạng query có sẵn hàm ...Options() dùng thẳng trong useQuery, mỗi endpoint dạng mutation có sẵn hàm ...Mutation() dùng thẳng trong useMutation. Bài 6.3 sẽ dùng ngay, không viết lại hook tay.

## 3. Chạy generate và đọc cấu trúc output

Đảm bảo backend đang chạy (dotnet run từ TeduMarket.Api ở một terminal riêng), rồi chạy lệnh generate ngay trong packages/api-client:

```bash
pnpm generate
```

Output sinh ra đúng vào packages/api-client/src/ (theo field output đã khai ở config):

```
src/
├── client.gen.ts
├── client/          # bundle runtime của @hey-api/client-fetch
├── core/            # helper dùng chung bởi mọi client plugin
├── types.gen.ts
├── sdk.gen.ts
├── react-query.gen.ts
└── index.ts
```

Giải thích nhanh từng file để học viên không thấy đây là hộp đen:

- client.gen.ts khởi tạo 1 instance client mặc định qua createClient(createConfig()) — mọi function trong sdk.gen.ts dùng chung instance này, đổi baseUrl 1 chỗ (client.setConfig({ baseUrl })) là đổi cho toàn bộ SDK.
- types.gen.ts chứa interface như CourseDto, CreateCourseData, CreateCourseResponse... ánh xạ trực tiếp từ OpenAPI schema, tên gọi phụ thuộc tên bạn đặt ở backend.
- sdk.gen.ts chứa function phẳng theo mặc định (flat, tree-shakeable) — dạng export const getCategories = (options) => .... Nếu bài 4.1 quên gọi WithName() cho endpoint nào, hàm sinh ra ở đây sẽ có tên tự động khó đoán — hệ quả trực tiếp của việc bỏ qua bước đó.
- react-query.gen.ts chứa hàm ...Options()/...Mutation() như đã nêu ở phần plugin phía trên.
- index.ts mặc định chỉ re-export sdk.gen.ts và types.gen.ts, không tự động re-export react-query.gen.ts — Module 6.3 sẽ import trực tiếp từ 'react-query.gen' khi cần.

> **📘 Ghi chú giảng viên:** *Tôi luôn mở thật 1 file sdk.gen.ts lên màn hình lúc dạy, chỉ đọc 1 function bất kỳ, để học viên thấy code sinh ra hoàn toàn đọc được — không phải một binary đóng hộp. Đây cũng là lý do khóa chọn công cụ sinh mã nguồn TypeScript thay vì một client library biên dịch sẵn.*

## 4. Build package thành dist/ thật

Cần thêm tsconfig.json để tsc biết build gì. Package này không dùng React/Next trực tiếp, nên cấu hình chỉ cần target hiện đại và moduleResolution kiểu bundler — cả Vite (apps/admin) lẫn Next.js (apps/web) đều đọc được format này qua workspace:\*, không cần build ra CommonJS riêng:

```json
// packages/api-client/tsconfig.json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2022", "DOM"],
    "declaration": true,
    "outDir": "dist",
    "rootDir": "src",
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["src"]
}
```

Build ngay trong package:

```bash
pnpm build
```

turbo.json từ bài 5.1 đã khai outputs: ["dist/\*\*", ".next/\*\*"] cho task build — chạy từ gốc frontend/ sẽ build đúng thứ tự topological: @tedu-market/api-client trước, rồi mới tới admin/web (2 app này vẫn còn placeholder echo, sẽ có nội dung thật ở bài 6.1 và 7.1):

```bash
cd ../.. && pnpm exec turbo run build
```

> **📘 Ghi chú giảng viên:** *Nếu log cho thấy admin#build hoặc web#build chạy trước api-client#build, nghĩa là dependsOn: ["^build"] cấu hình ở bài 5.1 bị sai hoặc workspace dependency @tedu-market/api-client chưa khai đúng trong apps/admin/package.json, apps/web/package.json — quay lại kiểm tra 2 file đó trước khi đi tiếp.*

## Bài tập thực hành

Đề bài: Viết 1 script nhỏ tên verify.ts ngay trong packages/api-client/src/, import 1 hàm SDK vừa sinh ra (ví dụ hàm tương ứng route GET /api/v1/categories mà bài 0.8 đã xây bằng Dapper), gọi thử và console.log() kết quả, chạy bằng tsx để xác nhận 2 điều: TypeScript autocomplete đúng tên field trong response, và request thật sự chạm được tới Postgres qua backend.

- Input: packages/api-client đã generate và build thành công theo phần Demo ở trên, backend + Postgres đang chạy với seed data từ bài 1.5.
- Expected output: chạy pnpm tsx src/verify.ts (trong packages/api-client) in ra mảng category thật, không có lỗi TypeScript khi biên dịch, không có lỗi network khi gọi.
- Hint 1: cần gọi client.setConfig({ baseUrl: 'https://localhost:{port}' }) trỏ đúng port backend trước khi gọi hàm SDK — client.gen.ts mặc định không tự biết baseUrl dev hay production, phải cấu hình runtime, đúng tinh thần note ở bài 5.1: workspace:\* chỉ resolve code trên đĩa, không tự cấu hình network.
- Hint 2: nếu hàm sinh ra có tên khó đoán kiểu getApiV1CategoriesGet thay vì getCategories, quay lại bài 4.1 kiểm tra WithName() cho đúng endpoint đó, sửa ở backend, generate lại — tuyệt đối không sửa tay bất kỳ file nào trong src/, vì mọi thứ trong đó sẽ bị ghi đè ở lần pnpm generate kế tiếp.

> **✏️ Thực hành:** Làm xong, so với kết quả mẫu: verify.ts chạy sạch, in đúng danh sách category đã seed, packages/api-client/dist/ có đủ .js và .d.ts cho types.gen, sdk.gen, react-query.gen, client.gen, index.

## Tổng kết

- @hey-api/openapi-ts đọc openapi.json — nguồn sự thật duy nhất từ Module 4 — để sinh types, SDK function và client runtime, thay vì viết tay type và fetch call cho từng endpoint.
- 4 plugin đã dùng — typescript, sdk, client-fetch, tanstack/react-query — mỗi plugin sinh đúng 1 nhóm file, ghép lại thành bộ output hoàn chỉnh trong packages/api-client/src.
- packages/api-client giờ build thật ra dist/, thay placeholder echo từ bài 5.1 — turbo build task đã cấu hình ở đó giờ mới thật sự phát huy tác dụng.
- Tên hàm SDK phụ thuộc trực tiếp vào WithName() đã gọi ở bài 4.1 — một lần nữa chứng minh việc chuẩn hoá OpenAPI trước khi generate (Module 4) không phải bước thừa.

> **✅ Tóm tắt:** packages/api-client đã có type và SDK function thật, build sạch, gọi thử được từ script verify.ts. Bài 5.3 sẽ tự động hoá lại bước generate này bằng 1 script duy nhất ở gốc monorepo (pnpm generate:client) để không phải lặp lại thủ công mỗi khi backend đổi API, và bài 5.4 sẽ chứng minh trực tiếp giá trị cốt lõi: đổi 1 field ở backend, generate lại, TypeScript báo lỗi compile-time ở cả admin và web cùng lúc.
