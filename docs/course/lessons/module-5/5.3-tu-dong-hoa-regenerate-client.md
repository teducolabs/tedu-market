## **Nội dung chính**

### **1. Vấn đề cần giải quyết**

*5 phút · Lý thuyết*

Ở bài 5.2, để có file openapi.json, bạn phải làm thủ công: chạy dotnet run cho TeduMarket.Api, mở trình duyệt tới /openapi/v1.json, tải file về, copy đè vào packages/api-client/openapi.json, rồi mới chạy lệnh openapi-ts. 5 bước tay, dễ quên, dễ dùng nhầm file cũ khi backend đã đổi API nhưng bạn quên tải lại spec.

Deliverable của bài này chỉ có 1 dòng: lệnh pnpm generate:client chạy 1 lệnh cập nhật toàn bộ client. Đây không phải tiện ích phụ — đây là điều kiện để giá trị cốt lõi của Module 5 (đổi kiểu dữ liệu backend → TypeScript báo lỗi compile-time ở cả 2 app admin và web) thật sự xảy ra ở bài 5.4. Nếu quy trình vẫn còn thủ công, dev sẽ generate qua loa hoặc bỏ qua, và 2 frontend app sẽ âm thầm lệch khỏi API thật.

> **📘 Ghi chú giảng viên:** *Tôi hay hỏi học viên trước khi vào demo: "Nếu quy trình lấy openapi.json vẫn phải tay, các bạn nghĩ dev thật sự sẽ làm gì khi deadline gấp?" — câu trả lời luôn là "bỏ qua, dùng client cũ". Đó chính là lý do Module 5 tách hẳn 1 bài 20 phút chỉ để tự động hóa, dù nội dung kỹ thuật không khó.*

### **2. Sinh openapi.json tại build-time, không cần chạy server**

*8 phút · Demo, thực hiện trên project TeduMarket.Api*

Cài thêm package Microsoft.Extensions.ApiDescription.Server vào TeduMarket.Api. Package này khác với Microsoft.AspNetCore.OpenApi đã cài ở bài 4.1: AspNetCore.OpenApi tạo document lúc runtime, phục vụ qua middleware tại /openapi/v1.json khi app đang chạy; ApiDescription.Server hook vào MSBuild, tự khởi động app với một "mock server" ngay trong lúc dotnet build để lấy document, không cần app thật sự lắng nghe port nào.

```bash
cd backend/src/TeduMarket.Api
dotnet add package Microsoft.Extensions.ApiDescription.Server
```

Mặc định, package này xuất file ra thư mục output (bin/...) với tên trùng tên project. Cấu hình lại trong TeduMarket.Api.csproj để file xuất thẳng vào packages/api-client, đúng tên openapi.json mà openapi-ts.config.ts (bài 5.2) đang đọc:

```json
<PropertyGroup>
  <!-- Xuất openapi.json thẳng vào packages/api-client, khỏi cần copy tay -->
  <OpenApiDocumentsDirectory>$(MSBuildProjectDirectory)/../../../frontend/packages/api-client</OpenApiDocumentsDirectory>
  <OpenApiGenerateDocumentsOptions>--file-name openapi</OpenApiGenerateDocumentsOptions>
</PropertyGroup>
```

Đường dẫn ../../../ vì TeduMarket.Api.csproj nằm ở backend/src/TeduMarket.Api/ — lùi 3 cấp ra root repo, rồi vào frontend/packages/api-client. OpenApiDocumentsDirectory luôn được resolve tương đối theo vị trí file .csproj, không phải theo thư mục bạn đứng khi gõ lệnh.

Build thử và kiểm tra:

```json
dotnet build backend/src/TeduMarket.Api
# packages/api-client/openapi.json xuất hiện, timestamp = vừa build xong
```

> **📘 Ghi chú giảng viên:** *Câu hỏi hay gặp: "Sao không dùng luôn /openapi/v1.json runtime cho tiện, đỡ cài thêm package?" — vì cách đó bắt buộc phải có server đang chạy đúng port, và ở môi trường Production, Module 3.9 sẽ khóa endpoint OpenAPI theo policy nên không gọi được từ máy dev. Build-time generation không phụ thuộc network hay OAuth2, chạy được ngay trong CI mà không cần start container Postgres.*

### **3. Script generate:client — 1 lệnh làm hết**

*5 phút · Demo, thực hiện trên packages/api-client*

Sửa packages/api-client/package.json, thêm script gộp cả 2 bước: build lại backend để có spec mới nhất, rồi mới generate client:

```json
{
  "name": "@tedu-market/api-client",
  "scripts": {
    "openapi-ts": "openapi-ts",
    "generate:client": "dotnet build ../../../backend/src/TeduMarket.Api -c Release --nologo -v quiet && pnpm run openapi-ts"
  }
}
```

Toán tử && đảm bảo openapi-ts chỉ chạy khi dotnet build thành công — nếu backend đang có lỗi biên dịch, script dừng lại ngay, không generate client từ spec cũ hoặc rỗng. -v quiet giảm log MSBuild xuống mức tối thiểu để terminal gọn, nhưng warning/error build vẫn hiện ra bình thường.

Chạy thử ngay trong package api-client:

```bash
pnpm --filter @tedu-market/api-client generate:client
```

Xác nhận packages/api-client/src (output của openapi-ts) được ghi đè với timestamp mới, đúng như kết quả bạn từng thấy ở bài 5.2 nhưng giờ chỉ mất 1 lệnh.

### **4. Đăng ký task trong turbo.json, expose ở root**

*2 phút · Demo, thực hiện trên frontend/turbo.json và frontend/package.json*

Thêm task generate:client vào frontend/turbo.json (đã tạo ở bài 5.1):

```json
{
  "$schema": "https://turbo.build/schema.json",
  "tasks": {
    "generate:client": {
      "cache": false,
      "outputs": ["src/**", "openapi.json"]
    }
  }
}
```

cache: false vì input thật sự của task này là code C# ở backend/ — nằm ngoài phạm vi workspace JS mà Turborepo hash được, nên Turborepo không thể biết an toàn khi nào cần chạy lại. Task này chỉ mất vài giây, nên tắt cache đơn giản hơn nhiều so với khai báo inputs xuyên thư mục backend/\*\*/\*.cs.

Thêm script ở frontend/package.json (root của monorepo frontend) để gọi task qua turbo:

```json
{
  "scripts": {
    "generate:client": "turbo run generate:client --filter=@tedu-market/api-client"
  }
}
```

Chạy từ thư mục frontend/:

```bash
pnpm generate:client
```

1 lệnh, chạy hết chuỗi: build backend → sinh openapi.json mới → generate lại client type-safe. Đây chính là lệnh học viên sẽ gõ mỗi khi đổi API backend, xuyên suốt Module 6 và 7.

> **📘 Ghi chú giảng viên:** *Tôi luôn demo lại đúng thao tác này thêm 1 lần nữa, không giải thích gì thêm — cho học viên tự thấy quy trình 5 bước tay ở đầu bài giờ rút gọn còn đúng 1 lệnh. Sự đối lập trực quan này quan trọng hơn giải thích lý thuyết dài dòng.*

## **Bài tập thực hành**

> **✏️ Thực hành:** Vào Course.cs (Module 1) hoặc DTO tương ứng ở TeduMarket.Application, đổi tên 1 field bất kỳ (ví dụ Title → CourseTitle). Chạy pnpm generate:client từ thư mục frontend/, quan sát output. Xác nhận packages/api-client/src phản ánh đúng field đã đổi tên. Sau đó đổi lại về Title để không phá code các bài trước.

Hint: Nếu dotnet build fail ngay bước sinh openapi.json dù PostgreSQL container (bài 0.10) chưa chạy — đây không phải lỗi của bạn. Build-time generation dùng mock server nên thường không cần kết nối DB thật; nhưng nếu Program.cs của bạn mở connection string ngay lúc khởi tạo DI (thay vì lazy), bước build sẽ fail. Đây đúng là tình huống "Customize runtime behavior during build-time document generation" — tạm thời không cần xử lý sâu ở bài này, chỉ cần nhận diện đúng nguyên nhân.

Solution: sau khi đổi tên field và build lại, mở packages/api-client/src/types.gen.ts (hoặc file types tương ứng openapi-ts sinh ra) — tên field mới phải xuất hiện, tên cũ biến mất hoàn toàn. Nếu vẫn thấy tên cũ, kiểm tra lại đường dẫn OpenApiDocumentsDirectory ở bước 2 có trỏ đúng vào packages/api-client hay chưa.
